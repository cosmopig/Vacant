# 2026-09-22：同一題、同一模型，**有 Vacant ↔ 沒有 Vacant**（pi，真模型）

> **一句話**：沒有 Vacant 的那一跑，**pi 退出碼 0 走人，而工作區一個位元都沒動**。
> 有 Vacant 的那一跑，同樣什麼都沒交，但**退出碼 20、有簽章收據、而且收據裡的
> `ws_start → ws_end` 兩個雜湊一模一樣**——「它什麼都沒做」是可以被第三方重算的事實。

- 題目：`lcb_3584`（R534）；模型 `gemma-4-12b-it-qat`；上游＝公開 Funnel
- agent：pi 0.87.0，`pi -p`，prompt 三臂**逐字相同**
- 工作區四個檔 ＋ 純度 fail-closed 擋門；權威驗收在工作區外；`--sandbox none`
- **n = 1**。這是存在證明，不是比率。

## 結果

| 臂 | 退出碼 | 秒 | 交付物 | 模型通數 | 裁決 | 事後查得到什麼 |
|---|---|---|---|---|---|---|
| **OFF**（完全沒有 Vacant） | **0** | 240 | **無** | **不可知** | 無 | **什麼都沒有** |
| **V0**（閘門，單次） | **20** | 242 | 無 | **4，全部 200** | `visible_fail` | 收據＋逐通 wire log＋`ws 1a1dacb74418→1a1dacb74418` |
| **V1**（閘門＋`revise` 重試 ×3） | 20 | 130 | 無 | 9（**其中 3 通 403**） | 🔴 **不可歸因** | 見下 |

## 一、OFF ↔ V0：差別不在程式品質，在**你知不知道**

兩臂的**交付物完全一樣**（都沒有 `solution.py`），模型也一樣。差別是：

- **OFF 給你退出碼 0。** 沒有 proxy、沒有 wire log、沒有收據。如果這是 CI 的一步，
  它會被當成成功往下走。而且**事後無法診斷**：你不知道模型有沒有被呼叫到、
  有沒有回應、是模型不會做還是網路壞了——因為**沒有任何東西被記下來**。
- **V0 給你退出碼 20，外加三件可重算的事實**：
  1. 四通模型呼叫**全部 200** ⇒ 模型是通的、有回應 ⇒ **失敗要算在 agent 頭上**，不是環境。
  2. `ws_start_sha256 == ws_end_sha256`（`1a1dacb74418`）⇒ **工作區一個位元都沒變**。
  3. 可見驗收的失敗原文：`ModuleNotFoundError: No module named 'solution'`。

⇒ **這就是「Vacant 不讓 agent 變好，它讓做過的事可被查核、並拒收不合格的」在一格裡的樣子。**
V0 的 `agent_rc = 0`：agent 自己宣告完成。閘門在行程結束那一刻擋下來。

## 二、🔴 V1 臂**不可歸因**，不准讀成「重試沒有用」

V1 的三次嘗試裡，**模型呼叫被上游回了 3 次 403**（`wire_index.jsonl` 逐通可查，403 與 200 交替）。
第 2、3 次嘗試各只跑 **9 秒**就 `agent_rc=1` ——那不是模型答不出來，是連線被拒。

403 的來源量出來了（`upstream_degraded_evidence.txt`，V1 跑完立刻量）：

```
HTTP/2 403
x-deny-reason: resolve_no_records
Host resolves to a private/reserved IP: resolve_no_records
```

**那是這個容器的出網過濾器**在重新解析 `*.ts.net` 之後拒絕的（Funnel 主機名有時會解到
tailnet 的 `100.64.0.0/10` 私有位址）。**不是 Vacant、不是 pi、不是 LM Studio。**
同一時間 10 通直連取樣只有 **4/10** 是 200。

時間窗說明為什麼 OFF／V0 仍然可比：

| 臂 | 時間（UTC） | 上游狀態 |
|---|---|---|
| OFF | 07:03:08–07:07:08 | 健康 |
| V0 | 07:07:08–07:11:10 | 健康（**四通全 200 是直接證據**） |
| V1 | 07:11:10–07:13:20 | **降級中**（第一個 403 出現在 +110s） |

⚠ 依鐵律 3 與 `infra_void` 紀律：**V1 這一格作廢，不併入任何結論。**
要拿到 V1 的數字，需要一條到模型的穩定路徑（LAN、或不被出網過濾器重解析的端點）。

## 三、順帶量到的、比數字更重要的一件事

**OFF 臂連「為什麼失敗」都答不出來。** 我手上有 V0 的 wire log，才敢說那一格的失敗
要算在 agent 頭上；OFF 臂**沒有任何紀錄**，所以「模型不會做」與「網路 403 了」
在它身上**無法區分**——而 V1 那一格證明了後者真的會發生。

⇒ 可究責性不是「抓到壞人」，是**「事後你分得開哪一種失敗」**。這一組三格剛好同時演了正反兩面。

## 四、不能說的

1. **n = 1**，一題一次。不是比率，不可外推。
2. **不能說 Vacant 讓模型變好**：兩臂的交付物一樣（都是沒有）。V0 改變的是**裁決與紀錄**。
3. **不能說重試沒用**：V1 作廢（§二）。
4. **不能說 OFF 臂失敗純粹是模型的錯**：它沒有紀錄，**本來就不可診斷**——那正是 §三 的重點。
5. 級別：V0／V1 都是 **B′**（沒有 bwrap）。上游是**公開 Funnel 不是 LAN**。

## 重跑

```
bash tools/ab.sh lcb_3584 OFF      # 完全沒有 Vacant：pi 自己的設定直接指上游
bash tools/ab.sh lcb_3584 V0       # 閘門，單次
bash tools/ab.sh lcb_3584 V1       # 閘門 ＋ revise 重試 ×3（需要穩定的上游）
```
