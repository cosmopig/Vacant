# LiveCodeBench v6（抗污染）× pi 對話介面 × 有/沒有 Vacant

> **一句話**：**正確率完全一樣（35% ↔ 35%，McNemar p = 1.000）**，
> 但**出貨品質不一樣**——ON 出貨 7 件全對；OFF 出貨 8 件，**其中 1 件是錯的**。
> 而且 OFF 有 **12 次什麼都沒產出卻沒有任何訊號**，ON 的同樣情況是 **13 次明示拒交、退出碼 20、附簽章收據**。

- 題庫：**LiveCodeBench v6**（`livecodebench/code_generation_lite`，`test6.jsonl`
  sha256 `bb4c364f71921c44…`）——公開、第三方、有公開 pass@1 數字
- agent：**pi 0.87.0 的對話 TUI**（真 pty，把同一句話**打進輸入框**，不是 `pi -p`）
- 模型：**`gemma-4-12b-it-qat`**（人類的 LM Studio，經兩臂共用的重試中繼）
- 40 格全收，**0 格作廢**；ON 臂 20 條收據鏈 `--selftest` 先過再驗，**總判全 OK**

## 一、結果

| | OFF（沒有 Vacant） | ON（有 Vacant） |
|---|---|---|
| 寫出 `solution.py` | 8/20 | —（放行 7/20） |
| 閘門拒交 | —（沒有閘門） | **13/20** |
| **通過官方隱藏測資** | **7/20 = 35.0%** | **7/20 = 35.0%** |
| **出貨正確率** | 7/8 = **87.5%** | 7/7 = **100%** |
| **假交付（出貨但錯）** | **1** | **0** |
| 什麼都沒產出、也沒有訊號 | **12** | 0（那 13 次都是明示拒交） |

配對比較：兩臂都對 2、只有 ON 對 5、只有 OFF 對 5、都不對 8。
**McNemar 精確雙尾 p = 1.000** ⇒ **正確率沒有差異**，而且不一致對是 5∶5，
代表**同一題重跑的變異很大**（每格只跑一次）。

### 那一件假交付長什麼樣

`lcbv6_3697`（hard，2025-02-01）OFF 臂：寫出了 `solution.py`、**過了題目頁面上的
可見範例**，但官方隱藏測資 **8/43 就答錯**。沒有閘門的話，那個檔案就這樣交出去了。

## 二、為什麼這批分得開，而 HumanEval 那批分不開

`../humaneval_ab_20260922/` 兩臂都 100%，因為工作區附的可見測資幾乎等於隱藏測資，
agent 自己迭代就到頂。這一批的落差是**題庫自己定的**：

| | 可見（agent 看得到、跑得到） | 隱藏（計分用） |
|---|---|---|
| HumanEval | 官方測資前 2 條 | 官方完整，通常 5–10 條 |
| **LCB v6** | 題目頁面的 **2–4 條小範例** | **42–44 條，含很大的輸入** |

⇒ 「過了可見卻過不了隱藏」在這裡是**真的會發生的事**（上面那格就是），
   而那正是閘門唯一能有貢獻的地方。

## 三、抗污染：這批的題，模型沒見過

人類 2026-09-22 的要求：「不能是他們在訓練模型時就會的」。三層處理：

1. **題庫本身就是為此設計的**：LCB 用比賽日期切窗。
2. **只收 2025-02-01 之後的比賽**（模型自稱訓練截止 2025-01，再留一個月的邊）。
   本批日期 2025-02-01 → 2025-03-29。
3. **實測回憶**（`tools/contamination_probe.py`，結果 `bank/contamination.json`）：
   只給題目標題，要它複述題目。

| | 結果 |
|---|---|
| 正控制（`Two Sum`／`Merge Two Sorted Lists`／`Valid Parentheses`） | **3/3 複述得出來** ⇒ 尺量得動 |
| 本批 20 題 | **19 UNKNOWN、1 疑似** |

⚠ 那 1 題（`lcbv6_3733`）逐字比對過：模型說「數值**嚴格遞增**、**恰好一個** 90 度轉彎」，
而真題是「開頭 1、之後 2,0,2,0… 的序列、**至多一個**順時針轉彎」——**兩處都錯**，
是照描述性標題改寫不是記得。**保留該題**；把它剔除後兩臂各是 7/19，結論不變。

⚠ 這把尺是**單邊**的：「複述得出來」＝確定看過（強）；「複述不出來」≠ 訓練資料裡沒有（弱）。

⚠ 第一次跑這個探針時 9 題全部 UNKNOWN，**包括 `Two Sum`**——那是思考模型把 token
   額度用在推理上、`content` 全空，**量具壞了不是證據**。正控制就是為了抓這個。

## 四、🔴 作廢重跑一次：量具造成的干擾

第一次跑到 33/40 時發現 ON 沒交付的比例異常高（4/17 ↔ OFF 10/16）。查下去**不是 Vacant**，
是我寫的 OFF 設定沒跟產品碼對齊：

| 欄位 | ON（`agentwrap.wire_pi` 寫的） | OFF（第一版，我寫的） |
|---|---|---|
| `contextWindow` | 262144 | **131072** |
| 模型 `name` | `m` | 真名 |
| 啟動 | `--provider X --model m` | 走 `defaultProvider` |

同一題（`lcbv6_3722`）只差這幾欄：**225 秒通過 → 327 秒失敗**。
⇒ 那個差異會被誤算到 Vacant 頭上，**整批作廢**。
第一版資料留在 `run_VOID_confounded/`（**不刪**，那是量具說謊的標本）。
現在兩臂的 provider id／api／compat／contextWindow／maxTokens／模型 name／啟動旗標**逐欄相同**。

## 五、模型的 runaway（兩臂都有，不是 Vacant）

ON 臂有 **21 通**單一回應超過 500 KB，最大 **4.4 MB / 39,431 字、零工具呼叫**——
模型在硬題上會寫一篇萬字分析而不動手。這是 repo 早就記過的思考模式 runaway。

兩臂的 pty 轉錄總量 **36.4 MB ↔ 35.3 MB**，幾乎相同 ⇒ **runaway 兩臂都踩，不偏袒任何一臂**。

## 六、環境補償（兩臂共用，不是 Vacant 的一部分）

`tools/relay.py`：本機重試中繼，**兩臂指到逐位元相同的端點**，只對環境層失敗重試。

| 本批 | |
|---|---|
| 總嘗試 | 775 |
| 出網 DNS 失敗被吸收 | **311**（40.1%） |
| 用盡重試（會導致作廢） | **0** |

## 七、不能說的

1. **不能說 Vacant 提高正確率**——這批量到的是**沒有差異**（p = 1.000）。
2. **不能說 Vacant 降低假交付率**——1 件 ↔ 0 件，**n 太小**，這是存在證明不是比率。
   能說的是：**這一批裡，沒有閘門的那一臂交出了一件錯的，有閘門的那一臂一件都沒有。**
3. **不能說 35% 是這個模型的 pass@1**——agent 手上有可見測資可以迭代，那不是 pass@1。
4. **變異很大**：不一致對 5∶5，每格只跑一次。要縮小要多跑幾次取平均。
5. 級別 **B′**（沒有 bwrap）；上游是公開 Funnel 不是 LAN；完成判定是輸出靜默的啟發式。

## 八、隱藏測資沒有入庫

`private_test_cases` 解開有 58 MB，**不進 repo**。題庫是公開的，照 repo 慣例只釘
`test6.jsonl` 的 sha256 ＋ 產生器；用 `tools/build.py` 對同一份檔案重跑可逐位元重建。

## 重跑

```
curl -L -o test6.jsonl https://huggingface.co/datasets/livecodebench/code_generation_lite/resolve/main/test6.jsonl
sha256sum test6.jsonl          # 要是 bb4c364f71921c44…
python3 tools/build.py 10 2025-02-01          # 等距抽樣，確定性
python3 tools/contamination_probe.py          # 污染檢查（含正控制）
python3 tools/relay.py &                      # 兩臂共用的重試中繼
HE_UPSTREAM=http://127.0.0.1:19000/v1 HE_MODEL=gemma-4-12b-it-qat \
  bash tools/cell.sh lcbv6_3722 ON            # 有 Vacant（對話介面）
HE_UPSTREAM=... bash tools/cell.sh lcbv6_3722 OFF
python3 tools/summarize.py                    # 兩臂正確率
```
