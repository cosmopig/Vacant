# 「可由第三方重算」類措辭的加註清單（送審用；2026-11-28）

決策方口徑（11/28）：
- 可以寫：「第三方可以驗證這條鏈內部一致、沒有被截斷或局部竄改，並重放出同樣的判定。」「鏈的內容只對沙箱外的紀錄（來源伺服器的存取紀錄、模型代理的計費紀錄）有外部錨點；其餘事件的真實性，取決於簽章金鑰沒有被鏈所記錄的那個 agent 拿到。」
- 不可以寫：「紀錄可由第三方重算，所以可信。」「agent 無法竄改紀錄。」
- 已發表的結論裡凡有「可由第三方重算」的地方，加一句：**「重算證明的是鏈內一致；同一系統帳號下的 agent 可整條重簽，外部錨點只有沙箱外的紀錄。」**（以下稱「加註句」）

### r454 執行器隔離的事實（執行方查；只讀 repo 紀錄）
- **金鑰**（`decisions/DECISION_20260906_R454_NAMED_DISSENT_PREREG.md` §一、第 225／397 行）：
  - K1 的私鑰是 Mac 上的檔案，K2、K3 的私鑰是 vacant-dev 上 scratch 目錄裡的檔案（`ops/gain/replay/r454/key_*`，不進 git）。
  - 各自和執行器在**同一個系統帳號**下。
  - **K2 與 K3 在同一台機器、同一個帳號**（兩個行程、兩把金鑰、兩條鏈）。
- **受測程式怎麼跑**：
  - 執行器用 `vacant_network/peerexec.py` 的 `sandbox_probe`，走 `ops.gain.gain_run` 的沙箱。
  - `vacant_network/checks.py` 的文件說明這一路的沙箱是「獨立行程 `python -I`＋逾時＋CPU rlimit＋暫存 cwd＋不繼承使用者環境」，並明寫「**不是對抗惡意程式碼的安全邊界**」。
  - 沒有用 bwrap 或容器把受測程式和金鑰檔隔開。
- **所以**：
  - 受測程式和簽章程式在同一台機器、同一個帳號下跑，受測程式**原則上讀得到同機的金鑰檔**。
  - K3（腐化者）的行程原則上也讀得到 K2 的金鑰檔。
  - 當時受測的是先前批次產生的模型草稿（MBPP+／LCB 類程式題），不是刻意對抗的程式；這只說明「沒有人試」，不是「試了也拿不到」。
- **建議展件補句**（先列給決策方）：「『這把金鑰說的』的前提是金鑰沒有被別人拿到。三台執行器都會執行受測的程式；在 r454，受測程式和簽章程式在同一台機器、同一個帳號下跑（K2、K3 還共用一台機器），沙箱只限時間、CPU 與工作目錄，不是安全邊界，所以這個前提沒有被保證，這一頁驗不出來。」
