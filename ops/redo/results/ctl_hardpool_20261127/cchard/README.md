## cc_1586I（cc40 的 3500 題）檢查（只讀已落盤檔案）
Haiku 的解不是「全答 NONE」：它推出環狀圖樣加折疊對角線的 m＝n/2 位參數化、逐格求一致性並輸出 UNIQUE／MULTIPLE／NONE 與完整格子，
在全部 60 案（含唯一一個 UNIQUE 與 4 個 MULTIPLE）上都對；但 60 案裡 55 案預期輸出是 NONE（「永遠輸出 NONE」就能過 55/60）且輸入最大只有 423 位元組，
所以這個 1.00 只證明它在小規模、有限幾個非 NONE 案上是對的，**沒有量到大 n 的正確性或效率**。

## 推論（未驗證）
- 這個池也在天花板：Haiku 的訓練暴露（2021 年 Codeforces 題與編輯題解）無法排除；測資是資料庫的變異小輸入，沒有擋規模的大測資，難題的「難」多在效率，被測試的輸入大小抹平。
- 要有 25–70%，需要不靠這個資料庫的 generated 測資（例如自備大規模隨機／最壞測資＋可信解當 oracle）或更新、不在訓練資料裡的題。

## 缺陷與處理
- 為 positive control 對 `ops/redo/claude_negctl.py` 加了 P5／P6 兩個探針（只增加探針；既有 21 項不變）。
- 驗收放行但 hidden 逾時 1 案（cc_1552G）：Haiku 在 jobs 16 的負載下測到的是比 hidden 時更鬆的時間；單案逾時是否為負載造成**沒有重測**（hidden 評分在 run 結束時跑，當時其他嘗試仍在跑）。
- 負載檢查只在 16 路驗過兩輪，不保證所有 hidden 逾時都不是負載造成；4 個失敗題中只有 cc_1552G 是逾時型。
- 特殊評判排除仍只有關鍵字＋雙解一致；兩份 C++ 解可能共享相同的確定性選擇。
