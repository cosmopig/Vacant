# 讓依賴有根據：交件紀錄的可究責性

**結論：目前的自動紅標不能當正確性裁決。** 收據欄位近乎平；凍結值重疊規則重跑方向混合；
流程主張可以逐句對照紀錄，但本版標籤的人工保留率僅 **6/20（30.0%）**。
紀錄有助於指出「哪句話應查哪段步驟」，尚未量到人類依據它判斷是否依賴交件會更準。

全部表格來自**實際歸檔模型跑數**，GT 是獨立 benchmark reward（0=fail，1=pass）。
沒有新增模型跑數、人工使用者實驗或模擬結果。合成案例僅用於單元測試。

## 4. 限制／下一步

- 缺輸出不是數值相反；本版精確 float 比對尤其會誤標四捨五入。上述機器標籤尚未經人工全面修訂，不適合當安全分數。
- 指令文字不同不保證核對語意獨立；有計算指令不等於執行了宣稱的算法；basename、間接腳本讀檔亦可能誤配。
- 最後訊息可能殘留 ATIF thought channel，不能直接當成人實際看到的畫面。u274 另有 timeout／截短；無 exception 也不保證紀錄完整。
- 規則覆蓋率受說明詳略／語言影響；沒有流程主張不代表沒做。中文支援只有合成回歸案例，未聲稱真實中文模型標籤精度。
- 相同任務、模型、抽樣相關；Wilson 區間只是描述性二項區間，沒有 task-cluster 校正。小紅標分母尤其不穩。
- 人工抽查只有一位分析者、非盲測且在開發後抽樣；未測 SUPPORTED 的精度／漏抓率，也未衡量讓人判斷改善。
- 若要做展覽或人類實驗，先用人工確認的主張／步驟配對作材料，呈現「可查算」與不確定性，不把本版自動紅標直接展示為裁決。
