## 更正（第九次稽核，11-27）：179 列作廢的原因是「沙箱裡的憑證過期、更新被白名單擋掉」
- 原文寫的「主機換 token、舊的被撤銷」**不對**。
- 代理日誌 `~/dev/ops/fl/pilot1_apps_haiku/proxy.jsonl`：被拒的 `platform.claude.com:443`（403，CLI 的憑證更新端點）從 **16:23:26Z** 就開始。16 時那一小時有 37 次，00 時那一小時有 2,435 次，和作廢時段吻合。同一份日誌裡 `api.anthropic.com` 200 共 3,524 次。
- 主機憑證的有效期約 8 小時：現在這份到 08:20Z，推回去是 00:20Z 左右換發。
- 沙箱用的是起跑時複製的那一份，過期後 CLI 想更新，被白名單擋掉（這是設計上刻意的），於是每次都認證失敗。
- **修法**：每次 Claude 工作階段開始前，從主機重新複製當下的憑證，並檢查剩餘有效時間。太短就等主機自己的 Claude Code 更新完再複製。
  - **不把 platform.claude.com 或任何更新端點加進白名單**：讓沙箱裡的 CLI 自己更新會旋轉 refresh token，可能把擁有者主機上的登入撤銷。
- **另加的檢查**：每個 worker 結束後，掃描它的工作區與日誌有沒有 accessToken／refreshToken 樣式的字串。有就把那一列作廢，遮蔽後才落檔，並回報。這些目錄本來就不進 git。
