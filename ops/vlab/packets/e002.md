## 0. 研究問題（ASSIGNMENT 原文）

> 究責 vs 更好做法 vs 多 agent vs 情緒提示：哪一種（在同一算力預算下）能改善結果？
>
> - H-acc（究責）：Vacant 的收據/閘門機制（驗收→擋回→回饋重試→簽收據）本身提升結果。
> - H-harness（更好做法）：流程指引（先規劃、先跑自己的測試、驗證邊界）提升結果。
> - H-multi（多 agent）：第二個 agent 審查提升結果。
> - H-stakes（情緒提示/利害關係）：後果框架提升結果；(a) 只是講（prompt-only）vs (b) 有真實後果（路由/續約）。

本實驗在**同一算力預算**（同任務集、同模型、同超時、各 1 rep）下同時測四種機制，
讓它們在同一 A 基線上互相比分。四假設是**互相競爭**的：答案是「哪個臂最好、差多少、
花多少成本」，不是四個獨立的 yes/no。

## 3. 量測（report.py，不信任自我報告）

每臂：`n / 通過 / 率 / calls_per_success / tokens_per_success / 逾時`；

## 4. 預註冊判準（發射前寫死）

**冒煙 go/no-go（8 格：A/H/M/S × {pg_affine_cipher, pg_beer_song}）**
- GO ⇔ 8/8 出 `score.json` 且 `pass ∈ {true,false}`；無臂專屬 rc 失敗；
  M 臂 events 顯示第二 agent 有被開起（記錄證據形式）；H/S 臂的 append-system 被 pi 接受。
- NO-GO（任一不成立）⇒ 不發 170 格大盤，先修臂檔/機構並複測冒煙。

**每假設的成立/反駁（主判準：配對 McNemar；確認線：4 組比較 Holm–Bonferroni）**

記 `p_X` = A_vs_X 的 McNemar 雙尾 p；`C_X` = X 臂 calls_per_success；`C_A` = A 臂同量。

| 假設 | 成立（CONFIRMED） | 反駁/未建立 |
|---|---|---|
| H-acc | Holm 校正後 p_C < 0.05 且 `C_only > A_only` 且 `C_C ≤ 2×C_A` | p_C 不顯著 ⇒ 未建立；p_C 顯著但 `C_C > 2×C_A` ⇒ 「有效但昂貴」（單獨標籤，不算無條件勝） |
| H-harness | Holm 校正後 p_H < 0.05 且 `H_only > A_only` 且 `C_H ≤ 2×C_A` | 同上結構 |
| H-multi | Holm 校正後 p_M < 0.05 且 `M_only > A_only` 且 events.jsonl 有**真第二 agent 證據**（`pi -p` shell 命令或 subagent 工具呼叫） | 無第二 agent 證據 ⇒ M 的成績降級為「提示式自檢」，H-multi 記 **UNKNOWN**（量不到，不是負結果） |
| H-stakes(a) | Holm 校正後 p_S < 0.05 且 `S_only > A_only`（且標註「只是講、無真實後果」） | 不顯著 ⇒ 「未建立」（不是負結果，禁止寫「情緒提示無用」） |

**成本紅線（所有臂）**：任一臂 `calls_per_success` 或 `tokens_per_success` > 2×A 且通過率未顯著提升 ⇒ 該假設記「不划算」。
成本必須與結果一起報告（紅線）；M 臂的 reviewer 模型調用在獨立 pi 行程、**不在** cell 的 events.jsonl 內，
故 M 的成本指標是**下界**（端點層日誌可補，已列 BACKLOG）。

**多重性**：4 組 A_vs_X 比較用 Holm–Bonferroni 作確認線；未校正 p 只作描述。
預註冊命令（1004 上執行）：

```bash
python3 - <<'EOF'
import json
from vacant_network.research import holm_bonferroni
r = json.load(open("/srv/vlab/runs/e002_hypothesis_arms/REPORT.json"))
ps = {k: r["A_vs_" + k]["mcnemar_p_two_sided"] for k in ("H","M","S","C")}
corr = dict(zip(ps.keys(), holm_bonferroni(list(ps.values()))))
print("raw   :", ps)
print("holm  :", {k: round(v,4) for k,v in corr.items()})
EOF
```

## 5. 限制（隨結果一起說）

1. 1 rep/題：配對設計消掉任務難度差異，但無 rep 內變異；rep 擴充另包（e003）。
2. M 臂 reviewer 成本在端點層，cell 指標是下界（§4 紅線已註）。
3. H-stakes 只測 (a)「只是講」；(b)「真實後果＝路由/續約」是多 rep + 排程器性質，e002 不測（BACKLOG）。
4. 三條 prompt 臂的文字量/結構不盡相同（機制本質不同）；token 差由 REPORT 記錄，不外推。
5. 模型是 gemma-4-12b 本地量化（H-12 類邊界）：結果不外推到別的模型/預算/任務庫。
6. `vacant install` 會改 pi 設定檔（json_hooks，可逆）與 `~/.vacant`（Vacant 自己管）；
   A/H/M/S 臂不裝 Vacant、不碰 `~/.vacant`。C 臂格子的收據鏈在該格 HOME 內，屬該格證據。
7. labd 串行 + PAR=2：170 格按 e001 現況 pace（~4–7 格/時）估 25–40h；磁碟與端點負載隨 e001 同量級。
