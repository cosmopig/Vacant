# 決定：**不**開 ON-random-routing 臂

- 日期：2026-08-24（round 61，Opus 5）
- 狀態：**已決定 — 不開新臂**
- 取代／延續：`DECISION_20260824_REVISE_COUNTERFACTUAL.md`（round 56）留下的
  待決事項「值不值得開一條 ON-random-routing 臂驗證『信譽路由選到比較差的
  agent』這個假說」。round 56 把它明確記成**假說**、不是量測結果，並指出
  驗證路徑是新臂。本檔的結論是：**那條新臂大部分是多餘的，而且在現有樣本
  量下不可能有結論。**

## 一、關鍵事實：OFF baseline 本身就是隨機路由

`ops/gain/gain_run.py:179-184`：

```python
def arm_off(task, agents, rng, calls):
    a = rng.choice(agents)
```

⇒ **OFF baseline ＝「均勻隨機路由 ＋ 1 通呼叫」**；
而 ON 的初稿 ＝「信譽路由（`_route_agent`, UCB-shaped）＋ 1 通呼叫」。

兩者相減**就是**隨機 vs 信譽的對照，同 seed 同題序、逐題可配對。round 56 已經
定位出「ON 對 OFF 的落差在第 1 通呼叫就產生，跟後面 4 通 review/revise 無關」
（且 round 59 證實 `revision improved = 0/60`）。**所以要問的那個問題，現有
資料已經回答得了，不需要花 ~8 小時後端時間再跑一條臂。**

## 二、事前判準（寫在正式輸出之前）

用 `ops/gain/analyze_routing_mix.py`（本輪新增，唯讀，不打端點）：

- **開新臂**：`off_only` 可歸因於路由的效應 **≥ 3.0pp** ﹦且﹦
  persona 品質離散度 Fisher 雙尾 **p < 0.05**。
- **不開新臂**：任一條不滿足。

**3.0pp 這個門檻是從本實驗自己的解析度導出的，不是品味**：n≈60 時觀測到的
7.15pp 落差，McNemar 精確雙尾 p=0.289 ＝ **7pp 在這個 n 下已經跟雜訊分不開**。
低於 3pp 的效應遠在解析度以下，開一條同樣 n=60 的新臂不可能解析出來。

**誠實聲明**：我在寫下這條判準之前，已經用臨時 shell 算過一次同類數字
（當時得到 ~0.8-1.2pp）。判準不是在完全盲的狀態下訂的。這削弱了「事前判準」
的強度，記在這裡不掩飾；抵銷的做法是下面第五節那條**前瞻性**推翻條件，
它用的是尚未產生的資料。

## 三、量具雙向驗證（做在正式跑之前）

`analyze_routing_mix.py` 的兩個計算都先在已知答案上驗過：

1. **Fisher 精確檢定**：與一支獨立的 exact-rational（`fractions.Fraction`＋
   `math.comb`）實作對照 **400 組隨機 2×2 表，mismatch = 0**。
   （另外：我一開始用記憶中的「標準答案」0.0350877 測 (8,2,1,5) 判 FAIL，
   實際是**我的記憶值錯了**——exact-rational 參考實作給 0.034965，與工具一致。
   記在這裡，因為「拿記憶當標準答案」正是會冤枉正確程式的那種驗證。）

2. **混合效應算式**：兩個植入案，判準寫在跑之前：
   - 植入 A（效應存在）：agentA 品質 1.0、agentB 0.0、ON 全路由給 A
     ⇒ 應為 **+50.00pp**（恆等式）。實測 **+50.00pp** ✓
   - 植入 B（**null 案**）：兩 agent 真品質相同 (0.4)、ON 份額極度偏斜
     ⇒ 應為 **+0.00pp**（偏斜份額本身不產生落差）。實測 `off_only` **+0.00pp** ✓

### ⚠ 植入 B 抓到一個真缺陷：pooled 估計是循環的

植入 B 裡，`pooled`（OFF+ON 合併的逐 agent 品質）吐出**憑空的 +10.00pp**。
原因：agent 的 pooled 品質裡**含有 ON 臂自己的成績**，而 ON 的份額正是被解釋
的對象 ⇒ 任何 ON-vs-OFF 落差都會被 pooled 估計自動部分改寫成「路由造成的」。

這與 `~/vacant` memory 記過的「代理量會被修復動作改寫就不是判別量」同型。
**歸因一律只看 `off_only`**（隨機指派、且完全獨立於 ON 臂）；`pooled` 在工具
裡改名 `pooled_CIRCULAR` 並保留為診斷對照。

**兩條判準都不滿足，且不是擦邊**：`off_only` 效應 **-1.33pp**（門檻 3.0pp）、
離散度 **p=0.7372**（門檻 0.05）。

**注意 `pooled_CIRCULAR` 那一行**：它把 careful-1 標成 p=0.0447 ＝「顯著」，
看起來正是「路由選到爛 agent」的鐵證。**那正是植入 B 預測會出現的假象。**
乾淨樣本裡最差的根本不是 careful-1（是 hasty-1），而且整池毫無可測的高下之分。
若沒做植入 B，本輪極可能就據此開了新臂，並把一個循環產物寫成發現。

## 五、結論與推翻條件

**結論（判斷，不是量測）**：現有 6 個 persona 在乾淨隨機樣本下的單稿品質是
74%–86%，信賴區間全數重疊、離散度檢定 p=0.74 ⇒ **池子裡沒有可測的好壞之分，
信譽路由沒有東西可以「路由過去」**。任何路由政策（信譽／隨機／甚至完美先知）
的期望交付率差距都在 ~1pp 量級，遠低於本實驗 n=60 的解析度（7pp 都測不出）。
ON 對 OFF 的 -7.15pp 落差，**最多只有 -1.33pp 能歸因於路由混合**，其餘與
McNemar p=0.289 一致地無法與雜訊區分。

**這同時是對 SPEC_GAIN 前提的一則負面證據**：一個「選 agent」的機制，
只有在 agent 真的有好壞之分時才可能產生增益。目前的 `POOL`（六種 system
prompt、**同一個底層模型** `qwen/qwen3.6-35b-a3b`）不滿足這個前提。

**前瞻性推翻條件（用尚未產生的資料，不受第二節那個誠實聲明影響）**：

OFF5 的每一通 gen 都是 `rng.choice(agents)`（`gain_run.py:242`）＝均勻抽樣。
跑滿 60 題會累積 **300 次抽籤（每 persona 期望 ~50 次）**，是一份獨立於本結論、
且比 OFF baseline 大 5 倍的乾淨 persona 品質樣本。本輪快照為 27 次抽籤
（`careful-1=3 careful-2=2 hasty-1=8 hasty-2=5 plain-1=4 plain-2=5`）。

- **若** OFF5 跑滿後，逐 persona 品質的離散度 Fisher **p < 0.05**，
  **且**最好與最差之差 **≥ 15pp**（每 persona n≈50 時可解析的量級）
  ⇒ **本決定被推翻**，池子確實有高下之分，屆時開 ON-random-routing 臂才有意義。
- **若** 離散度依然不顯著 ⇒ 本結論加強，且下一步應該是**改造池子**
  （引入真正不同的底層模型／能力層級），而不是繼續在同質池上比較路由政策。

⚠ OFF5 逐 persona 的成績要用「該 persona 的**個別解答**是否通過隱藏測資」來算，
**不是**該題最後多數決交付的結果——後者已經被 OFF5 的選版邏輯混合過，不是
persona 的單稿品質。這需要對 OFF5 的每一份候選碼各跑一次 hidden check；
`rows.jsonl` 目前只留 `involved` 的 agent_id 清單、不留逐份判定，
**所以那支分析工具還要寫**（留給下一輪，不在本輪範圍）。

## 六、本決定放棄了什麼

- 放棄了「直接量到隨機路由臂的交付率」這個最直接的證據。代價自知：本檔用的是
  OFF baseline 當隨機路由的代理，兩者差別在於 OFF 沒有 review/revise 後續，
  但 round 56/59 已證實 review/revise 對交付結果 `improved = 0/60` ⇒ 這個代理
  在本批資料上是站得住的。若哪天 revise 開始真的改變結果，這個代理就失效，
  屆時本決定要重新檢視。
- 放棄了 ~8 小時後端時間的支出（這是放棄成本，也是收益）。
