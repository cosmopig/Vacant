## 一、這一輪要決的是什麼

round77 把岔路留給人類：A（n 擴到 121，只答 OFF vs ON，約 31h）／
B（換題庫或換更弱的 worker 把效應量做大，**改變實驗條件**）／
C（接受「n=60 下三臂無法分辨」就是結論，收斂停手）。

本輪**沒有**在 A/B/C 之間拍板，而是先做三條路**共同的前置**：
在**完全不動實驗條件**的前提下，把 OFF 臂從 n=60 擴到**全庫 n=371**。

## 三、放棄了什麼，為什麼

- **放棄本輪就開 B（弱化 worker）。** B 需要新旋鈕（`brain_cline.py` 的 `POOL`
  目前沒有 `--pool` 之類的參數），而且會讓三臂的既有基準全部作廢
  ⇒ 要重跑三臂才有可比的 before/after。先把「沒動條件」的那個數字量到底，
  B 的 before 基準才存在。
- **放棄本輪就開 A（n=121 三臂，約 31h）。** 方向目前是負的（ON 比 OFF 差），
  在不知道全庫 OFF 失敗率之前擴 n，很可能只是把「輸」量得更確定。
- **放棄「挑難題組成子集」。** 用 OFF 的成績挑題再拿去比三臂＝選擇偏誤，
  而且偏誤方向正好對 OFF 不利。若日後要做分層抽樣，分層規則必須先公告。

## 四、⚠ 這個 run 解決不了什麼——先寫死，免得下輪誤讀

**全庫 OFF 不會、也不可能解開 round77 的 power 牆。**
ON vs OFF5 在觀察到的效應量下需要 n≈1096，而全庫只有 371 題。
把 OFF 量到 n=371 只是把 OFF 這一格的信賴區間收窄，**不會**讓 ON vs OFF5 變得可判定。

它買到的是三樣東西，僅此而已：
1. OFF 失敗率從 n=60 的點估計（21.67%，95% CI 約 ±10pp）變成 n=371 的量測；
2. **全庫 371 題的逐題難易圖**——這是 A/B/C 三條路共同的輸入；
3. 前 60 題的**重測一致性**（同 seed、temperature 0.7 ⇒ 非決定性）。
   這是所有 power 計算所依賴的**雜訊底線**，到今天為止**從來沒有被量過**。

**要讓判準 #2／#3 有機會達成，唯一的槓桿仍然是把效應量做大（路線 B）。**
下一輪不要把本輪的數字讀成「power 問題解決了」。

## 五、成本模型的更正（loop prompt 的數字是錯的）

loop prompt 寫「暖機後每筆約 10 秒、60 題 OFF ≈ 15 分鐘」。
**實測推翻**：`g_off60_qwenonly_20260824` 的 `wall_s=5377.5`／60 題 ≈ **90 s/題**，
`endpoint_latency_ms.gen.p50 = 71736`（71.7 秒）。
⇒ 全庫 371 題 OFF ≈ **9.3 小時**，不是 1 小時。本輪據此當成**跨夜背景 run**，
不是單輪內能收的東西。（單發 trivial 呼叫確實 3 秒——但那是 "Reply with exactly: OK"，
不是產生一支函式。**別拿 preflight 的延遲去估產生呼叫的延遲。**）

## 六、判準寫在量測之前

- **P1**（已驗，見下）全庫量具雙向驗證必須 371/371＋371/371，任一方向不滿分就不開 run。
- **P2** P1 過才開 OFF n=371。
- **P3** 本輪不開 ON／OFF5（兩支 run 同時打同一張卡 ⇒ 延遲被污染，而延遲是實驗條件）。
- **P4 下一輪的讀法（現在訂死，不准跑完再挑）**
  - 全庫 OFF 失敗率 **≥ 35%** ⇒ 效應空間夠，走 A（擴 n，條件不動）。
  - **25% ≤ 失敗率 < 35%** ⇒ 用實測逐題結果重算 required-n；只有 required-n ≤ 371
    的那些對才值得跑。
  - **失敗率 < 25%** ⇒ 現行 worker 池對這個題庫太強，**B 成為必要而非選項**，另立 DECISION。
  - 前 60 題重測 vs v3 的 OFF 47/60：兩者差距就是雜訊底線；**若重測本身就差 ≥5pp，
    那麼 round77 所有 required-n 都是低估**，power 比已知的更糟。
