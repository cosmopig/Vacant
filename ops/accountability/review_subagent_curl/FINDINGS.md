## pi 的子 agent：標記改成「固定、驗證過才接受」，是哪一個呼叫由 Vacant 用任務文字對

| # | 問題（嚴重度） | 怎麼修 |
|---|---|---|
| 1 | 平行的兄弟呼叫先結束時把標記刪掉 ⇒ 之後開的子 agent（串接的第二步、超過 4 個的平行）變成主 agent：跑驗收、關工作階段、交件，父 agent 打進任務的值被當成「任務本來就這樣說」（高） | 標記不再跟著呼叫走、不再被刪：每個行程一個固定標記（最上層 session、pid、專案） |
| 2 | 被別的擴充擋下的呼叫沒有 `tool_result` ⇒ 標記留在自己的環境；擴充重載後讀到自己的標記、把自己當成自己的子 agent：驗收靜默關掉（中） | 標記帶 pid；同一個行程重載時用自己記下的身分（`VACANT_PI_SELF`）；標記指到自己的 session 一律不算 |
| 3 | 巢狀：孫輩收到的任務裡子 agent 打的值，被怪到**主 agent**（和一個不相干的更早委派）頭上（高） | 子行程第一則訊息（任務文字）去對**它的父 agent** 還在跑的呼叫的輸入；對到恰好一個才記 `spawned_by`，追緝用它 |
| 4 | 兩個平行的單一委派：第一個子 agent 拿到兄弟的代理人類型，它可證明的錯記到別的代理人定義的信譽格（高） | 代理人類型從對到的那個呼叫的輸入拿（`agent`、`tasks[i].agent`、`chain[i].agent`）；對不到就是 `subagent`，不猜 |
| 5 | 標記活得比呼叫久：agent 開的 tmux 裡後來開的 pi 被當成一個已經結束的工作階段的子 agent（中） | 子行程只在標記的 pid **還活著而且是自己的祖先**時接受 |
| 6 | 從 pi 的殼層在**另一個專案**開的 pi 被當成子 agent ⇒ 那個專案的契約從來沒被驗收、交件（中） | 子行程只在自己的工作目錄在標記的專案底下時接受 |

## `curl`：只有「整個指令就是抓網頁」才算外部來源

| # | 問題（嚴重度） | 怎麼修 |
|---|---|---|
| 7 | 指令裡**提到** `curl` 和任何網址（註解、`true \|\|`、`echo`）就把 agent 可證明的錯洗成「網頁說的」（中） | 指令切成段（`;` `&&` `\|\|` `\|` 換行、去掉註解），每一段的**指令字**都要是抓網頁的指令或不造新值的過濾器 |
| 8 | 和 `curl` 同一個指令裡自己算出來的值（`echo $((50+8))`、`jq`、`tr`、`expr`、`bc`、`python3.12`、`nodejs`）被說成「網頁說的」（高） | 同上；有版本號的直譯器也認得出是在跑程式；`grep -c` 算數也不行 |
| 9 | agent 自己寫網頁、自己開伺服器、自己抓回來（中） | 指到這台機器的網址（localhost、127.x、這台機器自己的位址）不算外部；抓回來之前先看**這個行動者自己寫過的檔／打過的值**有沒有這個值 |
| 10 | `curl -d @draft.md`／`-F f=@draft.md` 把自己的檔上傳再抓回來（中） | `@檔` 算讀；自己寫過的內容優先 |
| 11 | 記成來源的是指令裡**第一個**網址（代理、來源頁）（中） | 只收抓網頁指令的位置引數，跳過帶值的選項（`-x`、`-e`、`-H`…）；抓了好幾個網址 ⇒ 列成候選、降成推論 |
| 12 | 沒寫 `http://` 的網址（`curl portal.example/q3`）不算抓網頁 ⇒ agent 背可證明的錯（低，既有） | 位置引數不管有沒有 scheme 都當網址 |

## 仍然成立的邊界（照實寫）

- pi：標記在主行程的環境裡一直都在，所以**從這個 pi 開出來、在同一個專案裡**的任何 pi（包括使用者在 pi 裡用 `!`
  開的）都算它的子 agent。任務文字對不到（或對到好幾個）⇒ 不記是哪一個呼叫，追緝在那一步只能說「對不到」。
- `curl`：Vacant 只看得到指令字串——代理、DNS、hosts 檔把一個正常的名字指到本機，看不出來。
  端到端的情境 F 就是這樣做的（`http_proxy` 指到假模型），這是實驗設定，不是 Vacant 能分辨的東西。
