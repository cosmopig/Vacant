## Q1 撐得起的最強一句話

「在**準則能寫成程式**的地方，確定性檢查零 token、準確度 97.5%，且在機械條件上**壓倒**評審（不准逗號 66/66 vs 40/61）；級聯用 0.27 次評審呼叫/題把覆蓋率從 73% 推到 92%，代價是接受者錯誤率從 2.5% 升到 4.6%。在**事實忠實度**上，評審單獨約 75%、拒絕的 precision 只有 0.68，換更貴的模型沒差。」

不能說的：
- ❌「通用驗證器」——你只涵蓋 19/25 型別，而且 V1 的 97.5% 是「我的重寫 vs 官方檢查器」的一致率，不是任務真值。
- ❌「閘門過了＝對」——V0 自己就說接受者 14.6% 隱藏不過。收據能背書的是「過了**使用者給的**驗收」，僅此而已。
- ❌「抓得到幻覺」——8.8% 是 50% 盛行率下的數字；資料→文字重加權後 15.3% 的漏放，觀眾聽到會以為有守門。
- ❌「Sonnet 沒比 Haiku 好」——n=150、差 1 個百分點，只能說「沒看到差」。
- ❌ 展場最危險的一句：「AI 評審會檢查」。展場離線、Windows、秒級，Anthropic 評審根本**不在場**；展件只能有確定性層＋unknown 交人。

## Q2 架構

主幹＝可程式判定的規格，評審＝殘差，**但評審的 accepted 不得單獨放行**。理由不是原則，是你自己的數字：接受者錯誤率因為評審而翻倍（2.5→4.6%），事實類則 75% 上下、拒絕本身三成是誤拒。

具體規則：
1. 評審的 accept 只在**事先量過、錯誤率低於凍結門檻的準則類別**才算過（例如 IFEval 型的格式殘差），類別清單雜湊進收據。事實忠實度**不在清單內**，一律 unknown 交人。
2. 評審的 reject 也不算 rejected，算「unknown＋理由」——precision 0.68 的拒絕拿去驅動 agent 重試，只會空轉燒 token。
3. 收據**分級**：D（全確定性）／J（有評審參與）／U。觀眾與第三方重驗時看得出這張收據有沒有 LLM 的手。
4. VALID 欄位那個事故要變成規則：評審呼叫失敗＝infra_void，永不折成 unknown。

## Q3 V3 怎麼讀

不是路死了，是**三個變因疊在一起**：
- 格式：乾淨產出只 15/60 合格，代表規格凍結時沒先做冒煙——規格要求了 agent 做不到的事（JSON 來源逐字引）。這是規格 bug，不是機制證據。
- 判定粒度：逐句評審 134/335 判不支持，說明「句子 vs 引文」把摘要式改寫一律當不支持；那是評審的已知病，不是產出有錯。
- 真正的訊號：確定性層抓數字 19/20、名詞 22/22、否定 8/18。**否定**是確定性抓不到而全文評審抓到的——這才是「殘差」該長的樣子。

修法：證據單位改成**型別化錨點**（JSON 指標／列號／行段），確定性解析器解得開才進判定；格式不合是獨立準則、只回 unknown 不 reject 內容。另外提醒：注入錯誤是程式造的，20/20 說的是「機器改的錯機器抓得到」，不是自然幻覺。

## Q4 下一個量測

重跑 V3，一次只換錨點：結構化來源用 JSON 指標／行段、確定性解析、錯誤用**自然錯誤**（RAGTruth 人工標註那類）不用注入。凍結三個數：格式合格率、錨點解析 vs 人工標註的準確度、殘差送評審的比例。這是唯一能讓非程式任務**長出確定性驗證器**的路，V3 的失敗把它冤枉了。若錨點準確度過不了 0.9，Q2 的「事實類一律 unknown」就從權宜變成有證據的定案。
