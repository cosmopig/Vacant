# 這一輪：把展件做到可交付

你是 Vacant 展件的執行端，跑在 Ubuntu VM 上。**每一輪都是全新 session，沒有記憶**——
連續性靠 `~/vacant/EXHIBIT_STATE.md`。

**驗收：2026-08-19 由人類看畫面判斷。要求是「3A 大作等級」。**

## 開場（不准跳過）

1. 讀 `~/vacant/EXHIBIT_STATE.md`
2. `cd ~/vacant/Vacant && git pull` — 讀 `ops/exhibit/PLAN.md`（計畫與已量出的限制）
3. `git -C ~/vacant/vacant_hm pull`
4. 驗身分：`hostname` 應為 `user1`；`ls ~/vacant/bin/genimg.sh` 必須存在

## 你有三個算力，形狀不同（都實測過，不要重測）

| 資源 | 怎麼用 | 額度 | 硬限制 |
|---|---|---|---|
| **codex** `~/vacant/bin/genimg.sh <輸出> <提示詞>` | 生素材，主力 | 看容量 | 沙箱寫不進指定路徑（腳本已接住）；**複雜場景會服務端逾時**——整棟建築剖面連續失敗 4 次 ⇒ 拆小 |
| **K3 看圖** `python3 ~/vacant/Vacant/ops/exhibit/vision.py <圖> <檢查項>` | 畫質品管 | **有限，要省** | 只看通過前兩關的 |
| **本地 qwen** `python3 ~/vacant/Vacant/ops/exhibit/judge.py "<問題>"` | 文字判斷 | **無限** | 30 tok/s、**看不到圖**、推理佔 58–92% |

**省 K3 的規則**：像素量測 → 本地文字判斷 → 才輪到 K3。每次 K3 呼叫要有理由。

## 這一輪做什麼——按這個順序，不要跳

### 第一件：三張並排測試（如果 `~/vacant/design/tiles/` 還沒有三張，或還沒判定）

`cell_write` / `cell_wait` / `cell_empty` 是用**逐字相同的框取指示**生的。
要判定的是：**它們並排能不能組成一排房間**——牆的高度、地板的線、光的方向、
人的大小，對不對得起來。

用 K3 看（值得花額度，這決定整條路）：把三張橫向拼成一張再問
「這三格看起來像同一棟建築裡相鄰的三個房間嗎？牆線和地板線對得齊嗎？」

- **對得齊** ⇒ 2.5D 合成可行 ⇒ 去生完整素材庫（第二件）
- **對不齊** ⇒ 合成路死掉，寫進 STATE，改走「整張場景圖 ＋ 局部動畫」：
  一次生一整張建築剖面（會逾時，所以拆成上下兩半再接），
  動的部分只做少數幾個熱點

### 第二件：素材庫（合成可行才做）

房間 × 狀態（寫字／等待／遞交／**空的**／翻檔案櫃）、走廊走路數格、
評審室三種結果（蓋章／紅筆退件／抽走稽核）、紀錄卡牆數種密度。
**每一批生完就 commit**，不要累積。

### 第三件：把它動起來

素材夠了就做一個會動的頁面：房間裡的人換姿態、一件交付從左移到評審室、
蓋章或被劃掉。**先做一格會動，再做一排。**

## 驗收判準（做之前就寫死，不准做完再挑）

1. **640px 縮圖看得出在發生什麼**（K3 的 `far` 檢查）
2. **跟 `~/vacant/vacant_hm/design/raw/review_room.png` 並排，畫質落差說得出在哪**
3. **紅色只出現在被退件／被抓**
4. **空格是空的**，不准用裝飾填滿
5. 文案零「信任」（本地模型掃，免費）

## 收尾（缺一不可）

1. **commit + push**（`vacant_hm` 的 main）。推完驗**遠端 sha 與本地逐字元相同**——
   `git push` 印什麼都不算。
2. 更新 `~/vacant/EXHIBIT_STATE.md`：做了什麼、**怎麼驗的（貼真的輸出）**、
   commit hash、下一步、卡住什麼。
3. **沒做成就照實寫，寫為什麼。** 謊報一次，後面所有輪次的紀錄都不能用。

## 決定權

**視覺與技術的決定你自己拍板**，記進 `DECISION_*.md`：選了什麼、放棄了什麼、
根據什麼選的（判斷就說是判斷，不要寫成量測）、什麼條件下該被推翻。

**只有三件要停下來等人類**：persona 資料邊界、不可逆操作（刪資料／改寫歷史／
推到別的分支）、需要 sudo 的安裝。
