## What the baseline process looks like (observations, n = 3 per task, not significance claims)

- **It never asks.** 0 of 12 runs asked the user anything, including T2 ("add a way to export as CSV":
  format, flag vs function, columns all unspecified) and T4 (funding priorities unspecified).
- **Same prompt, different decisions, no visibility into why.** T4 recommended three different
  portfolios across three runs (A+B+E, A+B+C, A+C+E), each presented confidently, none asking which
  trade-off the user wants. T1 assumed "discounts stack" in all 3 runs without flagging that this is
  a business-rule choice.
- **Reads before editing, but does not run tests before editing.** `read_before_first_edit` = true in
  12/12; `test_before_first_edit` = false in 12/12; tests run after the last edit in T1/T2 (6/6),
  never in T3/T4 (T3 has no tests; it did not add characterization tests in any run).
- **Scope of "clean up" drifts.** T3 diffs ranged +18/−20 to +34/−16; run r0 deleted
  `slug2` *and* the public `app.legacy_paths` that used it (import of `app.legacy_paths` now fails);
  r1/r2 kept behaviour. All three renamed `ReadCfg` → `read_cfg`.
- **Process stability varies by task:** self-consistency 0.61 (T2) to 0.91 (T3).

These are the patterns a user-specific process profile should change (e.g. ask once on business
rules, run tests first, keep public names) — and the metric columns are where that change would
show up in the with-Vacant arm. Persona similarity columns use SYNTHETIC example personas only.
