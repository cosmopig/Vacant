**這份文件是什麼**：不是預期產出，也不是正式論文。人類的原話是「我想確認我們的一切都符合學術研究的一切過程跟我們為什麼能有所突破」。
所以它照論文骨架寫，但語氣直白，對象是我們自己。它不新增任何數字——每一個數字都來自已經落盤的 DECISION／docs／json，並在文中標「（來源：檔名 §節）」。

**口徑**：全文用「可究責性／讓依賴有根據」，不用「信任」；少數必須討論「信任」這個詞本身的地方會標明是在引用定義。
不寫「證明」「保證」「防止」。比率一律帶分母。

## 摘要

本專題要回答的是一個很具體的問題：當一個 AI agent 把東西交出來，你憑什麼相信它？我們的答案不是「訓練得更好」也不是「多開幾場會」，
而是**把裁判換成執行**——讓客戶自己的驗收測資在沙箱裡跑，過了才出貨，全不過就拒交，而且每一次嘗試都簽進一條事後改不掉的收據鏈。
在這個地基上，我們用一顆 12B 本地模型（gemma-4-12b-it-qat）、跨三個真來源五個題目集，量到三件事：
**有迴圈（把失敗原文貼回去要它改）就贏單發**，這一條在同題庫五次複製的十五格對照裡全部通過 Holm 校正（+17.5～+29.2 pp），
在跨題庫四集裡四集全正、合併 p_adj 2.0e-8（來源：`DECISION_20260912_R460R_FABLE_AUDIT_REPLICATIONS.md`§八-1；`DECISION_20260912_R529_FABLE_AUDIT_CROSS_BANK.md`§三）；
**迴圈對「同預算重抽」的增量，五次複製分別是 +5.83／+4.17／+0.83／+2.50／+4.31 pp，跨題庫四集 +0.74／+3.70／+0.64／+1.08 pp，九次同號；
五次複製 0/5 通過 Holm（家族 6），跨題庫四集逐集未校正 p 皆不顯著、合併 Holm p_adj 0.341 亦不成立**——
同號未解析不等於沒有差異，但它也還沒被確立（來源：同兩檔）；
**增益的主體來自可執行驗收閘門加上重抽**（CONFORM 對 OFF 五次 +14.17／+18.33／+17.50／+19.17／+18.97 pp）。
同時，可究責層自己也被驗過：67 塊 run 的 V/GT 動態稽核零洩漏、194 條收據鏈 9,841 筆逐筆驗簽 0 失敗。
**整件事建立在「需求可以被編譯成可執行的驗收測資」。需求跑不起來的場合，這個機制沒有免費的裁判，會退化成「問一個模型」，而那正是量出來很差的東西**
（來源：`DECISION_20260903_R440P_CONFORMANCE_GATE.md`§五-1 逐字）。

## 一、問題：AI agent 的交付物沒有可究責的根據

### 1.1 問題長什麼樣

一個 agent 交出一份程式碼。你要決定收不收。你手上有什麼？
通常只有它自己說的話（「我已經測過了」）、一個平台上的星等、或者另一個 agent 的背書。這三樣的共同點是：
**產生紀錄的實體就是被記錄的實體**（來源：`examples/publish_now.py`·`DIRECTIONS_DONE[dir.ext.verifiable]`，引 Figuera 2026）。
自己說自己做過，這不是根據。

更麻煩的是，這個問題有一個看起來很自然但走不通的解法：**再問一個模型**。
我們自己把這條路走完了，而且量到它很差：ON 臂（信譽路由＋K=3 同儕評審＋一次修訂＋抽樣稽核，每題約 5 通呼叫）
在等預算之下打不贏 OFF5（同題跑 5 次取多數決），完整配對 p=0.45、難題子集 p=1.0
（來源：`examples/verdicts.py`·`gain.equal_budget_on_beats_off5`，裁決 refuted）。
評審票近乎常數函數：評審準確率 0.7552 對「全部判可」的基線 0.7522，只高 0.29 pp
（來源：`examples/verdicts.py`·`gain.mechanism`）。
而且這不是我們的 worker 太強或題目太簡單——換成 12B 單模型把 OFF 失敗率推到 31.8%，ON vs OFF5 仍然 p=1.0；
換成 LCB 難題把 OFF 失敗率推到 48.4%，仍然 p=0.4244（來源：`examples/verdicts.py`·`gain.ceiling_hypothesis`／`gain.hard_bench_hypothesis`，兩條都 refuted）。

這不只是我們自己的問題。外部文獻在同一個方向上更狠：人類專家的同儕評審信度本身就接近零——
Bornmann 2010（19,443 篇稿件的統合分析）平均 κ=.17；Cortes & Lawrence 2021 的 NeurIPS 雙委員會實驗 26% 決定不一致；
Pier 2018（PNAS）的 NIH 重評整體評分 ICC=0（95% CI 0–0.14）
（來源：`examples/publish_now.py`·`EXTERNAL[ext.peer-review-unreliable]`；直驗紀錄見 `參考文獻/_引用備份/MANIFEST.json`）。
「開評審會」在人類身上都撐不住，沒有理由假設它在 12B 模型身上會撐住——而我們也確實量到它撐不住。

### 1.2 為什麼我們刻意不用「信任」這個詞

這一條看起來是措辭潔癖，其實是定義問題。
Gambetta 1988 p.217 的原文把 before 與 and 排成斜體：「both *before* he can monitor such action (or independently of his capacity ever to be able to monitor it) *and* in a context in which it affects *his own* action」；
Mayer et al. 1995 p.712 寫「irrespective of the ability to monitor or control that other party」
（來源：`examples/publish_now.py`·`EXTERNAL[ext.trust-excludes-monitoring]`；證據強度：Gambetta 全文在手但無文字層，實際讀的那一頁已渲染成影像存檔；
Mayer 原件在付費牆後，該句經 Körber 2018 p.3 逐字轉引核對，**引用時必須標明轉引**）。

也就是說，兩個不同學科的經典定義，都把「不依賴監督」寫進信任的必要條件。
**而監督正是這個系統的全部**：跑驗收、記收據、多方作證、抽樣稽核，沒有一樣不是監督。
所以我們做的東西在定義上就不是信任，講成信任是在誤導。我們用的詞是**可究責性**，白話版是**讓依賴有根據**（warranted reliance）。

這條紀律在展場比在口委會前更嚴格，不是更寬鬆——觀眾沒有反問的訓練，也沒有對照組
（來源：`CLAUDE.md`§唯一交付物 第 5 條）。

### 1.3 交付物是展覽，這改變了技術決策

本專題的唯一交付物是**實體場地展覽**，不寫論文也不投稿（來源：`CLAUDE.md`§唯一交付物）。
這不是行政細節，它有四個會改變技術選擇的後果：秒級互動是硬需求（真模型每題實測約 114 秒，現場等不起）；
離線可跑、可無人值守；先行研究仍然重要，但理由從「新穎性」換成「不能對觀眾說錯話」；
統計檢定力不必到發表標準，但反事實對照要讓外行一眼看懂（來源：`docs/VACANT_COMPLETE_2026-09-12.md`§1.2）。

第三條是本文第二節存在的理由；第二條的具體後果見§2.3——OpenCode 的 doom-loop 預設處置是問人類，我們改成自動拒交，
理由逐字是「展場無人值守」（來源：`docs/HMIX_ARCHITECTURE_2026-09-11.md`§三 doom-loop 列）。

## 二、先行研究與我們站在哪裡

我們讀先行研究不是為了主張新穎性——**我們不投稿，新穎性對展覽沒有用**。
讀它是為了兩件事：(1) 不把別人 20 年前就命名過的東西講成「我們發現的」；(2) 借別人量過的東西當自己的地基或警戒線。

### 2.1 V/GT 分離：我們的實驗地基是別人蓋的

整個 G 實驗成立的前提是「需求」與「答案」可以分開，而這個分離不是我們發明的，是題庫自帶的。
EvalPlus 的 MBPP+ v0.2.0（378 題）與 HumanEval+ v0.1.10（164 題）、以及 LiveCodeBench 切出來的 v1（91 題）／v2（120 題）／v3（189 題），
都把「可見的例子」與「隱藏的判分測資」分開。我們把這個分離寫成操作定義：
**需求＝task prompt ＋公開 input contract ＋ `hidden_check`；選擇時只准碰 `visible_check`**
（來源：`SPEC_GAIN.md`§二）。
我們做的事是把它**釘死**：每個題庫檔的 sha256 寫進 `vacant/codebench.py`，loader 是 fail-closed 的；
MBPP+ 釘值 `af43697e8791c4c1…`、HumanEval+ 釘值 `272720b90ac37550…`，兩個包私有不轉散布，索引只記路徑與釘值、不含它們的任何一個位元組
（來源：`runs/INDEX.md`§七）。

分母也要照實講：MBPP+ 378 題裡有 7 題連官方參考解都跑不完我們宣告的 10 秒／128 MiB 沙箱，固定排除，餘 371 題（來源：`SPEC_GAIN.md`§二）；
HumanEval+ 的分母是 **156/164**，8 題被沙箱信封排除，逐題有名字有理由，而且排除是在看到結果之前定的——
但它仍然是一個本專題自訂的門檻，引用時要一起講（來源：`runs/INDEX.md`§七）。
LCB v3 自帶警語：contest_date 全部不晚於 2024-08-10，**不能**宣稱晚於訓練截止，污染風險比 v1／v2 高；
v3 的參考解覆蓋也較弱（來源：`runs/INDEX.md`§七；`DECISION_20260912_R529_FABLE_AUDIT_CROSS_BANK.md`§九-2、§九-4）。

### 2.2 self-consistency／多數決：我們的對照組，不是我們的發明

「同一題跑五次取多數決」是 self-consistency 的標準做法。我們把它做成 **OFF5 臂**，而且是**刻意**做的，理由寫在規格裡：
「ON 比 OFF 好是幾乎必然的，因為它多花了五倍的呼叫。拿 1 次對 5 次去宣稱『機制有效』是拿成本冒充機制。
真正要回答的是：等預算之下，Vacant 打不打得贏 self-consistency」（來源：`SPEC_GAIN.md`§三 逐字）。
而且同一節就寫死了「打不贏也要寫打不贏」（來源：`SPEC_GAIN.md`§十）。後來我們確實寫了打不贏（§1.1 的 ON vs OFF5）。

為什麼多數決在這裡不管用，外部也有量過：AI 檢查者會**一起錯**。
Kim 2025（ICML）在 350 個以上的模型裡量到，兩個模型都答錯時有 60.0% 錯在同一個答案（HELM 上，隨機基線 1/3；HuggingFace 上 0.423，隨機基線 0.127），
而且越準的模型錯得越像；Begin 2026 量到偏好對齊造成的同源相關 ρ=0.70，N=10 的有效獨立數只有 1.38；
Krumdick 2025 量到 GPT-4o 當評審、在它自己也答不出來的題目上 Cohen κ 從 0.86 掉到 0.16
（來源：`examples/publish_now.py`·`EXTERNAL[ext.correlated-errors]`；直驗紀錄見 `參考文獻/_引用備份/MANIFEST.json`）。
**必須一起講的邊界**：這三條量的是「錯得像不像」與「有效獨立數」，**不是**我們模擬裡那個盲區 β，我們自己的系統上仍未量過（同一來源逐字）。

### 2.3 execution feedback loop：pi 與 OpenCode 的原始碼事實，以及九條不准講的傳說

H-MIX 這條臂不是我們憑空想的，是照兩個公開 coding agent harness 的**原始碼事實**重做的：
`badlogic/pi-mono`（commit `9767ba27…`）與 `sst/opencode`（commit `53fec37d…`），逐檔讀過（來源：`docs/HARNESS_STUDY_2026-09-07.md`§1.1 版本釘死表）。
借來的是十個有出處的事實，其中對我們最重要的四個：
F1——pi 的迴圈只有一個停止條件（這一輪沒有 tool call），產品程式碼裡 `maxTurns|maxSteps|maxIterations|turnLimit` 一個都沒有；
F3／F4——工具失敗不是例外而是一則正常的 toolResult，迴圈照跑，而 pi 的 bash 把 stdout 與 stderr 合流、非零退出碼直接附在輸出尾巴（OpenCode 的 exit code 只進 metadata，**這是兩者的直接分歧，我們站 pi 這邊**）；
F7——OpenCode 的 doom-loop 門檻是 3，預設處置是問人類；
F9——OpenCode 唯一真正自動的 verification 是寫檔後注入 LSP 診斷，不是 prompt
（來源：`docs/HARNESS_STUDY_2026-09-07.md`§1.2）。

**同樣重要的是不准講的那九條**（T1–T9）。其中三條直接管住我們自己的敘事：
T2——Terminal-Bench 2.0 快照（口徑逐字 `as of Dec 1, 2025`）上唯一乾淨的同模型對照，四個 harness 全距只有 2.7 pp（42.8／42.6／42.5／40.1%），全部落在彼此誤差棒內
⇒ **「harness 才是關鍵」這個一般性質我們不能講**；
T3——那份快照的 60 個 entry 裡**沒有任何一個是 single-shot baseline**，
⇒ **「loop 比 single-shot 好」這件事在外部證據裡根本沒有被測量過**；
T4——pi 作者自己的論證前提是「frontier model 已經被 RL 訓練到內建知道 coding agent 是什麼」，而 gemma-4-12b-it-qat 沒有這個先驗
（來源：`docs/HARNESS_STUDY_2026-09-07.md`§1.3、§1.4）。

T3 這一條很關鍵：它說明**我們在做的這個對照，外部沒有人做過**。這不是我們挑的漂亮位置，是讀完才發現的空位。
而我們做這個對照的正當性不能建立在「業界公認」上（那是鐵律 5 的展場版問題），只能建立在 §5.1 那個我們自己量到的天花板上（來源：同檔§1.4）。

還有一條紅線級的：OpenCode `prompt/beast.txt:47` 寫
`remember there are hidden tests that must also pass before the solution is truly complete`——
**這句直接違反 V/GT 分離**，抄它的工作流時必須刪掉（來源：`docs/HARNESS_STUDY_2026-09-07.md`§1.3 末段）。
我們的稽核量具就是為了抓這類東西而存在的。

### 2.4 我們重新發現過、但別人先命名的東西

這一段是專門留給「不能對觀眾說錯話」的：

- **脈衝攻擊**：Srivatsa 2005 原文寫著 `oscillate between building and milking reputation`，他的 model I 就是我們的參數化，2009 年進了 ACM Computing Surveys 的攻擊分類表。
  連我們的頭條都被搶先：他量過四種震盪模型的攻擊者成本比 1 : 2.28 : 2.08 : 1.36，我們的「1.81 倍」既較舊也較弱，而且我們自己已判定那是雜訊
  （來源：`examples/publish_now.py`·`EXTERNAL[ext.oscillation-2005]`；直驗紀錄 `參考文獻/_引用備份/MANIFEST.json`·`2005_Srivatsa_trustguard-strategic-oscillation`，證據等級 A_全文）。
- **入場費沒用**：Friedman & Resnick 2001 已證明，身分可以免費重造時對新人課稅只是把無效率換一種形式
  （來源：`examples/publish_now.py`·`EXTERNAL[ext.entry-fee-known-2001]`；MANIFEST·`2001_Friedman_cheap-pseudonyms`，A_全文）。
- **「抗 Sybil」這個詞我們不能用**：對稱的信譽函數不可能同時是 sybilproof（Cheng & Friedman 2005）
  （來源：`examples/publish_now.py`·`DIRECTIONS_DONE[dir.ext.reputation-attacks]`）。

重現既有結果本身有價值——我們是在一個不同的機制組態裡量的。問題只在於把它當成新發現寫出去，而我們差一點就那樣寫了（來源：同上 `detail` 欄）。

## 三、研究問題與假設

把上面兩節接起來，問題變得很窄：**同樣五通模型呼叫，花在哪裡比較好？**
四個互斥的花法：單發（OFF，1 通）、換人重抽到過驗收為止（CONFORM，早停）、五次投票（OFF5）、把執行失敗原文貼回去讓同一個 worker 改（H 臂）。
四個假設：

| # | 假設 | 對照 | 事前寫在哪 |
|---|---|---|---|
| **H1** | 有迴圈就贏單發 | H-MIX／H-PI／H-OC vs OFF | `DECISION_20260907_R460_HARNESS_PREREG.md`§六-(4)；R460R 沿用逐字 |
| **H2** | 迴圈贏同預算重抽 | H-MIX vs CONFORM（**主要假設**） | 同上；`DECISION_20260911_R460R_FIVE_REPLICATIONS_PREREG.md`§二-1 |
| **H3** | 可執行驗收閘門這條選擇規則贏多數決 | CONFORM vs OFF5（同一組候選＝EQ5） | `CONCLUSION_20260904_R446_EQUAL_BUDGET.md`§一 |
| **H4** | 迴圈降低假交付（交出去卻是錯的） | H-MIX 假交付 < CONFORM | R460 預註冊 P-H4；R460R P-R4 |

H4 值得特別說一句：**我們事前預測的方向是錯的**。R460 的 P-H4 事前寫「假交付會比 CONFORM 高」（理由是迴圈朝可見測資改，過擬合風險更高），
實測是 14.2／15.0／11.7% 對 CONFORM 的 24.2%——**方向相反**（來源：`DECISION_20260911_R460_FABLE_AUDIT_HARNESS.md`§四 P-H4）。
這條 MISS 我們照實記、不改窗，而且後來把它改寫成 R460R 的 P-R4（方向改成事後量到的那個方向），五次複製 5/5 成立。
**事前預測錯了就留著，不能回去改成對的** ——這一點在第八節還會再提一次。

## 四、方法

### 4.1 臂的定義（逐字）

| 臂 | 做法 | 呼叫／題 |
|---|---|---|
| **OFF** | 隨機路由，交回來就收 | 1.00 |
| **CONFORM** | 逐一跑 `visible_check`，第一份通過就出貨並早停，全不通過就拒交 | 1.30–1.71（依題庫：R529 合併 1.30／MBPP+ 1.51／LCB v3 1.55／LCB v2 1.62–1.71） |
| **OFF5** | 同題跑 5 次取多數決（self-consistency）；票以行為簽名分桶 | 5.00 |

### 4.2 V/GT 紅線與動態稽核

V/GT 分離是實驗的紅線：**選擇與回饋都不准碰 `hidden_check`**。
但「我們沒碰」是一句宣稱，不是量測。所以有 `ops/gain/harness_vgt_audit.py`：掃 harness 真的送出去的每一段文字，找有沒有隱藏測資的字面值。

這個量具本身經歷過一次失敗與一次修。v1 在 R460 六塊上報 90 筆違規，逐筆分類後**全部是偽陽性**
（題目原文 54、harness 回饋引述模型自己的 SELFTEST 22、模型自己的回覆 8、可見測資失敗回聲 5、Rules 那行被模型改寫 1；
harness 自己寫進 prompt 的隱藏內容 **0 筆**）。判定是「量具偽陽性，不是 run 無效」，但同時寫下了為什麼這仍然是個問題：
**90 筆噪音之下，第 91 筆真的洩漏沒人看得出來**（來源：`DECISION_20260911_R460_FABLE_AUDIT_HARNESS.md`§一、§八-6）。

v2 把判準從「掃整段文字」改成「這段文字是誰寫的」：題目原文扣掉、assistant 訊息完全不掃、三條很窄的回聲豁免、凍結的 Rules 那行扣掉；
**`system` 訊息一格豁免都不給，驗收碼原始碼被貼進 user 訊息永遠是紅的**。
放寬必須配反向負控：把**真的**隱藏 case 塞進 harness 自寫的 user 訊息、塞進 system、塞進 `got=` 以外的欄位、貼驗收碼原始碼——四種都必須變紅；
`--scope v1` 在六塊上仍要逐字重現 90；對不到題目的 `task_id` 也要判違規（**沒有檢查不准冒充沒有違規**）
（來源：`docs/VACANT_COMPLETE_2026-09-12.md`§4.3）。
v2 實作時又被稽核抓到三處「文件說的與程式碼做的不一致」，包括一個真的破口：CODE needle 掃的是塗抹後的文字，
所以把驗收碼原始碼藏在 `got=` 後面就能過稽核；三處都修掉並各自補了反向負控（來源：同上）。

⚠ **量具 v2 沒有在「真的有洩漏」的真實 run 上驗過——負控全是人工植入的**（來源：`DECISION_20260911_R460R_FIVE_REPLICATIONS_PREREG.md`§五-1、§六-9）。

### 4.3 收據鏈

每一次嘗試（`harness_attempt`）與每一次裁決（`harness_verdict`）都簽進 `vacant/logbook.py` 的 append-only hash-chain：
`seq` 真單調、`prev_hash` 串接、簽章覆蓋全欄位、`stream_id` 是創世事件的 hash。中間被竄改就驗不過，而且持公鑰者都能自己 `verify_chain`
（來源：`vacant/logbook.py` docstring；`docs/VACANT_COMPLETE_2026-09-12.md`§2.1 L1）。
誠實邊界要跟著講：收據證明的是「這句話是這把金鑰說的、事後沒改過」，**不是**「這句話是真的」；
簽章指認金鑰，不指認主體（來源：`docs/VACANT_COMPLETE_2026-09-12.md`§4.1 B11）。

### 4.4 預註冊：四狀態、Holm、complete-case、不併 n

R460 的決策規則在看到任何資料之前就寫死了，而且 R460R 逐字沿用、一個字沒改：

- **四狀態**（照順序判）：(i) Δ_O ≥ +25.0 pp ∧ Δ_C ≥ +10.0 pp；(ii) Holm 兩者 p_adj < 0.05；(iii) `tpc_incl_void` ≤ OFF5 的；(iv) 假交付 ≤ CONFORM + 5.0 pp。
  四條全過＝`EFFECTIVE`，其餘落 `COSTLY_BUT_REAL`／`RULED_OUT`／`INCONCLUSIVE`
  （來源：`DECISION_20260911_R460R_FIVE_REPLICATIONS_PREREG.md`§二-1 逐字）。
- **Holm 家族固定 6**（3 條 H 臂 × {OFF, CONFORM}），**在那一次複製之內**調整。
  **不准**把五次的 30 個檢定丟進同一個 Holm——那會把「複製」偷偷變成「一個 n=600 的實驗」（來源：同上）。
- **complete-case**：配對單位是 `task_id`，分母是 `n_common = |rows[A].task_id ∩ rows[B].task_id|`，逐對印。
  r5 有 7 列 `infra_void`，所以逐臂分母不同（OFF 119／CONFORM 117／OFF5 118／HPI 120／HOC 120／HMIX 119），主指標的 complete-case 是 116
  （來源：`DECISION_20260912_R460R_FABLE_AUDIT_REPLICATIONS.md`§八-1）。
- **禁令**（事前寫死六條）：不准併 n、不准看到數字後改窗、不准挑最好的一次當代表、不准平均五個點估計、不准跨複製配對、不准只跑三次就結算
  （來源：`DECISION_20260911_R460R_FIVE_REPLICATIONS_PREREG.md`§二-3）。
- **宣稱規則**（逐字）：「5/5 同號（Δ_C > 0）且 ≥4/5 Holm 顯著 ⇒ 可以寫『複製穩定』；否則逐次照實列」——不准挑一次、不准平均、不准寫「多數支持」
  （來源：同上§二-2）。
- **贏家詛咒免責**（強制，不印不准結算）：n=120 對 +10 pp 的檢定力只有 0.43–0.63；能被判顯著的點估計被截斷在 MDE 以上 ⇒ **上偏**；
  所以複製跑的點估計**預期會比 +13.33 小**，某幾次 P-R2 失敗是預期之內的事，不是「效果消失」
  （來源：同上§三-1；`DECISION_20260907_R460_HARNESS_PREREG.md`§五）。

R529 換題庫時不能沿用 R460 的四狀態（它沒有 OFF5 臂，(iii) 的仲裁值不存在），所以另外凍結了一套，並逐字寫明「不得與 R460 的 `EFFECTIVE` 互引」
（來源：`DECISION_20260911_R529_CROSS_BANK_PREREG.md`§六-3）。
R529 的主指標是跨題庫分層的配對精確檢定，而它的誠實邊界寫得比公式還長：
**這個統計量與「把四集不一致對直接加起來做一次 McNemar」數值上完全相同**，分層買到的不是更嚴的檢定，
而是 (a) H0 變成「每一集都沒有效果」、(b) 逐集 b_k/c_k 必須照實列、(c) 異質性另外量而且只是描述性；
**不准**寫成「我們做了分層校正所以比較穩」（來源：同上§六-1 逐字）。

## 七、為什麼這算一個突破

（本節每一句成效都帶著§6.4 那句前提，不再逐段重複。）

先說不是什麼。**不是「84%」**。84.17% 是 R460 單次、單題庫、單模型的 H-MIX 交付率，
而五次複製的 H-MIX 落在 73.33–77.50%，我們自己已經把首頁三張卡從「58 → 71 → 84」改成五次的範圍
（單發 51–58、閘門＋重抽 71–75、迴圈 73–78）（來源：`DECISION_20260912_R460R_FABLE_AUDIT_REPLICATIONS.md`§八-5）。
拿單獨一個 84% 當結論，正是這套方法要防的事。

真正算突破的是四件事。

### 7.1 「增益主體＝可執行驗收閘門＋重抽」這件事被量出來，而且經過五次複製

在此之前，我們跟所有人一樣預設「多開幾場會、多投幾次票」會有用。量下去全是負的：
ON 對 OFF5 等預算打不贏（p=0.45／1.0）、評審票只比常數基線高 0.29 pp、五倍預算的 self-consistency 在 MBPP+ 買不到東西（+0.81 pp，區間 [−2.78, +4.28] 排除了 ≥5 pp 的實務增益）
（來源：`examples/verdicts.py`；`CONCLUSION_20260904_R445_CONFORM_SETTLEMENT.md`§一）。
換成**執行**當裁判之後，數字一下子就出來了：CONFORM 對 OFF 五次複製 +14.17／+18.33／+17.50／+19.17／+18.97 pp，
跨題庫四集 +4.9～+11.5 pp。而且這不是「Vacant 這個系統有效」的模糊宣稱，是一句機制陳述：
**選擇規則的上限是候選池（82.68%／85.03%，17–19% 的題五份全錯），要越過它只能改變候選本身**
（來源：`DECISION_20260903_R440P_CONFORMANCE_GATE.md`§二；`docs/HARNESS_STUDY_2026-09-07.md`§2.1）。

而迴圈確實改變了候選：D5 歸因顯示迴圈只救不傷（R529 四集 31/0——它只改可見驗收沒過的候選），
但**重抽在同樣的題上救回的差不多多**，所以迴圈對重抽多買到的東西很少（來源：`DECISION_20260912_R529_FABLE_AUDIT_CROSS_BANK.md`§十）。
這個「很少是多少」我們沒有量出來，而且照規則不准假裝量出來了。

### 7.2 整條鏈可究責：每一步簽進收據，9,841 筆驗過

大部分「AI 可信度」的工作停在指標。我們的東西停在**收據**：67 塊 run 的每一次嘗試與每一次裁決都簽進 hash-chain，
194 條鏈 9,841 筆逐筆驗簽 0 失敗，任何持公鑰者都能自己重驗；展件那張 4.48 MB 的離線單檔在瀏覽器裡從創世驗到鏈頭、
逐格重算裁決／指名／出貨（5,579 筆），展場 Linux VM 的 headless Chrome 以 `file://` 實測渲染 2.1 秒
（來源：`docs/VACANT_COMPLETE_2026-09-12.md`§3.1-F、§7.3）。
而且它同時把**做不到的事**印在同一張收據上：說謊者過半時指名會反過來指向誠實那一台；
驗收清單本身是爛的時候，k 台機器會一致地、可驗證地交出錯的答案，畫面上一個警告都不會亮（來源：同檔§6.1 第一句逐字）。

### 7.3 研究過程本身可審計

這一點比任何一個數字都重要，也是人類這次問題的核心。具體是：

- **預註冊在資料之前凍結**，而且凍結點查得到（R529 的 v2 凍結於 `43a5cbe`；R460R 的五顆 seed 發射前掃過 50 個 summary.json 確認從未用過）。
- **預測逐條對帳**，命中與未命中一起印：R460 6 HIT／3 MISS、R445 7 HIT／1 MISS、R529 4 HIT／4 MISS、R460R P-R1 5/5、P-R2 0/5、P-R3 0/5、P-R4 5/5、P-R5 3/5。
- **被推翻的留著**：`examples/verdicts.py` 是裁決的單一真相來源，12 條對外宣稱送去給獨立 agent 推翻，3 條 refuted、3 條 overstated，**舊的不刪**。
  理由寫在模組 docstring 裡，而且是一個真實發生過的失敗：裁決原本只寫在網頁那一支腳本裡，
  於是機器可讀索引還在宣稱那 12 條都好好的，而網頁上寫著其中 6 條有問題——**給 agent 讀的那份比給人看的那份樂觀，就是主動誤導**（來源：`examples/verdicts.py` 模組 docstring）。
- **事故揭露**：排程器兩次猝死、1003 兩次當機、hub 不分流、1004 模型崩潰與 JIT TTL、共租、分析器併發窗假象、兩台推論模式不同——全部寫進收官檔，
  而且寫的是「這一條影響哪一格裁決、不影響哪一格」，不是一句「有些技術問題」。

### 7.4 我們自己把自己最亮的數字降級了

R460 的 +13.33 pp 是這個專題到目前為止最漂亮的一個數字：Holm 後 0.0112、四狀態判 `EFFECTIVE`、主要假設成立。
五次複製之後，我們把它寫成**單次上偏的點估計**，把對應的宣稱從 `held` 改成 `unresolved`，把官網主視覺的 84 拿掉
（來源：`DECISION_20260912_R460R_FABLE_AUDIT_REPLICATIONS.md`§八-3、§八-5）。

這件事之所以算突破，是因為它不是事後的美德表演——**贏家詛咒免責是事前寫死的**，
而且 `analyze_r460r.py` 每次執行都必須印出「複製跑的點估計預期會比 +13.33 小」與檢定力預期兩句，**不印不准結算**
（來源：`DECISION_20260911_R460R_FIVE_REPLICATIONS_PREREG.md`§三-1）。
一個宣稱可究責的系統，如果不能對自己可究責，主張就沒有內容（來源：`examples/publish_now.py` 模組 docstring 的同一句）。

## 九、限制與沒做到的

1. **一顆 12B 模型**。全部的 harness 結果都是 gemma-4-12b-it-qat Q4_0 的結果。pi 作者那套「frontier model 內建知道 coding agent 是什麼」的前提在這裡不成立（T4），
   所以既不能把我們的結論外推到大模型，也不能把外部 harness 的結論搬進來（來源：`docs/HARNESS_STUDY_2026-09-07.md`§1.3 T4）。
2. **n=120 的檢定力是 0.43–0.63**（對 +10 pp）。0/5 通過 Holm 落在那個分布的下尾，但**單獨看不足以反推真值**；
   R529 的單集檢定力更低（n=54–156 對 +10 pp 只有 0.14–0.55），逐集「不顯著」是設計的已知代價，不是證據
   （來源：`DECISION_20260912_R460R_FABLE_AUDIT_REPLICATIONS.md`§二；`DECISION_20260912_R529_FABLE_AUDIT_CROSS_BANK.md`§九-7）。
3. **五次共用同一批 120 題**。LCB v2 bank 就是 120 題、`--n 20 × 6` 取全部 ⇒ seed 只打亂順序、不抽樣 ⇒
   「這批題剛好適合把失敗訊息貼回去改」這個可能性在各次之間**完全相關**。
   就算 5/5 同號且全部通過，能講的也只是「在這 120 題上穩定」（來源：`DECISION_20260911_R460R_FIVE_REPLICATIONS_PREREG.md`§六-2 逐字）。
4. **兩台後端推論模式不同**（1003 thinking／1004 非 thinking），而且是在 R529 收官之後才發現的。
   配對主指標不受影響（塊內同一台），但逐集絕對值與 token／tpc 是兩種推論條件的混合物，不可單獨引用；
   而且處置只做了一半再補齊——`generate()` 的 sha 釘死一度讓五臂在 1003 上仍是 thinking，那個缺口被寫成測試釘在明面上，
   後來才由裁決授權改碼（來源：`DECISION_20260912_R529_FABLE_AUDIT_CROSS_BANK.md`§十一、§十二-3、§十三-1）。
5. **LCB v3 的 GT 較弱**：隱藏測資下界只有 5 條、日期窗 ≤2024-08-10（污染風險較高）；
   `lcb3_hard` 只有 3 題被參考解直接驗過（`gauge_in_filter_n`＝3），而量具是**單邊保證**——擋得住已知壞解不等於涵蓋真需求
   （來源：`DECISION_20260912_R529_FABLE_AUDIT_CROSS_BANK.md`§九-2、§九-4；`vacant/suitegauge.py` docstring）。
6. **合成族沒跑**。`vacant/codebench.py` 的六坑型族（boundary、off_by_one、empty_input、duplicate_values、negative_numbers、type_coercion）是程序生成、題目不落盤、靠 seed 重現，
   但 harness 系列一題都沒跑過它（來源：`runs/INDEX.md`§七）。所以「可見測資更少、更鬆」那一端完全沒有資料。
7. **D5 歸因不是決定性的**。同一份 r1 資料在本機三次重評差 1 題／120；仲裁值不受影響（rescore 與 norescore 兩份 JSON 仲裁區塊逐位元相同），
   但引用歸因數字必須標明是哪一次重評（來源：`DECISION_20260912_R460R_FABLE_AUDIT_REPLICATIONS.md`§八-4）。
8. **對外措辭階梯還沒到「證明」那一格**：`docs/PREREG_V2.md`§8 的階梯要求 C-3（本檔凍結＋batch 跑完）才能說「證明」，
   而 PREREG_V2 待人類簽字凍結、G 系列 run 不是 RECORD_SPEC 證據包 ⇒ **兩個前件都還沒到位，對外一律停在「看得到提升」**

## 十、下一步

1. **閘門的品質**（Fable 建議的下一個實驗，待人類裁決）。既然增益主體在閘門＋重抽，最值得問的不是再堆複製，而是
   **可見測資少／鬆的場合，閘門會放過多少交錯成品、迴圈能不能補**。LCB v2 每題只有 2–4 條可見測資，

   合成族（§九-6）正好是可以把「可見測資條數」當自變數掃的地方（來源：`DECISION_20260912_R460R_FABLE_AUDIT_REPLICATIONS.md`§六-4）。
2. **把推論模式當一個因子**。R529 §十一的處置逐字有兩條路：要嘛把 1003 對齊成非 thinking，要嘛**在預註冊裡把推論模式當一個因子**。
   前者已做（`reasoning_effort`，預設 none，五臂與 H 臂都送得出去了）；後者還沒有任何一份預註冊這樣寫過。
   在那之前，任何跨機 run 發射前先用同一支探針確認兩台 reasoning token 行為一致（來源：同檔§十一 處置）。
3. **H-MIX 的 token 為什麼在簡單題庫上偏高**。R529 量到 H-MIX 呼叫比 CONFORM 少、token 卻多 1.4 倍——每通輸出更長，
   疑似「by hand 檢查」那一行把 reasoning token 拉長。這是機制題，不是再跑一次能回答的（來源：同檔§四、§六-4）。

   三把金鑰的 `vacant_id` 要印在**實體標示牌**上（R455 攻擊者 T8 的緩解——整條鏈用攻擊者自己的金鑰重鑄是離線單檔檢視器的結構性界線）；

5. **官網與索引口徑跟上**：`harness.hmix_loop_beats_resample_same_budget` 與 `harness.majority_vote_loses_to_gate` 都是 `unresolved`，
