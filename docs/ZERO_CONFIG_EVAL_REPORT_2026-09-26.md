**為什麼**（第七節，82 個失敗逐一分類）：
1. **時機錯**：三分之二的失敗（55 跑）是「沒交」——54 跑被這一輪設的 15 回合上限在 agent 說做完之前切斷（1 跑撞到輸出長度上限），

   （裝了 Vacant 的 C 組裡是 8 跑，最多 9 跑）。
2. **看的東西錯**：剩下的錯答案，**每一步都有根據**（值是自己算的、手冊打開了、步驟沒失敗），錯在「這個決定對不對」
   （例：7 跑把手冊寫明的「詐欺率＝金額比例」算成筆數比例；5 跑自己算出了正解又選了另一種解讀）。只看「有沒有根據」的檢查從設計上看不到。
3. **能做的動作弱**：只能在同一個工作階段裡把話送回去——在「重抽」之上，這是過去量到增量最小的那一種。

**和過去比**（第八節）：過去量到交付變好的（驗收＋重抽對單發，五次複製 +14～+19 個百分點，家族外、未校正；跨題庫各題組 +4.9～+11.5），
全部是 Vacant 自己握著生成：**有真的知道對錯的檢查（可執行的測資）、不過就重抽、全不過就不交**。最像 agent 的那個版本（G 實驗：路由＋評審＋修訂）
沒有量到正確交付的增益；「把話送回去修」在重抽之上多買到的很少。所以這一輪的結果**和過去的資料不矛盾**（過去沒有量過完全一樣的設定）。
文獻（摘要層級）也**不預期**沒有正確性訊號的回饋會有增益（但有反例）。

**Vacant 一定要做成 agent 嗎？不用**（第十節）。要的是兩樣零設定的 Stop 檢查現在沒有的東西：
**一個真的訊號**（答案檔在不在、專案自己的測試、獨立再算一次）和**在對的時間點動作、必要時重來的權力**——
這是包在使用者自己 agent 外面的一層，不是另一個 agent。用這一輪的紀錄零花費地估（探索性、同一批題、不是證據）：

**接下來**：第十一節列了四條路和它們碰到的產品原則，**由人類決定**；我的建議是「先交、沒交就重來」＋「有測資就跑測資」，

## 二、C 組是什麼（被量的那個東西）

設計：`decisions/DECISION_20260925_ZERO_CONFIG_DESIGN.md`（第 2 版＋§九 第 2.1 版）。

- **安裝**：`pipx install vacant-network`，然後 `vacant install`。沒有契約、設定檔、金鑰、環境變數（產品原則 1、3）。
- **做什麼**：每一步記進簽章鏈；agent 說「做完了」（Stop）的那一刻，只看紀錄做一次證據檢查。**只有五類會退回**（其餘只寫進交件說明）：
  1. 要求寫出的檔不存在（第 2.1 版加）
  2. 失敗的步驟被略過（跑自己的腳本或讀資料失敗、之後沒再成功，就交件）
  3. 說測過但紀錄對不上
  4. 沒有出處的具體值（要有點名資料、值是 agent 自己打出來的、在看過的東西裡找不到、不是簡單算得出來的）
  5. 任務單獨點名的檔沒打開
- **退回**：人的一個要求之內最多 2 回合（「沒打開」最多 1 回合）；退回文字只說「哪裡、應該是什麼」，沒有責任／懲罰字眼、沒有行動者（KS-1）。
- **交件說明**：`~/.vacant/trace/projects/<key>/delivery.{md,json}`——查了什麼、交件前改了什麼、還沒驗證的。不進工作區、不送模型。
- **失敗一律放行**：檢查在子行程裡跑、330 秒時限，出錯就放行。
- **程式**：`vacant_network/adapters/mode.py`、`adapters/hook.py`、`trace/evidence.py`、`trace/review.py`、`trace/zerostop.py`、`trace/recorder.py`。

**這個設計刻意很保守**：只在「幾乎一定是真的問題」時退回，因為退回一個對的答案等於弄壞使用者的東西。
代價是它**看不到**「讀了資料、推理錯」這種錯——這一點在花錢之前就已經寫下來了（見第三節的重播）。

### 問題五：這個設計本來就量不出小的差別（量法）

- 每題每組只跑一次、77 題：gemma 的 16 個翻轉、qwen 的 8 個翻轉全部和退回無關，最可能是兩次獨立取樣的差異——但這個設計分不開。

### 一句話

**時機錯（多數失敗發生在 Vacant 看得到之前）、看的東西錯（剩下的錯每一步都有根據）、能做的動作弱（只能在同一個工作階段裡講一次）。**
花錢之前都有跡象（設計檔 §九：四類抓不到真實失敗、回合用完時 pi 不進 Stop；校準：gemma C 沒走到檢查），但當時把「沒走到檢查」當成公平性的問題、

## 十、回答：Vacant 一定要做成 agent 嗎？

**照我們自己的資料，不用。** 整個專題裡最像 agent 的設計——G 實驗的 ON 臂（信譽路由＋三個模型評審＋一次修訂）——
同樣花 5 通打不贏「抽五次投票」；評審只比「一律說過」高 0.29 個百分點（第八節）。這只是一個實驗，
而且「不必做成 agent、要的是下面這幾樣」是從過去資料和文獻**推論**出來的，**還沒有在 DABstep 這類題上測過**。

過去真的量到交付變好的，是一層很薄的外殼，做三件事：**跑一個真的知道對錯的檢查、不過就重抽一份、全不過就不交**。
它不需要自己會解題、不需要理解任務、不需要評審，只需要兩樣**零設定的 Stop 檢查現在沒有的權力**：

| 需要的 | 過去（CONFORM） | 這一輪的零設定 C 組 | 差在哪 |
|---|---|---|---|
| **真的知道對錯的訊號** | 客戶的可見測資，可以執行 | 只看紀錄的五類檢查；DABstep 的答案沒有可執行的東西可以查 | 看得到「有沒有根據」，看不到「對不對」 |
| **重來的權力** | 自己再抽一份全新的 | 只能在**同一個**工作階段裡把話送回去（最多 2 次）；回合用完被中止時連這個都沒有 | 退回＝修訂，在重抽之上是過去增量最小的那一段 |
| **拒交的權力** | 全不過就不出貨 | 失敗一律放行 | 零設定原則下刻意不拒交（不能弄壞使用者的東西） |
| （時機） | 每一份候選生成完就檢查 | 只在 agent 自己說「做完了」時檢查 | 被中途切斷的跑（這一輪 gemma 的失敗大多是這種）永遠輪不到檢查 |

換句話說：**要的不是「Vacant 變成 agent」，是「Vacant 握著重來的權力，並且有一個真的訊號決定要不要重來」**。
這可以是包在使用者自己 agent 外面的一層（`vacant do` 已經是這個形狀：隔離工作區＋headless＋交件；過去的 `vacant run` 在 R535 也是），
agent 還是使用者原本那一個。

**用這一輪已經付過錢的資料，零花費地估一下「換成重來」大概會怎樣**（`ops/eval/formal/explore_two_runs.py` →
`investigation/two_runs.json`；⚠ **探索性**：同一批題、事後才想到、不是預註冊，只能當方向）。
把每一題的 A、C 兩跑當成同一題的兩次獨立作答。Vacant 改了 C 組 8 跑的輸入（退回）；其中 gemma 第 62、1753 題的 C 跑被當成第二跑用到
（A 那一跑沒有答案檔）——兩跑退回前後答案都沒變，不影響下面的數字，但它們不是「完全沒被 Vacant 動過」的第二跑：

- **「沒寫答案就重開一跑」**（檢查＝答案檔在不在，這是零設定就有的真訊號）：
  gemma **50 → 55／77**（多 5 題：15、18、62、65、66），多跑 25 跑、多花 0.52 美元（＋58%）；55 也正好是「兩跑任一對」的上限。
  這個規則按構造不會少掉任何一題（第一跑有答案就用第一跑），所以「多 5、少 0」**不是檢定，不報 p 值**。qwen 只有 1 題沒寫答案，**不變**（68）。
  ⚠ 這個增益綁在這一輪的 15 回合上限：pi 預設沒有上限，一般互動使用裡同樣的行為不一定變成「沒交」。
- **「兩跑答案對不對得上」**（檢查＝獨立再算一次）：qwen 兩跑都有答案的 76 題裡，對得上的 66 題有 62 題對（**94%**，單跑是 88%）；
  對不上的 10 題裡藏了單跑 8 個錯答案中的 **4 個**，但也把 **6 個對的**標成可疑。只有兩跑時不知道該信哪一個
  （對不上而一邊對的 8 題裡，A 對的 6 題、C 對的 2 題）——要變成分數，需要第三跑來投票，成本約 3 倍。
  gemma 兩跑都有答案的只有 41 題，40 題對得上（39 題對），這一招對它幾乎沒有作用：它的問題是沒交，不是交錯。

- **比重來更便宜的：在被切斷之前先交**。失敗分類（第七節）找到兩組合計 15 跑（最多 19 跑）**已經說出正確答案**、只是沒寫進檔
  （14 跑是回合用完、1 跑是撞到輸出長度上限）。同一條「要求的檔不存在」如果在預算快用完時就提醒「先把現在的答案寫進去，再繼續確認」，
  不用多跑一跑就可能救回——**在 C 組碰得到的是 8 跑（最多 9 跑）**；qwen 0。這沒有重播過，模型收到提醒後會不會照做不知道——只是上限。

這幾個估計合起來說的是同一件事：**對這兩個模型的 DABstep 失敗，有機會的是「時機」和「重來」，不是「再檢查一次同一份」**。
弱一點的模型（gemma）主要是沒交——在切斷之前提醒、或重開一跑就補得回來；強一點的模型（qwen）主要是每一步都有根據的推理錯，
只有獨立再算一次才看得到，而且要付 2–3 倍的錢、還要有辦法決定信哪一個。


## 十一、接下來可以走的路（人類決定；每一條都寫出它會碰到的產品原則）

錢：剩約 **1.40 美元**（金鑰不加值、約 2026-10-25 失效）。gemma 一輪 77 題約 0.9 美元——**任何一條路再跑一次正式批次都放不進去**，
所以下一步應該是先選方向、用不花錢的方法（L-fake、重播、這一輪的紀錄）做到產品等級，再決定錢怎麼用。

| 路 | 做什麼 | 對這一輪資料的估計（探索性） | 成本 | 會碰到的原則 |
|---|---|---|---|---|
| **A. 先交、沒交就重來** | ① 「要求的檔不存在」不只在說做完時查：預算快用完時（有上限的情境）提醒先把現在的答案寫進去；② 說做完或被中止時還是沒有，就開一個全新的嘗試（`vacant do` 的隔離工作區＋headless），交新的那一份 | ① C 組 8（最多 9）跑答案已在手上；② gemma 50→55；qwen 都不變 | ① 幾乎 0；② 只在沒交時多一跑（這一輪 gemma ＋58%） | 零設定 ✅；① 要在 agent 做到一半時插話——只在「預算快用完、答案還沒寫」時，沒問題時模型輸入仍然逐位元組相同；② 互動介面裡重開一跑會打斷使用者，headless／`vacant do` 自然。⚠ 這一條的分數增益綁在「有預算上限」（官方 DABstep 基線是 10 步，比這一輪更緊）；pi 預設沒有上限，一般互動使用裡同樣的行為可能變成「一直確認、花錢」而不是「沒交」（沒量過） |
