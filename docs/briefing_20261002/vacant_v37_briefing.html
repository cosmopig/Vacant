一句話：Vacant 現在是什麼

1. 裝一次、照常用

使用者只做「安裝」＋「打開本來就用的 agent」（pi／Claude Code／Codex／OpenCode）。不寫契約、不設定、不給金鑰。

2. 說做完時查一次

沒有契約也記錄每一步；agent 說做完的那一刻，只看紀錄，查「每一步有沒有根據」，只在五類幾乎必然是問題的情況退回，並附交件說明。

3. 可選的可執行驗收

有契約＋收件端持有的可見測試時，才走 bridge（gate／repair／conform）。這是選配，不是預設。

Vacant 不判斷答案對錯，只看每一步有沒有根據。目的是「在交給人之前改好」，不是事後給人一份報告。

架構：一條預設、一條選配

預設路徑（零設定）產品預設

agent（pi／Claude Code／Codex／OpenCode）照常工作
▼ 原生掛鉤（vacant install 裝的）
trace 病歷：一個專案一條簽章鏈，每步前後看工作區
▼ agent 說做完（Stop）
evidence 檢查（只看紀錄、子行程、330 秒時限、失敗放行）
五類退回
▼
退回（人的一個要求內最多 2 回合）／放行＋交件說明 delivery.md

bridge 路徑（契約＋驗收）選配／實驗

契約＋收件端持有、事先釘住的可見測試
▼ prepare（gate／repair／conform）
agent 在原工作區跑（原生 agent，不替換）
▼ judge（同步凍結成品→驗證）
accept → release（收件端自己重驗、發布）
不過 → repair：同工作階段回饋；conform：外層開新 session

PR #82 bridge：定位與它要證明的事

  • 定位：把「可執行驗收＋重來」接到原生 agent 上，不替換 agent，不呼叫模型。契約與可見測試在 agent 跑之前由收件端釘住；收件端那份是唯一裁決者，工作區那份只供 agent 掛鉤、僅比對。
  • 三個模式：gate（把關）／repair（同工作階段回饋）／conform（外層每次不過就開新的完整 session）。prepare → judge → release。
  • C5 審查結論：C361 實際測的是 mode: evidence 而非 CONFORM。「換成 CONFORM 就會補回來」是未檢驗的假說；CONFORM 上限 +9.0 個百分點裡 63／83 是撞時限後重跑，不需要套件就拿得到。
  • 所以要證明的是：把「可執行驗收」和「多給幾次機會」分開——需要預算相同、不用套件的 RETRY-NOSUITE 對照（i1001 的 R 組）。
  • 它是契約型路徑，結論不能講成零設定 Vacant 的效果。
