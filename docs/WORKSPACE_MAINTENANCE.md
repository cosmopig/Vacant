# 工作區清理與複製邊界

`python -m vacant_network.maintenance` 預設只列計畫；`--apply` 才刪除／輪替。
工作區根只用 `work_dir()`；專案根由 `--project` 明確指定。只清工作區根的
直屬舊目錄、專案內的 `.pytest_cache`／`__pycache__`，以及專案根的 `nohup.log`。
工作區與快取預設七天未更新才處理（整棵樹的最新 mtime）；日誌只依大小輪替，超過 10 MiB，保留三份。
Linux 上掃描 `/proc` 同帳號行程的 cwd／開啟檔案，使用中的工作區與快取略過。
不涵蓋其他帳號的行程；工作區應由自己的帳號獨佔。
不可讀的行程略過，在輸出 note 的 `uninspectable_processes` 報數；這些行程的工作區只能靠年齡門檻保護。
沒有 `/proc` 仍拒絕清理。日誌有開啟中的描述符時使用 copytruncate，否則重新命名；
若有不可讀行程，也保守採 copytruncate。備份檔若正在使用則略過這次輪替。
`fdinfo` 顯示有非 `O_APPEND` 寫入者時不輪替，輸出 `skip`／`non-append writer`，避免截斷後寫出 NUL 洞。
copytruncate 保留寫入者的描述符，但複製與截斷之間的新資料可能遺失；不是無損日誌封存。
不掃任意系統暫存目錄，不追蹤符號連結；根路徑的父目錄也不接受符號連結。

restart 的複製與回寫以目錄描述符開啟每層路徑（`O_NOFOLLOW`），檔案也不跟隨連結。
來源只接受仍指向工作區內的相對符號連結，保留成連結；絕對／逃逸連結拒絕。
回寫不覆寫目的端既有連結；驗收還原測試前移除測試檔連結，父目錄連結則拒絕。
回寫維持原規則，只同步一般檔案；agent 新建的連結不交回專案。
這不是 agent 沙箱，也不防同一帳號惡意搬動已開啟的目錄、或清理掃描後才啟動的行程。
