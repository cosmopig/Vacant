# S10 · 展件說「它保證做過什麼會留下來」——它自己的模擬留下了 19.7%

第 115 輪（2026-08-17）。資料性質：**機制模擬**（`vacant_hm` 的 JS 模擬），
不是真模型、不是 Vacant 的 Python 機制。真模型實測只有 E10 那兩行路由序列。

## 一、被判的那句話

`vacant_hm/index.html:153` 與 `world/js/main.js:194`，一字不差兩處：

> 「它不保證每次都對——**它保證做過什麼會留下來**，而且會有後果。」

前半是誠實邊界句（〈否定脈絡〉，紅線 C 允許），**沒動**。
後半是正向宣稱。第 108／114 輪只查到「有 5 條紅線 C 命中、4 條是否定脈絡」，
但**沒有人量過那半句對不對**。

## 二、量什麼（四個比值，分母一律連報）

展件裡「做過什麼」的唯一逐件紀錄是 `r.recent`：

- `sim-bridge.js:233-234 / 304-305 / 344-345` 三處都封頂 **10 筆**
- `unshift` **只在「收下」那條路**發生 ⇒ 被擋下（L1/L2）與被抓到（L3）的交付
  完全不進去
- `phone.js:145-147` 給觀眾指認的清單只列**前 6 筆**
- 全 `world/` **沒有任何 hash chain**——這一層的「留下來」是普通可變 JS 物件

| 代號 | 定義 |
|---|---|
| `R1` 保留率 | 期末 `recent.length` ÷ 這輩子曾有過逐件紀錄的件數 |
| `R2` 有紀錄率 | `ever_recorded` ÷ `done`（被派到的件數） |
| `R3` 指得到率 | `min(6, recent.length)` ÷ `done`（手機頁實際列得出來的） |
| `R4` 壞的留住 | 曾被收下的壞交付裡，期末還在前 6 筆的比例 |

參數＝**手機頁那一組真實參數**（`phone.js:52`：`buildWorld(DAY)` ＋
`warmUp(world, sim, 12000)`），因為那才是觀眾手上那台會跑的東西。
大螢幕的活體路徑**沒量**。

## 三、結果（3 場 × 12000 輪 · `runs/s10_retention/`）

```
  pooled  R1 = 0.360 (10612/29503) · R2 = 0.821 (29503/35919)
          R3 = 0.197 (7061/35919)  · R4 = 0.328 (422/1285)
```

- **觀眾指得出來的是派工的 19.7%**——五件裡一件。
- 曾經有過的逐件紀錄，到觀眾看的那一刻**只剩 36.0%**。
- **被擋下與被抓到的 6416 件，零逐件紀錄**：恆等式
  `done − ever_recorded == rejected + caught` 在 **466/466 位居民 × 3 場**成立。
  也就是說，**「抓到」這件事本身在展件裡指不出是哪一件**。
- 上限咬到的是勤奮的人：曾有 >10 筆紀錄的 **278/466** 位，他們的 R1 只有 **0.31**；
  單人最多曾有 41 筆，期末最多握 10 筆。**做得越多，被丟掉得越多。**

## 四、探針自驗（先做，全過才採信上面的數字）

| 格 | 內容 | 結果 |
|---|---|---|
| `P0a` | 分塊等價：`warmUp(w,s,12000)` vs `warmUp(w,s,1)`×12000，期末 tally／每位居民 `(done,rejected,caught,audited,stage,rep,recent key 序列)` 逐值相同 | PASS —— 不成立的話，觀測手段本身就是竄改 |
| `P0b` | 正向 fixture：收下 3 件 ⇒ `R1 = 1.000` | PASS |
| `P0c` | 負向 fixture：收下 25 件封頂 10 ⇒ `R1 = 0.400 · R2 = 0.833 · R3 = 0.200 · R4 = 0.000` | PASS |
| `P0d` | 失聯偵測：故意漏算 11 筆 ⇒ 恆等式**必須**壞掉 | PASS（`identity_ok = 0`），而且漏算把 R1 從 0.400 拉到 **0.714** |
| `P1` | 觀測完整性：逐件觀測到的筆數 == 模擬自己的 `tally.accepted` | PASS 3/3 場逐值相等（9817／9821／9865），`missed = 0` |

`P0d` 是本輪唯一真正的觀測風險，而且**漏算的方向剛好會讓 R1 變好看**——
`recent` 是長度 10 的 FIFO，取樣太疏就會有東西進了又被擠掉而沒被看見。
所以採集端每 **1 件**觀測一次，並在 JS 裡自己驗「兩次觀測之間任何人的
`recent` 長度不得增加超過 1」，超過就累加 `missed`；`missed > 0` ＝ 本場作廢。

派工裡一件工作都沒再拿到。

## 八、誠實邊界

- 量的是**展件自己的 JS 模擬**，不是 Vacant 的 Python 機制（`vacant/logbook.py`
  那條 hash chain 在 Python 那邊是真的，**但展件的 `world/` 沒有接上它**）。
- 只量**暖機路徑**（`warmUp`，手機頁那條）。大螢幕的活體路徑
  （`stepSim` + `tickDeliveries`）沒量，雖然 `unshift` 那三處的上限一模一樣。
- `R3` 用 `min(6, still)` 當分子，是**上界**：手機頁還會因為
  `?flag=` 之類的參數列到第 6 筆之後，但預設只列 6 筆。
- **「留得少」不等於展件在說謊。** 展件可以有意識地只留一個窗口，
  只要畫面上不寫「保證留下來」。本輪改的正是後者。
- 新句子「指得出是誰做的」也只對**留下來的那些**成立——這是刻意的，
  舊句的問題就是把限定條件省掉了。
