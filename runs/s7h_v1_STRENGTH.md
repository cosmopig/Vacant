## 三、本輪最實際的發現：〈否定脈絡〉提示在紅線 C 上比在 B 上弱

`[02]` 與 `[04]` 被機器標成〈否定脈絡〉，**但它們是肯定用法**：
「它**只保證**一件事」。之所以被標成否定，是因為同一句前面有「**不**保證每次都對」，
落在前後 12 字的否定窗裡。

這不是 bug，是這個提示欄位的能力上限——而**紅線 C 的全部風險正好住在
機器分不出來的那條線上**：

| 句子 | 紅線 C | 機器看到的 |
|---|---|---|
| 「不保證每次都對」 | 守線 | 否定脈絡 |
| 「只保證會留下紀錄」 | **守線**（這是被允許的那個宣稱） | 否定脈絡（被前半句汙染） |
| 「保證每次都對」 | **踩線** | 肯定用法 |

也就是說：機器能把第三種挑出來，但**分不出第一種與第二種**，
而且第二種被標錯的原因（被同句的否定詞汙染）**在紅線 B 上不會發生**——
B 沒有「被允許的肯定用法」這個類別，所以 B 的設計把這個弱點遮住了。
紅線 C 沿用 B 的形狀，就一併繼承了它沒被測到的地方。

**這一格沒有補**。補法（把否定詞限定在同一個子句內、或改判「保證＋什麼」的受詞）
會改動 `--diction` 的既往輸出，要獨立登記一輪。

## 四、C3 語料 1 / 原始檔 23：22 個差額是**別的領域的同形詞**

`擋住` 在 `world/js/clay/*.js` 裡指的是**遮擋（occlusion）**，3D 算圖詞彙，
跟「防止作惡」一點關係都沒有（`clay/main.js` 一支就 10 個）。
`prevent` 那 6 個全是 `preventDefault()`。

> 對一個**內含 3D 算圖器**的 repo 做詞族掃描，詞族會自動收進圖學詞彙。
> 抽取器把它們擋在語料外（23 → 1）是這一格唯一有用的事。

事前預測 `C1401`（EN 語料 = 0，7 個全是識別字）與 `C1403`（C3 語料 ≤ 4）都對。

觀測台**有**在講強度，講的是被允許的那一種。這次是真的守線。
