## 一、為什麼是紅線 B，以及為什麼它比紅線 A 更容易被漏掉

S7 全系列（第 96–102 輪）掃的都是**紅線 A**：把「排除」歸因給「被抓到」。
紅線 A 是**一句話內兩個詞同時出現**才成立的形狀，所以需要掃描器。

紅線 B 不一樣——它是**單一個詞**。正因為 `grep 信任` 三秒就跑得完，
七輪 S7 沒有一輪跑過它。**簡單到不需要工具的檢查，最容易變成沒人做的檢查。**

紅線 B 的理由不是用字潔癖（CLAUDE.md §5）：經典定義（Gambetta 1988、
Mayer 1995）把「**不依賴監督**」寫進信任的必要條件，而監督正是這套系統的全部。
對觀眾說「信任觀測台」，是用一個定義上排斥監督的詞，去命名一個只做監督的東西。

## 四、本輪最實際的發現：同一條紀律，一個展件做了，另一個一次都沒做

`vacant_hm/js/hero.js` 原始檔有 3 個「信任」，**語料 0 個**——因為那三個全在註解裡：

```
標籤刻意不寫「信任層」。經典定義（Gambetta 1988、Mayer 1995）把
「不依賴監督」寫進信任的必要條件，而監督正是這套系統的全部——
對不懂的觀眾講「信任」是騙人。改成「可究責層」。
```

也就是說：**人類動物園那邊已經照紅線 B 做了**（畫面上 0 命中），
**而且把理由寫在註解裡**。觀測台（`app.html`／`app.js`／`dashboard.py`）
**一次都沒做**，29 條命中裡有 28 條在觀測台。

這是 HANDOFF §八那條的另一個形狀：不是兩份程式漂移，是**理由寫在 A 的註解裡，
所以 B 從來不知道有這條理由**。紀律寫在某一支的註解裡＝那條紀律只覆蓋那一支。

### 招牌類 vs 否定類（人工整理，供人類判定，**非機器判準**）

29 條不是同一件事，粗分三形狀：

1. **招牌類**（把「信任」當名字用）——最該處理的：
   `app.html:6 <title>Vacant — 信任觀測台`、`app.html:15 Trust Observatory`、
   `dashboard.py:66 <h1>Vacant · 信任觀測台`、`app.html:62 信任開關對照`、
   `app.html:70 信任層要花錢`、`app.html:100 它的信任狀與簽章鏈頭`、
   `app.js:213 要主張信任層有價值`。
2. **否定類**（6 條，在**否定**信任）：`app.html:115 面板不是信任來源`、
   `app.html:162 此面板為唯讀視圖，不是信任來源`、`app.js:213 信任層不是免費的`、
   `app.html:138 面板好看不代表系統可信`、`vacant_hm/index.html:40 可不可信是不知道的`、
   `app.js:395 未互審（trust off 時不互審）`。
   **這幾條是誠實聲明，拿掉反而更糟**——需要的是換詞不是刪句。
3. **機制識別字類**（`#chip-trust`、`trust_card`、`trust on/off` 徽章）：
   `trust on/off` 是 `router.py` 那個**單開關的實際名字**（CLAUDE.md 程式碼地圖）。
   改畫面標籤與改程式碼識別字是兩件事，成本差很多。

**`dashboard.py:66` 的 `_PAGE` fallback 也在名單裡**（第 102 輪發現的第二個觀測台）。
展場條件（離線、無人值守、`vacant/web/` 少一個檔）正好會送出那一頁，
所以「觀眾實際看到的標題」在最壞情況下也是「信任觀測台」。

## 五、等人類的決定（執行端不拍板）

1. **觀測台要不要改名。** 「信任觀測台」出現在 `<title>`、`<h1>`、英文副標三處，
   是這個展件的名字。改成「可究責觀測台」是敘事決定，不是打字工作。
2. **`trust on/off` 這個機制名要不要一起換。** 它同時是程式識別字、CSS 選擇器、
   `router.py` 的開關名。畫面標籤與程式識別字可以分開處理。
3. **否定類那 6 條怎麼換詞。** 「面板不是信任來源」直接刪會失去誠實聲明；
   換成「面板不是究責來源」語意也不對（面板確實不是究責來源，但原句在講的是
   「別把好看當成可信」）。這條需要人寫，不是機器換字。

決定之後，把 `--diction` 接進收尾檢查，紅線 B 就有了跟紅線 A 一樣的常設關卡。
