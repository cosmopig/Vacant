## 一、為什麼不能直接把 `.py` 丟進現行路徑

舊的 `extract()` 對任何非 HTML 檔一律走 `js_strings`（JS tokenizer）。
把同一組 Python 已知答案 fixture 分別交給兩支抽取器：

| | 新的 `extract_py`（走 `ast`） | 現行 `js_strings` |
|---|---|---|
| 11 格 fixture | **11／11 對** | **4／11 對（答錯 7 格）** |

答錯的七格是：模組 docstring、f-string 的洞、註解裡的撇號讓後面錯位、
非 docstring 的三引號、函式 docstring、相鄰字串隱式相接、f-string 與一般字串混排。

**兩個方向都會錯**，不是只有少抽：
- `# 註解` 在 JS 裡不是註解 ⇒ 註解內的引號會開一段假字串（PY6 那格）。
- `"""..."""` 在 JS 眼裡是「兩個空字串 ＋ 一段錯位」，之後的配對整串偏掉（PY7／PY9）。
- 相鄰字串隱式相接（PY10／PY11）逐 token 抽會把**一句話切成三段**，
  同句掃描就永遠看不到它——而 `dashboard.py` 的 evidence 正是那個形狀：
  ```python
  f"需要：≥60 對配對任務且 bootstrap CI 下界 >0。"
  f"目前 on {n_on} 筆 / off {n_off} 筆，"
  "且本面板的池化差不是配對統計——這一階不能由面板判定"
  ```
  `ast` 在解析時就把三段併好了，抽出來是完整一句（洞用 `▮` 頂掉）。

事前登記的 P7b 判準是「js 答錯 ≥3 格，否則代表我多寫了一支不必要的抽取器」。
實測答錯 7 格。

**預測 `C1203` 只對一半**：我事前寫「最可能錯在 `#` 註解那格」，
實測 PY2（純中文註解）**js 也答對了**——因為那行註解裡沒有引號，
JS tokenizer 根本沒開字串，於是「不准抽到」那半剛好過。
真正會爆的是註解裡**帶撇號**的 PY6。錯的形狀猜對了，猜錯了觸發條件。

## 二、docstring 算不算觀眾文案

**不算**（事前登記，不是事後決定）。它跟 `probe/`、`styles/`、`*FINDINGS.md`
同性質，是寫給改碼的人看的工作紀錄，觀眾走到展場前面看不到它。

但**不准靜靜丟掉**——排除的東西要數得出來：
- `--scan` 收尾印「刻意排除：.py 的 docstring」＝ **8 段 · 1457 字元 ·
  其中候選句 1 條**。
- `--cjk-audit` 把它列成第三類：「判為 docstring 而排除在分母外：60 段」，
  不混進「漏失」也不混進「註解」。

那 1 條 docstring 候選是 `dashboard.py:1`：

> 信任是「之間那條線」上的東西：路由給誰、誰審過、稽核過沒、有沒有被 slash

〈抓到類〉＝`稽核`、〈排除類〉＝`slash`。它是模組 docstring，不是觀眾文案，
所以不列入候選——但它印在畫面上讓人自己判，這正是「排除要可被稽核」的意思。
