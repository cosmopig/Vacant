# round658 判準（**寫在量測之前**；先 commit 才開始量）

## 問題

round656 量出 E3 頭條「ON 等預算打不贏 OFF5」的差值區間是 **[−7.82, +16.33]pp
⇒ UNINFORMATIVE**，並算出要把半寬壓到 ±5pp 需要 **≈480–538 配對題**，而 E3 只有 91。

交棒因此寫成「需要更多題」。但**沒有人查過磁碟上已經有多少 ON/OFF5 配對資料**。
記憶條目寫死的規則：**卡在「需要更多」的量測，先查磁碟上有沒有現成資料**
（r522 就是這樣零 API 量出 A 曲線第二點）。

本輪的問題：**把已落盤的 ON/OFF5 配對資料合併，能不能在零 API 之下把頭條的區間收窄到可判定？**

## 一、可合併集合（**先訂納入規則，再看數字**）

磁碟上同時有 ON 與 OFF5 臂的 run 共 6 個。納入規則**只有一條，且與結果無關**：

> **量具必須是 round393 修好之後的那把尺。**

理由（不是本輪發現，是 r393 已落盤的結論）：commit `4795190`（2026-08-31T10:34:23Z）
修掉 `_GAIN_ALLOWED_IMPORTS` 漏了 `typing`。r393 的離線重放證明這個 bug
**對 ON 的懲罰遠大於 OFF5**（視覺檢查失敗中 86% vs 33% 只是被白名單擋下、不是邏輯錯）。
⇒ 這是一個**方向正好落在頭條比較軸上**的系統偏誤，混進去會讓 ON 被系統性低估。

判定用 **run 的起跑時刻**（`calls.jsonl` 第一筆 `ts_ms`），不用檔案 mtime——
r393 明載「決定性的 run 沒有被碰到，改 gain_run.py 不影響已載入記憶體的程式碼」，
所以跨越修復時刻仍在跑的 run 用的是**舊尺**，而它的 rows.jsonl mtime 會落在修復之後。
（`g_r356_3arm_20260830` 正是這型：mtime 09-01，起跑 08-30 ⇒ 舊尺。）

⇒ 兩層：**S1 = E1（MBPP+）、S2 = E3（LCB 快照）**，worker 池都是 gemma-4-12b 單模型，
**差異只有題庫**。被排除的四個 run（含 371 題那個大 run）**不是免費的統計功力**——
這件事本身要寫進交棒，免得下一輪又去撿。

## 二、主指標與合併方式

Δ = (ON 的 meets_demand 率) − (OFF5 的 meets_demand 率)，只算兩臂都落盤的配對題。
`meets_demand` 的取法**直接 import `ops/gain/analyze_paired.py` 的 `arm_rows`**，不重新實作。

合併是**加法恆等式、不是新模型**：
Σ(b_i − c_i)/Σn_i = (2B − N_d)/N，其中 B=Σb_i、N_d=B+C、N=Σn_i。
⇒ 與單層公式**同一個式子**，可以直接呼叫 round656 已雙向驗證過的
`ops/gain/replay/paired_ci.py::diff_ci(b, c, n)`，**不新增估計量、不新增旋鈕**。

事前聲明的假設：合併區間的效力來自「兩層的 π 相同」。**這個假設本輪要檢定，不是假設它成立。**

## 三、異質性檢定（**擋在合併之前**）

對 2×2 表 `[[b1, c1], [b2, c2]]` 做 Fisher 精確檢定，得 `p_het`。

- `p_het < 0.05` ⇒ 判 **HETEROGENEOUS**：**不得**把合併區間當頭條，
  必須分層各報一條，並照實寫「兩層的方向不同，合併沒有意義」。
- `p_het ≥ 0.05` ⇒ 允許報合併區間，但**仍要同時登出兩層各自的 b/c/n**。

## 四、判定表（**沿用 round656 的表，不重訂**），單位 pp，門檻 ±5.0

| 條件 | 判定 | 頭條必須怎麼寫 |
|---|---|---|
| L > 0 | `ON_WINS` | 頭條翻案，升級 fable |
| U ≤ +5.0 | `RULED_OUT` | 頭條照原樣成立 |
| U > +5.0 且 L < −5.0 | `UNINFORMATIVE` | 頭條必須寫「這個 n 回答不了」 |
| U > +5.0 且 L ≥ −5.0 | `NON_INFERIOR_BUT_UNRESOLVED` | 頭條必須加註上界 |

±5.0pp 是**借用**（R440B L2、round483），不是本輪新訂；**無論判哪一格，原始 [L,U] 都照登**。

## 五、事前預測（量之前寫死）

- **P-R658-1**：`p_het ≥ 0.05`（兩層同一個 worker 池，只差題庫；且 n_d 小，檢不出異質性）。
- **P-R658-2**：合併後**仍不會**到 `RULED_OUT`（U 仍 > +5.0pp）——E1+E3 配對數 ≈250，
  離 round656 算出的 ≈538 還差一半以上。
- **P-R658-3**：合併判定會是 `NON_INFERIOR_BUT_UNRESOLVED` 或 `UNINFORMATIVE`，不會是 `ON_WINS`。

**預期會多冒出一類**：兩層方向相反（E1 的 Δ 與 E3 的 Δ 異號）但 `p_het` 仍 ≥0.05。
冒出來就**照實寫、人眼確認、不算進判定、不當場補判準**。

## 六、量具雙向驗證（不做完不准報數字）

`diff_ci` 本身 round656 已驗（M1/M2 兩個突變體）。本輪**新增的只有「合併與異質性」那段**，
所以自檢條只針對新增部分：

- **P1（合併是加法恆等式）**：把某一層的 b/c/n 設成 0，合併結果必須與另一層**逐位元相同**。
- **P2（合併不等於平均）**：兩層 n 差 10 倍時，合併 Δ 必須等於 `(Σ(b−c))/Σn`，
  **不等於**兩層 Δ 的算術平均（防「不小心寫成未加權平均」）。
- **P3（Fisher 對稱）**：`[[b1,c1],[b2,c2]]` 與其行列轉置的 `p_het` 必須相同。
- **P4（異質性有牙齒）**：`[[20,0],[0,20]]` 這種完全相反的表，`p_het` 必須 <0.05。

突變體必須被擋：
- **M3**：合併改成兩層 Δ 的**未加權平均** ⇒ 必須讓 **P2** 破。
- **M4**：`p_het` 恆回 1.0（等於沒檢定） ⇒ 必須讓 **P4** 破。

## 七、BROKEN（事前寫死的推翻條件）

1. 任一自檢條沒過，或任一突變體沒被**事前指定的那一條**抓到。
2. E3 是**活的 run**（本輪仍在跑）⇒ 必須先快照到 `/dev/shm/r658` 再量，
   並登記快照的行數與 sha256；量完再驗一次快照 sha **逐字元相同**，不同就 BROKEN。
3. 出現 rows 缺 `meets_demand` 的第三類 ⇒ 照實列出，不補判準。
4. 兩層的 `pool` sha 不同 ⇒ 不是 BROKEN（題庫不同本來就會讓 instrument 不同），
   但**必須把四項條件 sha 逐項登出**，讓讀者自己判斷合不合理。
