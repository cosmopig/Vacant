# S7e：觀測台（`vacant/web/app.html`）活體 DOM 的紅線掃描

> **資料標籤（鐵律 6）**：面板裡的 40 筆交付是**機制模擬**——
> `runs/s7b_interact_dom.py:_FakeBrain` 確定性假腦，不是真模型實測。
> 本輪要量的是「文案會不會渲染出來」，不是品質。

## 一、為什麼要有這一輪

S7 的 `SCOPE`（`runs/s7_claim_audit.py:33`）對 Vacant 只含
`vacant/web/app.html` 與 `vacant/web/app.js`。但觀測台畫面上的字**大部分不在
那兩個檔裡**：磚、名冊、活動列、鏈完整性、成本表、事件流全是 API 生的，
而〈宣稱階梯〉那一頁（「這套系統現在可以說什麼」）住在
`vacant/dashboard.py:claim_ladder()`。原始碼路徑與 DOM 路徑**兩條都沒看過它**。

它也不能用靜態 http 掃：`/api/state` 會 404，整頁只剩骨架 ⇒ **假的乾淨**
（第 97 輪對 `vacant_hm` 實測過 21 倍差距）。所以本輪起一台真的 dashboard
（`python3 -m vacant.cli up`，**產品入口本身**，不另寫一份 provider 接線），
灌 40 筆離線假腦交付，再掃。

## 二、量到什麼

### ① 觀測台是第三種形狀：兩邊都講，但**分開在不同的格子裡**

獨立詞頻（不經候選邏輯，直接數 9 個狀態的 DOM 純文字，239595 字）：

```
〈抓到類〉 216 次   稽核 183 · audit 9 · 抽樣 18 · 抽中 3 · 被抽 3
〈排除類〉  27 次   SLASH 18 · 扣減 9
候選（兩類同句）  0 條
```

把三個展件並排看：

| 展件 | 〈抓到類〉 | 〈排除類〉 | 同句候選 |
|---|---|---|---|
| 官網（第 100 輪） | 91 次 | **0 次** | 0 |
| `vacant_hm` | 有 | 有 | **2**（紅線風險） |
| **觀測台（本輪）** | 216 次 | **27 次** | **0** |

也就是說：**觀測台把「抓到」與「後果」都放上畫面了，但沒有任何一句話
把它們連起來。** 「稽核通過率 22/28」是一格，「SLASH 0 ／信用已被扣減」
是另一格，中間沒有因果句。這跟官網「根本沒講後果」是兩件不同的事。

只中〈排除類〉的三句全部來自觀測台，且全部是磚上的孤立標籤：

```
DOM:app_load.html:65 ['SLASH'] | SLASH
DOM:app_load.html:67 ['扣減'] | 信用已被扣減
DOM:app_load.html:87 ['SLASH'] | SLASH
```

**這是敘事決定，不是執行端能拍板的**（規則七）：要不要在觀測台上把
「稽核佐證 → SLASH」那條機制連起來寫成一句話，等人類。
機制上它**是**有前提的——`ecosystem.py:1127` 寫死了人類仲裁只有在
「確定性稽核已獨立佐證此筆失敗」時才真的扣信用；畫面現在沒講這件事。

### ② 全站唯一「兩條路都沒看過」的觀眾文案：宣稱階梯

E2 量的結果是我事前高估了三倍。四句候選裡：

| 句子 | 活體 DOM | 靜態檔 | 結論 |
|---|---|---|---|
| 「擁有權」 | 有 | `app.js:99` | 原始碼路徑本來就看得到 |
| 「待回溯」 | 有 | `app.js:156` | 同上 |
| 「簽章鏈可驗」 | 有 | `app.js:167` | 同上 |
| **「在預註冊條件下量到提升」** | 有 | **無** | **只存在於 `dashboard.py:429`** |

所以「活體才掃得到」的那一類，實際上**只有宣稱階梯那四階**
（`dashboard.py:394–436`）。它們沒踩紅線——講的是「證據支持到哪一階」，
不講「被抓到⇒排除」——但它們確實是全站文案裡唯一沒被任何一條掃描路徑
涵蓋過的一段。

**建議（不自己動）**：把 `vacant/dashboard.py` 加進 `s7_claim_audit.SCOPE`。
沒加，因為那會改動所有既往輪次的分母，屬於該獨立登記的一輪。

### ③ 事件流會把 ledger payload 原封不動印上畫面

`app.js:272 evNode()` 把事件 payload 的每個欄位攤平成畫面文字。本輪第一次跑
時，我塞進 `eco.report(..., evidence=...)` 的那句話裡有「稽核」兩個字，
於是 9 個狀態各生一條候選——**9 條候選全部是量測工具自己的字**。

這件事對展場有兩個後果：

1. **對這條掃描管線**：任何寫進 ledger 事件 payload 的文字都會變成觀眾文案，
   而 `app.html`／`app.js` 的原始碼掃描**結構上永遠看不到它**。
2. **對展場本身**：觀測台的事件流是一個把**資料**直接變成**畫面文字**的通道。
   展場若接真人捐出的 persona，那些字會直接上牆。
   （persona 資料邊界仍是等人類的項目。）

修法是把 fixture 的 evidence 換成不含任何詞族的英文串
（`s7b_interact_dom.py:seed_app_root`），並在該處寫下原因。

## 四、兩個判準是我自己寫錯的（不是程式的問題）

兩條都**往安全的方向錯**——它們都是「該過卻沒過」，不是「該擋卻放行」。

**E0c**：我要驗「ledger head 有被渲染出來、不是還停在佔位符」，寫成看
`#chip-head b`。但 `app.js:249 renderTop()` 是用 `innerHTML` 把整格換掉，
`<b>—</b>` 被換成 `<button class="hash">`。所以 **`#chip-head b` 存在，
反而代表渲染失敗**——我寫了一個「越成功越不會過」的反向判準。
事後從已凍結的 `app_load.html` 直接讀（**post-hoc，不計入判準**）：

```
title = b4ce8b9f648bc5c7d561eb1aa5db96bfc7781837aa82e1bfd82e1a5af18ef749（點擊複製）
按鈕顯示 = 'b4ce8b…f749'
```

64 個十六進位字元，確實渲染了。但**登記的判準是 FAIL，就記 FAIL。**

**E2**：我事前寫「這四句在靜態 `app.html`／`app.js` 裡一個字都沒有」——
其中三句根本就是 `app.js` 的模板字面量。這個高估是本輪最有資訊的一件事：
它把「活體才掃得到的東西」從我以為的四類縮到實際的一類。
判準裡那半條「且靜態檔必須 0 次」正是抓到它的東西——沒有那半條，
這一格會四句全中、漂亮地過，而結論會是錯的。

## 五、一個事前就登記、事後沒改的加詞

E4e 在動手之前就把 `SLASH`（大寫）與「扣減」加進 `EXCLUDE_CLAIM`
（`s7_claim_audit.py:44`）。原詞族有 `slash`／`Slash` 卻沒有 `SLASH`
（比對區分大小寫）、有「扣分」卻沒有「扣減」，而那兩個正是觀測台唯一
直接講後果的字。加詞是**放寬召回不是放寬判準**；實測 src 候選 2 → 2，
沒有改變任何既往數字。

## 六、樣本裡本來不含待測物（事後補的一格）

第一次 sweep 的 SLASH 計數是 0，於是 `app.js:105` 那格走「尚未發生」那一支，
**「信用已被扣減」從沒進過 DOM**——而那是觀測台唯一直接講後果的句子，
也就是 S7 紅線的待測物本身。同第 98 輪 `findbad` 的形狀。

補法：挑一筆**稽核實跑且未通過**的交付去做人類仲裁（不是隨便造一筆；
`ecosystem.py:1127` 要求稽核佐證才會真的扣信用），SLASH 1 筆、`credit_applied=True`，
「信用已被扣減」才進畫面（詞頻裡的「扣減 9 次」＝ 9 個狀態各一次）。

## 八、怎麼重跑

```bash
cd ~/vacant/Vacant
python3 runs/s7b_interact_dom.py --canary-app /tmp/s7e_canary   # E1 探針自驗
python3 runs/s7_claim_audit.py  --scan --dom /tmp/s7e_canary    # E1 判定
python3 runs/s7b_interact_dom.py --sweep-app runs/s7e_dom       # 真掃（起 dashboard）
python3 runs/s7b_interact_dom.py --check-app runs/s7e_dom       # E0/E2/E3/E3b
python3 runs/s7_claim_audit.py  --scan --dom runs/s7e_dom       # E4
python3 runs/s7b_interact_dom.py --freq runs/s7e_dom            # E4d 獨立詞頻
```

`runs/s7e_dom/root.txt` 記的是那一次的 `/tmp` root（重開機就沒了，
留著只當出處紀錄）。`--check-app` 的 E3b 需要它存在；重跑 `--sweep-app`
會產生新的 root 並覆寫這個檔。
