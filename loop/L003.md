## 3. 候選假說（草稿，未承諾；判準先於任何修改寫下）

**已查而排除**：環境缺件（pytest/pip）非 C 特有——F-6（A 臂 pg_bowling 同缺，任務觸發非系統性）。

**假說 H（兩部分）**：
- **(a) 盲迴圈（主因、兩臂共有、非產品機制）**：模型對解不出的題反覆重寫＋重跑同一失敗
  簽名；C 格陷入更深（1.5–7×）主要為採樣變異（4 格 0 產品訊息，F-3）。
- **(b) stop check 單次 nudge 延長（產品機制、時序證據在 2 格、已受既有上限約束）**：
  agent 想收手時，stop check 以事實陳述（最後測試失敗）回「Fix … and re-run」→ 把
  「A 放棄收尾」變成「C 繼續燒到 1800s」（poker-C：訊息在 40% 處、其後再燒 60%；
  list_ops-C：訊息在 97.6% 處、殘效很小）。
  **既有上限（prior art，本輪實讀）**：`vacant_network/trace/zerostop.py:47`
  `TEST_FAILED_MAX_ROUNDS = 1`（`pushable_for:235`）——「測試失敗」同對話內最多只退一回合，
  docstring 明寫「避免 12B 模型在同一對話內無效死循環」；另 `ZERO_MAX_ROUNDS = 2`（:45）、
  `UNREAD_MAX_ROUNDS = 1`（:46）。⇒ 觀察到的 2 格各 1 條訊息**正落在既有上限內**；
  「每 session ≤1 次 continue」不是待改、是現況。(b) 的殘留＝**那唯一一次 nudge** 本身。

**改的位置（選項，待 e009 完賽＋判準鎖定後選一）**：
- **選項 0（不改）**：若完賽數據顯示逾時差距主要是 (a)（A 臂在別題亦有多逾時、或重跑 e002
  同題 A 亦逾時），結案為「模型盲迴圈＋量具邊界（nudge 是設計中的 accountable 行為）」，不改產品。
- **選項 1（最保守、loop-aware 抑制）**：同一（命令、失敗簽名）在紀錄步驟中重複 ≥3 次時，
  `test_failed` finding 不再 push（放行收手、chain 照記、note 照寫）——「模型已試 N 次仍盲迴圈，
  nudge 只延長燒預算」。改點＝`evidence.py` 的 `_failed_steps`（:2000–2075；test_failed
  finding 產生於 :2058–2068）——在那一串「豁免」規則裡加一條「同命令同失敗簽名 ≥3 次＝
  盲迴圈、豁免」；`zerostop.pushable_for`／`TEST_FAILED_MAX_ROUNDS` 不動；hook 端不動。
  （上游豁免＝finding 根本不在，chain 上無此 finding、note 仍寫其他項。）
- **選項 2**：loop-aware 措辭——同條件下 nudge 改為「同一測試已失敗 N 次且輸出相同；
  可以停止並回報現狀」，不說「Fix … and re-run」。改點＝`review.py:108-111`（test_failed
  行渲染，即 e009 兩格訊息的逐字來源）＋`evidence.py` 產生端附 loop 計數欄位。
  風險：措辭對 12B 模型的行為效應未驗，需 smoke 實測。（REVIEW_HEADER 在
  `feedback.py:46`＝訊息開頭「Before delivery: …」，本選項動的是後續 test_failed 行。）

**預期翻轉（若改，只對 (b) 格）**：選項 1/2 只影響「有 nudge 且模型盲迴圈」的格（現觀察到
poker-C、list_ops-C）：C 應在 nudge 點附近收手（poker-C 現 91 calls/3.03M tok，應接近 A 臂
33 calls/0.76M tok 的量級）。**無 nudge 的 4 格是 (a) 模型盲迴圈，產品改動對它們無效**——
若改後仍逾時，那是 (a) 的證據，不是改動失敗。pg_grep 的 A 過 C 掛是 (a)（C 零產品訊息、
56 次重跑），不預期由 (b) 改動翻轉。

**判準（pre-registered，改前鎖定）**

  test_failed nudge 的 C 格）**全部收手**（rc≠124；現狀 0/2 收手）且無新增「A 過 C 掛」。
  （若 smoke 中無 nudge 格＝未觸發，C1 記 UNKNOWN 不記達。）
