## 二、跟 round456 訂的推翻條件對照

`DECISION_20260901_R456_SCALE_FOR_POWER.md` 第三節寫死：「如果下一批
（scale2）的 ON void 率遠高於 35%（例如後端進一步惡化到 round23 的 57%
那一端），…屆時要重新評估是否值得繼續加碼」。

**觸發了**——66.7% 不只遠高於 round456 的 35% 參考點，也比 round23 歷史
最壞的 57% 還高。統計檢定（n=12 太小，先確認不是純噪音）：

```
P(X>=8 | n=12, p=0.35 舊參考點) = 0.0255  → 顯著高於 round456 的參考批次
P(X>=8 | n=12, p=0.57 round23最壞值) = 0.356 → 跟「落在歷史最壞那端」相容，不顯著
```

**判讀**：這不是前所未見的新故障模式——67% 落在 round23 當年
（33-57%）紀錄的延伸範圍內是可信的（第二個檢定不顯著），只是這次的
後端壅塞程度落在那個歷史區間的更差一端，而不是 round456 那批溫和的
35%。n=12 仍小，隨著批次跑完可能回歸到歷史區間中段，也可能不會。

## 三、重新評估：續跑還是換做法

**決定：續跑，不殺、不改任何參數。**

- **選了什麼**：讓 PID 2513538 按原計畫跑完 60 題，照實記錄最終 void 率；
  不因為中途 67% 就提前判死刑。
- **放棄了什麼**：
  - 沒有調寬 `review_timeout_s`（跟 round456 同理由：那是 round23 的既定
    取捨，改它是改變實驗條件，不是本輪該做的判斷）。
  - 沒有殺掉重開——已經花費的 62 分鐘與 4 個成功樣本殺掉即歸零，而根因
    （後端壅塞）不會因為重開就消失，重開沒有預期收益。
  - 沒有現在就寫「70 個配對任務」的檢定力目標已經破產——這批若維持
    67% void，60 題預期只有 ~20 題成功（而不是 round456 那批的 39
    題），需要下一輪算完才知道實際數字，現在下結論太早。
- **根據什麼**：兩個二項檢定的結果——「顯著偏離 35%」但「跟歷史最壞值
  相容」——是量出來的，不是猜測。
- **什麼條件下該被推翻**：
  1. 若跑完 60 題後整批 void 率仍 >60%（即這次不是短期波動，是新的
     壅塞水位），下一輪要重新評估：継續加碼這個方向是否划算，或改用
     round456 第四節寫的 CMH 合併法，把這批打折後的 ON 樣本跟舊批
     （round456 的 39 題）合併，而不是硬湊到單一 70 題的批次。
  2. 若 void 率在跑完後回落到 35-45% 區間（跟 n=12 時的噪音一致），
     維持原計畫（下一輪接著跑同 seed 的 OFF5 對照臂）。
