# DECISION 2026-11-27 — 證據式決策控制器（續做／修復／重開／保留最佳／提前結束）：設計凍結

> 決定者：vacant-hope 11-27（擁有者轉來校外展只剩約一週；停止大範圍探索，只做這一件）。本檔在看任何正式資料之前凍結；門檻數值不再改。

## 研究問題（凍結）
在同樣的運算預算上限下，小模型能否靠可驗證的執行紀錄與驗收結果，由 Host 決定續做、修復或重開，而比固定重開做得更好？

## 控制器（確定性規則表，不加模型審查者）
每次嘗試結束後，Host 在驗收測試上得到：每條測試的通過／失敗、失敗簽章（失敗測試名的排序集合）、通過數，以及和「目前最佳版本」的比較，還有剩餘預算。規則**照下列順序**比對，第一條成立的就執行：

1. **全部驗收通過 → 提前結束**，交付這一版。
2. **預算耗盡 → 交付最佳版本**（驗收通過數最多的那一版；同分取最新），並列出未滿足的項目。
3. **這一版比已知最佳差**（通過數 < 最佳）→ **回到最佳版本的快照**，再從那裡續做；回饋用最佳版本的失敗資訊。
4. **沒有進展**：和上一次的失敗簽章完全相同、通過數沒有增加，而且這是**連續第 2 次**出現同一個簽章 → **丟掉工作區、從原件重開**。提示明講「上一種做法卡在這些測試：…」。最佳快照保留，供交付用。
5. **大部分通過**（通過數 ≥ 驗收總數的 **70%**）→ **保留工作區、針對失敗項修復**。回饋給失敗測試的名稱與訊息。
6. **其他情況**（含通過數增加、沒有新壞掉的）→ **保留工作區續做**，附具體失敗資訊。

- 寫死的門檻：「大部分」＝≥70%；「沒進展」＝同一失敗簽章連續 2 次而且通過數沒增加。每次嘗試上限 600 秒、總預算 1800 秒、最多 3 次嘗試（和 R、B 同）。
- 回饋文字：B 與 C 用**同一個產生器**——失敗測試名稱，加第一個失敗的訊息，合計 ≤400 位元組（沿用 harness 的 first_failure 上限）。C 只多一行動作說明（例如「保留你的工作區，修這些失敗」「從頭重來：上一種做法卡在…」）。
- **每次決策都寫成簽章鏈上的事件**（`vacant_network.logbook`）：依據的證據（各測試通過／失敗、失敗簽章、和最佳版本的比較、剩餘預算）、所選動作、規則編號。事後任何人都能從鏈重建「為什麼在這裡重開」。
- 放在 `vacant do` 的父行程裁決路徑上（選項開啟，預設行為不變），同一份決策模組也給實驗 harness（`ops/redo/redo.py` 的新政策 `controller`）用。

## 實驗（探索性，只判斷方向）
- **題目挑選規則（凍結）**：

- **模型**：qwen3.5-9b（pi，本機 LM Studio，ctx 131072）；時間夠再加 gemma-4-E4B。
- **指標（只看五個）**：
  - 獨立評分的最終成功率（hidden 半數全過）。
  - 需求（hidden 測試）滿足比例。
  - 每個成功任務的實際 token。
  - 已通過項目被弄壞的比例：曾在某次嘗試通過、交付版卻失敗的驗收測試，占曾通過者的比例。
  - 等待時間（牆鐘）。
- **判讀（凍結）**：報 C 對 B、C 對 R 的成功率差（題×重複配對）與成本差。明寫「這是 16 題的探索，只判斷方向」。C 沒有比 B、R 好就照實寫，不延伸。
