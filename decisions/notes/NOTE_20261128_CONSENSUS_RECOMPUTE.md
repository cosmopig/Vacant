## 多數決規則（讀 `consensus_offline.py` 確認，沒有執行）

- 票＝canon_strict 後的值；**空白不算票**（`can is not None` 才計）。
- 取得票最多者；**平手取「最小 r 的那份先出現的值」**（`first.setdefault`＋`min(..., key=首見 r)`）。
- 5 份全空白的行＝空白，算錯（分子不加）。
- 逐行 oracle：該行任一份對即算對。

### 兩個選擇會不會影響結果

**沒有逐行資料，無法各算一次，所以不能說影響多大。** 只能給方向與界：

- 把空白算一票：只會讓「空白是嚴格多數、或平手時 r 較小者是空白」的行變成空白；原本若選到對的值，會變錯，
  選到錯的值則不變。所以**準確率只會持平或下降，不會上升**；大小取決於空白多的行，而這批 154 跑裡有 44 跑 context 用盡（`drafts_runs`）、r1／r2 配對裡有 21 對的草稿含空白（`blank_draft_pairs`），
  空白不是小量，不能當作可忽略。
- 平手規則（取最小 r）：任何只在 1 對 1／2 對 2 平手時換選法的規則，結果都落在逐行 oracle 以下，
  即最多比現值高 0.812−0.746＝6.7 個百分點（上界，不是估計）；也可能更低。
  取最小 r 對對錯是任意的（r 與品質無關，除非早出的草稿有系統差異，這點沒檢查）。
- 這兩個選擇都**影響的是「多數決−record／nonblank」那兩個本來就沒有差別的比較**，不影響多數決−A 的結論
  （差 28 點遠大於上界以外的任何一種規則變化可能抹掉的量，但這句也是推論，不是重算）。

## 一致度旗標的定義與門檻

- 只看有填行（canon 非空）。一份的某行**旗標＝(它的值 ≠ 多數值) 或 (有相同值的份數 ≤ 1)**。
  即：自己是孤票（k=5 中只有這一份寫這個值）就旗標；或在平手裡沒被選為多數值的那一組（即使有 2 票）也旗標。
  所以門檻是「同意份數 ≤ 1」加上「不是被選中的多數值」，並不是單純「票數低於某個數」。
- **門檻是事前定的還是事後選的：從資料看不出來是事前定的。** 腳本與提交訊息都標明「事後離線分析、非預註冊」；
  `consensus_offline.py` 只有一個提交（6796ec83），沒有掃描多個門檻的痕跡，也沒有預註冊檔提到它；
  但分析是在確認批次已看過 v1–v4 結果之後做的。照實寫：**單一門檻、沒有看到調整記錄，但不是事前凍結的**，
  因此不能當預先宣告的判準；能說的是「事後、單一定義、沒有量到掃描」。我沒有 git 之外的紀錄可以排除
  他們在本機試過別的門檻。

## 2. 第二正規化器與誤判風險

規則：(a) 年齡：答案含「N years ago」，去掉後 `canon_strict(答案)＝canon_strict(值)`；(b) 代號：欄位＝Traded as，值抽出的（交易所, 代號）
非空且為答案抽出集合的子集。`canon_strict` 只留數字記號、忽略所有文字，所以：

- **年齡規則等於「日與年的數字都相同」**。合成案例（不是資料裡的值）：年份錯、日錯、只寫年份、寫了年份加年齡括號都不判相等（正確）；
  **月名寫錯但日年相同會判相等（誤判風險，案例已重現）**；他語月名正確地判相等。這和原評分器的盲點相同（原本就不看月名），
  所以不是新增的寬鬆，但修正後它會讓「月名錯、日年對」的行從錯變成等值。資料裡有沒有這種行，我無法查（值不在 git）。
- 判別 p 是獨立的旁證：K-等值 131 行 V1 平均 p 0.96（130 行 p≥0.9）、U-等值 53 行 0.94（47 行 p≥0.9）——頁面讀到的是同一個值，
  與「值是對的」相容，但 p 量的是頁面支持，不是對照答案，不能當作證明。
- **代號規則偏寬：** 子集比對讓「只寫答案兩個上市地中的一個」也算相等；只寫代號不寫交易所抽不出對，不算（留在 U，5 行）。
  交易所清單是白名單。這條規則涉及 55 行（占量具等值 30%），我無法重跑。
- 結論：兩條規則不會把年份錯、日錯的值判對；有月名錯與只列部分上市地兩個已知的偏寬方向，影響行數未知（上界＝129 與 55）。
  即使把這兩類全當成不確定，也不改變「大部分公司組錯行是量具造成」的方向，但 84% 這個數字帶這個不確定。
