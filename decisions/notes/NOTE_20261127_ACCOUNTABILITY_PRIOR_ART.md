## 3. (c) 我的提案（以下全是推論，不是來源）

出發點：來源層的共同結論——**增益來自「健全的外部訊號＋有權力讓它真的重來」，不是來自「說出理由」**。這與本 repo 自己的結論一致（`docs/ZERO_CONFIG_EVAL_REPORT_2026-09-26.md`：過去有增益的都是 Vacant 握著生成；`CLAUDE.md` 零設定一節：量得到差別的只有「說做完卻沒寫要求的檔」）。

### 3.1 提案一：紀錄式證據分數做 best-of-n，或「退回就丟掉重開」

- 機制：同題跑 n 次（新行程、乾淨工作區），用 T 的紀錄檢查（空行、值不在任何抓回內容中、沒抓來源就改值）給每一份交件一個「沒根據行數」分數，交分數最低者；平手隨機。
- 文獻判斷：Large Language Monkeys 說增益取決於驗證器；紀錄式檢查是**弱驗證器**（「有出處」≠「對」），所以預測**只在錯誤型態以「缺／沒出處」為主時有增益**，其餘退化成隨機挑。這與 `ops/redo/` 的 R3（測試沒過就重開）同方向，但訊號換成紀錄。
- 最便宜的測試：先離線——把 T 已有的多次跑次當樣本集，模擬三種挑法：(i) 單跑；(ii) n=3 隨機挑；(iii) n=3 取證據分數最低。零機時。只需要 (iii) 贏 (ii)。
- 風險：依 Baker 2025，若模型被訓練去迎合這個分數，會學會填「有出處但錯」的值；這裡不訓練、只選擇，風險小。

### 3.2 提案二：退回時附「新資訊」，不只附理由

- 機制：被標記的行，回饋裡附上「抓回的內容裡與該欄位最接近的 1–3 個候選片段（原文引句＋所在檔）」，或要求先重抓該欄位的來源頁再寫。
- 文獻判斷：CRITIC、Stechly 後續都指向「新資訊／健全訊號」才有增益；RARR 的流程本身包含「找證據」一步。T 目前的主臂只給理由，預測接近「通用請再檢查」，除非問題就是「漏寫」。
- 最便宜的測試：在 T 的退回臂上加一個子臂「理由＋候選片段」，其餘一模一樣，比較兩子臂最終答對率。候選片段由對抓回內容的字串搜尋產生。**注意**：候選只能用紀錄裡已有的內容、提示字句要過 KS-1。
- 風險：候選片段若直接含答案，等於替模型答題；要把它定位成「證據顯示」，結果另外報「值是從候選片段抄的比率」。

### 3.3 提案三：證據薄弱時升級到較強模型（路由）

- 機制：第二輪之後仍被標記的行，只把那幾行交給較大的模型重做（其他行不動）。
- 文獻判斷：我這一輪**沒有查路由／級聯的文獻**，所以這條只有推論支持。Large Language Monkeys 的搜尋摘要稱「便宜模型多取樣有時勝過貴模型單次」（SWE-bench Lite；未驗證），表示「升級」與「重抽」要比成本，不能假設升級更好。
- 最便宜的測試：離線——對 T 已有紀錄中最終仍被標記的行，各用大模型單跑一次（小批量），看多少被改對、花多少 token，與提案一的第三次重抽比成本效益。
- 風險：需要第二個模型端點；排在前兩者之後。

優先順序（推論）：3.1 最便宜（可離線）、3.2 次之（只改提示）、3.3 最後。

## 4. 對實驗 T／N 的直接含意

### 4.1 實驗 T

**預測「沒有增益」的已發表發現：**
1. Huang 2023、Kamoi 2024：沒有新資訊的修訂沒用或變差——T 的「通用請再檢查」對照臂**應該**接近單跑。這是對照臂的預期，不是主臂的預期。
2. Stechly 2023/2024：增益綁在「驗證器健全」。T 的檢查只說「值沒出現在抓回內容裡」，不說對錯；9B／E4B 在 Wikipedia 上最常見的錯若是「抓到了、但讀錯了數」，T 抓不到。
3. RARR 量的是歸因不是正確率：T 的主臂即使把「有出處」拉高，答對率也可能不動。
4. Large Language Monkeys：只有弱驗證器時增益很小。
5. 本 repo 自己的歷史：零設定 Stop 檢查大多沒有量到差別（`CLAUDE.md` 零設定一節）。

**預測「有增益」的已發表發現：**
1. CRITIC、Reflexion、SWE-Gym：有可執行或工具提供的外部訊號時有增益——T 的訊號是「來自執行紀錄的客觀事實」，比自我批評強。
2. 本 repo 的 DABstep 結果：+11 個百分點幾乎全來自「沒寫檔就退回補寫」——T 的「空行」類退回與這相同；若小模型常漏寫行，預測有增益。

**預測「沒有增益」的已發表發現：**

**預測「有增益」的已發表發現：**
