## 一句話

- **T 的增益幾乎一定來自「空行」**。空行不需要紀錄就看得出來，所以 T 量到的是「叫它補空行」，量不到「紀錄有用」。
- **N 量的是一個本 repo 自己的鐵律（KS-1）明令排除的變因**，而且這個做法做成產品就會違反零設定原則。結果不管好壞，都進不了展場。

## 實驗 T（逐行標記退回）

### 1. 沒控制的混淆

- **空行的標記是定義出來的，不是發現。**
  - 〔事實〕exp1 的 F1 定義寫著「沒有值＝找不到出處」，所以「紀錄標到 99.6% 的空行」是同義反覆。
  - 〔事實〕排除整行沒寫之後，標記內外錯誤率比只剩 1.30（門檻 3），只比隨機好一點。
  - 〔事實〕exp1 寫的是「錯誤約一半是整行沒寫」，任務說明寫約 70%。出處要對上同一份資料。
- **位置資訊和理由綁在一起。**
  - 標記臂同時告訴模型「哪幾行」和「為什麼」；通用重查臂兩者都不給。
  - 差異可能全來自「哪幾行」，而這個資訊連最笨的「找空行」腳本都給得出來。
- **觸發條件也帶了資訊。**
  - 如果通用臂是無條件送 2 輪，標記臂只在有旗標時送，那「有沒有收到第二輪」本身就是訊號，回合數和 token 也不對等。
- **「值出現在抓過的內容裡」會獎勵亂抄。**
  - 〔事實〕exp1 的「讀錯值」（值在頁面別處）召回只有 11–29%，軟體＋公司 5–12%，是盲點。
  - 〔推論〕第二輪模型只要從頁面抄任何一個數字，旗標就消失。短數字（年份、個位數）幾乎在每頁都找得到，子字串比對會被巧合騙過。
- **通用控制組本身可能造成傷害，讓對照看起來更差。**
  - 〔事實〕D2′ 裡大範圍指令讓 9B 刪掉對的行：d 臂在 r2heldout_b 刪改 264 條，236 條發生在無關週期。
  - 〔推論〕T 若贏過通用臂，有一部分可能是通用臂把東西改壞，不是標記有幫助。
- **答案鍵和評分器。**
  - 〔事實〕exp1：只比第一個數字時比值是 13.89，嚴格比對所有數字時是 1.87；「3 years ago」這類相對時間字尾會被算錯；新教材的答案鍵沒有人工核對。
- **頁面會漂移。**
  - 〔事實〕exp1 重抓用的是教材當期的凍結頁面檔。
  - 如果 T 抓的是即時維基百科，答案鍵和頁面之間、先跑的臂和後跑的臂之間都會漂移，臂的差別和時間的差別混在一起。
- **預算不對等。**
  - 原生單跑拿到的回合、token、牆鐘都比較少。
  - 〔推論〕空行有一部分是預算或上下文用完造成的，多給一輪本身就會補上一部分。

### 2. 缺的對照（依資訊量排序）

1. **只補空行臂**：只退回空行，可以帶理由。T 標記臂減掉這一臂，才是「紀錄」的邊際貢獻。
2. **只標位置臂**：列出全部被標的行，不給理由。分開「哪幾行」和「為什麼」。
3. **觸發相同的通用臂（yoked）**：用該臂自己的紀錄算旗標，有旗標才送，但只送「請再檢查」。分開「訊息內容」和「觸發條件」。
4. **神諭旗標臂**：用答案鍵標出真正錯的行，套同一個模板。這是這種機制的天花板；連它都沒有增益，就不必再調標記。
5. **全新重開臂**：〔事實〕過去量到的增益都來自「可執行驗收＋重抽」，修訂迴圈在重抽之上的增量最小（零設定總報告 §八）。
   `ops/redo/redo.py` 已經有 `restart` 政策加 `hint`，可以把「被標的行」當提示，接上去只要改計畫檔。

### 3. 會誤導的指標

- **「全部行的正確數」會把「空行變成錯值」算成中性甚至加分。**
  - 對使用者來說，誠實的空白看得到，錯的數字看不到。
  - 必須並列：填寫行的精確率、空→錯、對→錯（傷害），以及原本就填寫的行上的正確率。
  - 〔事實〕這正是 v3 回合預算提醒被關掉的原因：多交出來的 63 跑裡 25 對、38 錯，人類 09-27 決定預設關（CLAUDE.md，v3.6）。
- **「旗標清除率」不是正確率。** 旗標可以靠抄任何頁面數字清掉。
- 要分層報告：空行／非空 F1／F3，以及數字長度（≤2 位、3–4 位、更長）。

### 4. 結果出來後會超出證據的說法

- 「Vacant 的紀錄讓 agent 交件更正確」：要有臂 1 加分層才能說，而且只限於維基百科資訊框的數字抄寫。
- 外推到一般 agent、程式任務或沒有出處可比的任務：exp1 的已知限制已經寫了「只適用內容抄自來源的交件」。
- 「能指出錯在哪」：exp1 已經明文禁止這句話（讀錯值是盲點）。

## 實驗 N（「會被獨立驗證、簽章記錄」段落）

### 1. KS-1

- 〔事實〕KS-1 是鐵律第 1 條，違反＝run 作廢。它禁止 prompt 出現責任／懲罰修辭。
  - 可執行防呆 `memory.assert_ks1_clean` 只比對 8 個固定片語（`你有責任`、`you will be held accountable` 等）；
  - 產品回饋另外加了「沒有行動者」（`trace/feedback.py`）。
- 〔推論〕N 的段落大概能通過字串比對：「will be independently verified, every step… signed and recorded」不含那 8 個片語。
  - 但它正是 KS-1 要排除的東西：靠「你被看著」修辭改變行為，而不是靠機制。
  - **通過黑名單不等於合規**；黑名單擋的是手滑，不是這種刻意設計。若英文版用了「held accountable」，連字串比對都會擋下。
- 這代表三件事：
  1. N 只能當成「KS-1 的動機是否成立」的科學問題，**要先由人類在 `decisions/` 寫明豁免**。資料不可和任何產品或零設定證據合併。
  2. N 做成產品，會同時違反 KS-1 和已經對外宣稱過的「沒有問題時每一通請求和沒裝時逐位元組相同」（CLAUDE.md 零設定口徑）。
  3. 〔推論〕N 若有效果，反而是對 Vacant 的警告：產品裡任何讓模型察覺「被記錄」的痕跡，都可能造成修辭效果，被誤讀成機制效果。

### 2. 混淆與缺的對照

- **框架和指令綁在一起。** 段落同時有「稽核框架」和「實際去跑測試並列出結果」的程序指令。
  - 〔推論〕小模型的反應多半來自後者。最少要 2×2：中性／框架 × 有指令／沒指令。至少要補「只有指令、沒有稽核框架」這一臂。
- **說法真假要看臂的條件。** 兩臂是否真的都有簽章記錄？
  - 沒有記錄卻說有，量到的是「被告知被看著」的效果；
  - 兩臂都有記錄，那 N 只是告知與否。這兩種不能都叫「可究責性」。
- **任務裡有沒有測試，會改變整個題目。**
  - 工作區有可見測試時，「去跑測試」直接提供正確性訊號，成功率提升＝指令效果；
  - 沒有測試時（例如 exam37 的設計：工作區不放測試），它只會叫模型寫自己的測試，自己寫的測試很容易一跑就過。
- **中性段落的內容和位置。**
  - 中性段落等長但內容不同，可能本身就造成干擾。
  - 段落位置會影響 prompt 前綴快取命中率，進而影響速度和逾時。〔事實〕D2′ 已經出現 600 秒逾時主導成本比的例子。
  - 兩臂要綁同一台機器、交錯發射（`redo.py` 已經做到一對兩臂綁同機）。

### 3. 會誤導的指標

- **「有跑測試」的量法。** 必須是紀錄裡看得到的執行：指令＋退出碼，而且跑的是題目的測試，不是 `print('ok')` 或剛寫好的空殼測試。不可以看模型自己說的。
- **「錯誤宣稱率」的分母。** N 臂被要求列出結果，宣稱數本來就比較多。
  - 以「每一跑」為分母和以「每條宣稱」為分母，方向可能相反。
  - 要事先定義：「說測過／說通過」對上紀錄的退出碼。
- **成功率**：要配對同題、多種子，事先寫好「無法區分」的判定條件。
  - 〔事實〕ctl12 剛以「無法區分」收場（DECISION_20261127_EVIDENCE_CONTROLLER）。

## 2026-11-29 08:00Z 前做得到的最小修正（依「價值÷成本」排序）

1. **〔零成本〕在發射前推上一份預註冊**（寫進 `decisions/prereg/`）。內容：
   - T 的主要指標，並列填寫行精確率和傷害數；
   - 依空行／非空 F1／F3 與數字長度分層；
   - 凍結嚴格評分器；
   - 寫明「無法區分」的條件。
2. **〔零成本〕T 的通用臂改成觸發相同的 yoked 設計**；每臂報告回合數、token、牆鐘。
3. **〔低成本〕頁面固定**：用 oldid 或 realrev 的凍結頁面伺服器，不抓即時頁面。答案鍵抽 20 條人工核對（exp1 的做法）。
4. **〔一臂的成本〕加「只補空行」臂。** 這是 T 能不能談「紀錄」的關鍵。算力只夠加一臂時就加這一臂；要省算力，寧可砍掉通用臂。
5. **〔一臂的成本〕加神諭旗標臂**，界定天花板，結果很好判讀。
6. **〔N〕** 先由人類寫明 KS-1 豁免。把 N 縮成「只有指令」對「框架＋指令」一對，事先定好「有跑測試」與錯誤宣稱的量法。
   - 算力不夠時，**建議整個延後 N**：它對展場沒有差別（CLAUDE.md 的判準），也做不成產品。
7. 只補位置臂、全新重開臂：有算力再加。全新重開可以直接用 `redo.py restart`＋提示。

## 預測（標為預測，不是結果）

- **T**：
  - 標記臂的「全部行正確數」會比原生單跑高，主要來自空行被補上；
  - 對「觸發相同的通用臂」差距會小很多；
  - 對「只補空行臂」會無法區分；
  - 填寫行精確率會下降，空→錯的數量不會小；
  - 非空 F1 的退回幾乎改不對讀錯值的行。
  - 理由：exp1 排除空行後比值 1.30；DABstep 的 +11pp 是「沒寫檔被叫回來補」，而且 CLAUDE.md 寫明那一次「變的是 A」；09-27 的預算提醒多交的大多是錯的。
- **N**：
  - 9B／E4B 的成功率量不到差別；
  - 「有跑測試」會小幅上升，幾乎全部可以歸給指令句；
  - 錯誤宣稱的絕對數會因為列得比較多而上升。
  - 理由：零設定總報告的結論是「未經訓練、提示層級、沒有正確性訊號」的介入，文獻不預期會有增益，本專案也一再量不到。
