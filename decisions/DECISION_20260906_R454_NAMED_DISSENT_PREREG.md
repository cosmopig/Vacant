## 〇、為什麼是這一輪

R453 的稽核（`DECISION_20260906_R453_FABLE_AUDIT_REAL_MULTIPARTY.md` §三-3）
把限定寫得很白：

> 那條路徑**（R449 §三「說謊者 100% 被指名」仍只有模擬證據）……

> **k=2 的 quorum ＝ 2 ＝ 全票**，所以本輪**沒有量到**「少數方被指名」那條路徑：
> 兩台一致時無從產生少數方。

也就是說：整條「不一致 ⇒ 可歸屬 ⇒ 指名」的機制，到現在為止**只有模擬證據**
（R449 §三-1：說謊者 100% 被指名、誠實者 0% 被誣告、有耐心的說謊者偵測率 0.000）。
真跑那一側，R453 只證明了「誠實者會一致」——一致的時候，指名路徑根本不會被走到。

`form_verdict` 有沒有指名對人。這是 R449 §三 那張表第一次拿到真跑證據。

**本輪不測的東西（先講在前面）**：不測有耐心的說謊者（R449 §三-2 的偵測率 0.000
本輪一個字都不會加強或推翻）、不測腐化比例過門檻、不測驗收套件本身腐化

## 三、腐化設計：**確定性、預註冊、可獨立重算**

K3 的腐化**不是隨機的**，是一個純函式，只吃 `(seed, task_id, cand_index)`。
任何人拿到這份文件就能在不跑任何沙箱的情況下，**逐格重算出哪一格 K3 會說謊**。

```python
SEED = 20260906          # 本輪的腐化種子，寫死在這裡
LIAR_FRAC  = 0.15        # 說謊格比例
EQUIV_FRAC = 0.03        # 自相矛盾格比例（在說謊格之外，兩者互斥）

def corrupt_role(seed, task_id, cand_index, liar_frac, equiv_frac):
    h = hashlib.sha256(f"{seed}|{task_id}|{cand_index}".encode("utf-8")).hexdigest()
    u = int(h[:16], 16) / float(1 << 64)          # [0,1) 的確定性抽樣
    if u < liar_frac:                     return "liar"
    if u < liar_frac + equiv_frac:        return "equivocator"
    return "honest"
```

**腐化施加的時點：沙箱真跑之後。** K3 **真的**渲染、**真的**開沙箱、**真的**跑完那一格，
拿到真實的 `ProbeResult` 之後才竄改要簽的值。所以 K3 是一個「跑了然後說謊」的執行器，
不是一台「沙箱壞掉」的機器（那是 R453 §四 win1003 的情況，兩者不可混為一談）。
K3 的牆鐘因此是**真的**。

三種角色各自做什麼：

| 角色 | 簽出去的 payload |
|---|---|
| `honest` | 與真實 `ProbeResult` 逐欄相同（K3 在 82% 的格子上跟誠實執行器沒有差別） |
| `liar` | `visible_ok` **翻轉**；真值 True ⇒ 簽 `visible_ok=False` 並**捏造** `first_failing_test = int(h[16:24],16) % max(1, n_visible_tests or 1)`、`detail_reason=None`（＝誠實 FAIL 的形狀）；真值 False ⇒ 簽 `visible_ok=True`、`first_failing_test=None`、`detail_reason=None`（＝誠實 PASS 的形狀）。`n_visible_tests`、`loads_ok` 保留真值 |
| `equivocator` | 對**同一格**簽**兩筆**內容不同的證言並依序上自己的鏈：第一筆＝真實結果，第二筆＝上面那條 `liar` 規則的竄改結果。兩筆都簽得過、都在鏈上、seq 連續 |

**以本輪的 1840 格代入上面那個純函式，格數在跑之前就已經算出來（純雜湊算術，
不需要任何證言，因此不違反「預註冊在資料之前」）**：

| 角色 | 格數 | 其中落在量具擋下的兩題（`Mbpp/404`、`Mbpp/587`） | **能進計票的格數** |
|---|---|---|---|
| `liar` | **274** | 1 | **273** |
| `equivocator` | **59** | 1 | **58** |
| `honest` | **1507** | 8 | 1499 |
| 合計 | 1840 | 10 | 1830 |

量具擋下的那 10 格為什麼要另外算：`form_verdict` 在 `gauge_status != "ok"` 時
**在驗任何一筆簽章之前就回傳**（`vacant/peerexec.py` §form_verdict 步驟 0），
`dissenters`／`equivocators` 一律為空、`rejected` 是三把金鑰各一筆
`suite_not_gauged`。那不是「沒指名對人」，那是**這一格根本沒有進入投票**。
所以 P-1／P-3 的分母是 **273／58**，而不是 274／59。這個扣除是**在跑之前**算好的，
不是事後看到結果才減的。

## 四、預測（P-1 … P-6），窗口寫在括號裡

**P-1 說謊格指名 K3**：273 個「說謊且能進計票」的格子，每一格的
`Verdict.dissenters` **恰好等於 `("K3",)`**（不是「包含 K3」，是「恰好只有 K3」）。
窗口：**273/273（100%）**。
（機制上為什麼會這樣：K1、K2 誠實且一致 ⇒ 2 票；K3 翻轉 ⇒ 1 票；
`n_pass ≠ n_fail` ⇒ 多數方勝、`dissenters` ＝ 少數方陣營 ＝ {K3}。）
**任何一格少於 273 都要逐格列出並歸因；沒有具名的機器層原因就是 NAMING_FAILS。**

**P-2 誠實金鑰零誣告**：`K1`、`K2` 出現在
`dissenters ∪ detail_dissenters ∪ equivocators` 的格數 = **0**（分母 1840 格全體）。
窗口：**0**。

**P-3 自相矛盾作廢、裁決仍成立**：58 個「自相矛盾且能進計票」的格子，
每一格都同時滿足三件事：
(a) `K3 ∈ equivocators`；(b) `("K3","equivocation") ∈ rejected` 且 K3 的**兩票都不計**
（`n_admitted == 2`、`camp_pass ∪ camp_fail` 不含 K3）；
(c) `visible_ok` 仍然判得出來（不是 `None`）且等於 K1／K2 的誠實標籤。
窗口：**58/58（100%）**。

**P-4 出貨決定不變**：k=3、1 把腐化（腐化數 ≤ 門檻）下，逐題的出貨 sha 與
r446 runtime 的 `gate_code_sha256` 相符 **340/340**，拒交 **26/26**，
量具擋下 **2**（帳目：340 + 3 不可轉 + 2 量具擋 = 345 = runtime accepted 數）。
窗口：**340/340 且 26/26**。這是與 R453 逐字相同的窗口——**一把腐化金鑰不准改變任何
一題的交付決定**。
**任何一格不符且無法歸因到具名機器層原因 ⇒ NAMING_FAILS**（機制在門檻上就已經失效）。

**P-5 三條鏈皆驗真**：`verify_executor_chain` 對 K1、K2、K3 皆為 True。窗口：**3/3**。
⚠ **這一條必須帶著它的意思一起講，否則就是騙人**：K3 是說謊者，它的鏈**照樣驗得過**。
鏈驗證證明的是「這些話確實是這把金鑰說的、而且事後沒被改過」，**不是**「這些話是真的」。
一條合法的鏈是**歸屬**的前提，不是**正確性**的證據。展場那句話必須這樣講。
（K3 的鏈長 = 1840 + 59 = **1899** 筆，比誠實執行器多出自相矛盾那 59 筆的第二簽。）

**P-6 K1／K2 跨機一致（重新量，不是沿用 R453）**：1840 格上 K1 與 K2 的
`visible_ok` 相同。窗口：**≥ 99.5%（≥1831/1840）**，點預測 **1840/1840**。
附帶回報（不進判定）**P-6b**：K3 在它 1507 個 `honest` 角色格上與誠實標籤一致，
點預測 1507/1507——這一條在測「腐化只發生在預註冊的格子上，沒有外溢」。

**預期為零、因此本輪測不到的通道（先寫下來，免得事後被說成量到了）**：
`detail_dissenters` 預期**恆為 0**。原因是本設計的翻轉方向決定的：真值 True 的說謊格
翻成 FAIL 時 K3 是 FAIL 陣營**唯一**成員（`len(camp_fail) > 1` 不成立，不進條號比對）；
真值 False 的說謊格翻成 PASS 時 FAIL 陣營是 K1＋K2 兩個誠實者、條號必然相同。
**所以本輪不測「條號歸屬」那條通道。** 要測它得另設計一種「說 FAIL 但卡在假條號」的
腐化型別，那不在本輪的預註冊裡。

## 五、展場能講的

> 三把金鑰各自跑同一份客戶驗收清單、各自簽名。其中一把說了 274 次謊、還有 59 次
> 對同一件事簽了兩份互相矛盾的證明。結果：**那 274 次謊，每一次都被指到它頭上，
> 一次都沒有指錯人**；那 59 次自相矛盾，兩張證明**一起作廢**，案子照樣由另外兩把
> 金鑰判完。340 題的交付決定跟沒有說謊者的時候**逐題相同**。
>
> 但是——**說謊那把金鑰的帳本，驗起來完全合法。** 帳本能證明的是「這句話確實是它說的、
> 而且事後沒被改過」，不是「這句話是真的」。抓到它靠的是**另外兩把金鑰跑出了不同的
> 答案**，不是靠帳本。所以如果說謊的變成多數，被指名的就會是誠實的那一方，
> 而系統**不會知道自己在門檻的哪一邊**。
