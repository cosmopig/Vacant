# R449：「互跑不互審」的架構稽核——它買到什麼、買不到什麼，以及唯一真正的固定點

（2026-09-05，Fable 5.1 稽核輪。機制與模擬由 Opus 實作（`vacant/peerexec.py`、
`ops/gain/replay/peer_exec_sim.py`、`tests/test_peerexec.py` 25 個測試），一名 Opus 攻擊者重跑
整個掃描——200 格 JSON 逐位元相同——並補跑了作者漏掉的「抖動×腐化」格。零 API。
本文件只做裁決；數字全部出自那份掃描與攻擊者的複跑。）

## 一、要解的問題（人類 2026-09-04）

「不能固定評審或委員，一被污染就完蛋。」CONFORM 把信任從評審搬到單一執行器＋單一驗收套件——
效率高，但**再中心化**了。出路：去中心化的不是「審」（意見，昂貴且無訊號），是「跑」（執行，
免費且無損）。驗收測資是確定性的 ⇒ 誠實執行器必然一致 ⇒ **不一致本身就是證據，且能指名**。

## 二、機制（已實作、已測）

k 個互不認識的執行器各自在本機沙箱跑同一份草稿的可見驗收，各自把結果簽進自己的 hash-chain；
多數決裁決；少數派被**指名**（簽章可歸屬）；同一執行器對同一草稿簽出兩份不同結果＝自證犯規，
兩票作廢；套件 hash 不符的簽章不計票（commit-reveal 掛鉤）；平手或票數不足 ⇒ 未決 ⇒ 拒交
（平手不是通過的證據）。輸家可要求另一組執行器重跑（`challenge_rerun`，k 次沙箱、零模型呼叫——
委員會付不起這個，執行器付得起）。

**校準**：k=1、無腐化時，371/371 的閘門決定與 R446 真跑逐位相同（1855/1855 可見標籤、345/345 交付
sha、26/26 拒交）。分數差 1（279 vs 280）是這台 Mac 的 libm 對 `l**2` 與 `l*l` 差 1 ULP，
MBPP+ 隱藏測資用 `atol=0` 比對——**計分端的可攜性問題，不是機制**。攻擊者獨立重現了這個 ULP。

## 三、量到什麼（r446 371 題 × 5 候選、r443 91 題 × 5；k∈{1,3,5,7}；腐化比例 0–70%；五種攻擊）

**它買到的三件事：**

| | 結果 |
|---|---|
| **多數門檻以下（腐化數 ≤ ⌊(k−1)/2⌋）** | 交付準確率與無腐化基線**逐位相同**（100 格），說謊者 **100% 被指名**，誠實者 **0% 被誣告**——四種吵鬧型攻擊（說謊、破壞、隨機、串謀）全部如此 |
| **單點容忍** | 1 個腐化執行器在 k=1 致命（−7.8pp、偵測 0），在 k=3 完全無害（偵測 1.000） |
| **成本** | 簽章＋上鏈 1.0 ms、驗簽 1.2 ms、沙箱 ~630 ms；**可歸屬性只佔整個 run 的 0.2%**。執行器天生平行 ⇒ 每題牆鐘約 0.9 秒——展場秒級要求成立 |

**它買不到的三件事（全部量到，不是猜的）：**

1. **對「腐化比例」沒有抵抗力。** 固定比例下，k 從 1 到 7 交付率一個字都不變（串謀 67.39%、破壞 0%）。
   k 買的是「容忍固定**數量**」，不是「容忍固定**比例**」。過了門檻，裁決翻轉，**指名也翻轉**——
   指向誠實的那一方（誣告率 0.175／0.374）。**機制無法知道自己在門檻哪一邊。**
2. **抓不到有耐心的說謊者。** 只在不會被抓時才說謊的執行器，四個 k、兩個題庫上偵測率全部 **0.000**；
   代價是它 93–95% 的機會都得放棄，所以傷害只有 −1.35／−2.20pp。攻擊者補跑了作者漏掉的
   「抖動×腐化」格：在 0.5%／1% 沙箱抖動下，腐化者被指名的比率仍是誠實者的 34 倍／12 倍——
   **歸屬會退化，不會崩潰**；且 repo 自己的資料顯示 2310 個可見標籤跨機重跑 0 個不一致，
   作者假設的 1% 噪音地板被高估，這一條對機制**有利**。
3. **對驗收套件本身腐化毫無防禦。** 所有執行器誠實、套件換成「載得進就算過」：交付率 −6.47pp／
   −18.68pp，假交付 31%／49%，**四個 k 的爭議率全是 0.0%**——每一票誠實、每條鏈驗得過、
   所有健康指標滿格，系統在交垃圾。

## 四、裁決

1. **採用「互跑不互審」作為 Vacant 的裁決層。** 它把 CONFORM 的單一執行器換成可歸屬的多方執行，
   保留全部交付效果（門檻以下逐位相同），成本可忽略，牆鐘秒級。這是人類「不能固定裁判」的
   要求在資料上站得住的版本。
2. **對外一律帶著三條買不到的東西講。** 尤其第 3 條：它是整個構造**唯一真正的固定點**，
   去中心化執行對它零保護。
3. **下一階的工作只有一件：驗收套件的可究責性。** 三個已有或可立即接上的手段：
   - **commit-reveal**（已實作 `commit_suite`／`open_suite`）：套件 hash 在草稿出現前上鏈，
     事後不能換。它擋的是「看到草稿後改套件」，擋不了「一開始就是爛套件」。
   - **量具驗證擋爛套件**（repo 已有！`probe_instrument` 的「壞解被擋 12/12」）：一套「載得進就算過」
     的套件會讓所有壞樁通過 ⇒ 壞解被擋 0/12 ⇒ 閘門拒絕。**把這一步綁進套件的 commit**——
     套件要上鏈，必須先證明它擋得住一組已知壞草稿。這是對 §三-3 最便宜的部分解，且是現成的。
   - **申訴重跑**（已實作 `challenge_rerun`）：輸家可要求換一組執行器；零模型呼叫。
   剩下的固定點（roster 准入／Sybil、相關性沙箱故障、簽章只認金鑰不認人、需求必須可執行）
   照實列在 `peerexec.py` 的 docstring 與本文件，**不宣稱已解**。

## 五、展場能講的一句（Opus 擬、本輪核）

> 這是機制模擬，不是真模型。k 台互不認識的機器各自跑同一套客戶自己的驗收測資、各自簽名。
> 結果一致，你手上多的是一張自己驗得完的收據；結果不一致，收據會指名是哪一把金鑰說了不一樣的話
> ——這就是可究責性：讓你的依賴有根據。它做不到的兩件事也寫在同一張收據上：說謊的機器一旦過半，
> 指名的方向會反過來指向誠實的那一台；而如果那套驗收測資本身是爛的，k 台機器會一致地、可驗證地
> 交出一個錯的答案，畫面上一個警告都不會亮。

沒有信任、防止、保證；模擬標示在句首；兩個量到的失效模式與主張同句。

## 六、誠實邊界（沿用 Opus 的七條，一字不刪）

需求必須可編譯成可執行驗收；套件是被信任的輸入（§三-3）；腐化分數與 k 的關係（§三-1）；
有耐心的說謊者（§三-2）；roster 准入未建模；相關性沙箱故障（共用同一份 `checks.py`）未建模——
`--flake` 只模擬獨立抖動；簽章識別金鑰不識別主體；MBPP+ 隱藏測資 `atol=0` 跨機不可攜（1 ULP）。
另：r443 的「61/91」在 repo 裡找不到來源（Opus 得 63/91、舊標籤 60/91，可見側 455/455 相同），
引用時要先確認出處。

## 七、推翻條件

- 若真跑（非重放）的多方執行在門檻以下出現與單執行器不同的交付決定 ⇒ 「逐位相同」是重放假象。
- 若「壞解被擋」綁進套件 commit 之後，仍能構造出通過量具卻交垃圾的套件 ⇒ §四-3 第二點作廢，
  套件固定點回到「無解」。
- 若相關性沙箱故障被實測（同一 bug 讓 k 台一致錯）⇒ 需要實作異質沙箱才能宣稱 §三 的表。
