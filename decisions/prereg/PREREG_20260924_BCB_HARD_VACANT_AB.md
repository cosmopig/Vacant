## 一、要回答的問題

使用者把 Vacant 裝進 pi 之後，**「agent 說做完了、其實沒做對」的東西被交出去的比率**，
有沒有比沒裝的時候低？裝了但只記流量（沒有閘門）會不會讓 agent 變差？閘門＋重抽能不能讓
**交出去而且是對的**比率變高？

## 三、組（arm）

| 組 | 有沒有 Vacant | 怎麼叫 pi | 「交出去」的定義 |
|---|---|---|---|
| **OFF** | 沒有 | `pi -p "<prompt>"`（沒裝 Vacant 的 HOME） | pi 退出碼 0 |
| **CH** | 有（常駐 extension，只記流量） | pi 完整路徑，不經 shim | pi 退出碼 0 |
| **GATE** | 有（PATH shim 閘門，可見測試當驗收） | `pi -p` 經 shim | shim 退出碼 0（20＝拒交） |
| **GATE+R** | 有（閘門＋重抽） | GATE 被拒交時，**新的乾淨工作區**再跑 GATE，最多再 2 次 | 任一次退出碼 0（交出的是第一個被接受的那份） |

- GATE+R 的第一次**就是** GATE 那一格（不重跑），重抽只在拒交時發生；成本另計。
- 三組的 pi 設定逐字相同（`models.json`／`settings.json` sha256 在發射紀錄），prompt 逐字沿用 R534：
  `Read goal.md and contract.md in this directory and do what they say. Use your tools to write the file.`
- 鐵律 1（KS-1）：prompt 不含任何「有責任／會被懲罰」措辭；各組的 prompt 逐字相同。

## 五、結果定義（每題 × 每組）

- **對（correct）**：交出去的那份 `solution.py` 隱藏測試全過。
- **假完成放行（false release）**：交出去 ∧ 不對（含「沒有 `solution.py` 卻退出碼 0」）。← 主要指標
- **正確交付（correct delivery）**：交出去 ∧ 對。
- **擋錯**：GATE 拒交 ∧ 那份其實隱藏全過（閘門太嚴）。
- **infra_void**：CH／GATE 那一格的模型呼叫**一通 2xx 都沒有**，或 OFF 那一格 stderr 顯示每一次都是
  HTTP 錯誤（沒有任何成功回應）。該題在受影響的比較中**整題排除**，數量照實報。不補跑。

## 六、假說與檢定

**主要（H1）**：假完成放行率 **GATE < OFF**。每題配對（同一題、同一層），不一致對 `b`＝OFF 放行
∧ GATE 沒放行、`c`＝反之。檢定＝`research.stratified_mcnemar_exact`（三層），雙尾，α＝0.05。
同時報各層的 `mcnemar_exact` 與 `bc_heterogeneity_chisq`（層間是否一致，描述性）。

**次要（Bonferroni，族＝下面兩個，各 α＝0.025）**：TOST 只給等效判定與 CI、沒有 p 值，
沒辦法跟 H2 一起做 Holm 排序，所以用較保守的 Bonferroni。
- **H2**：正確交付率 **GATE+R > OFF**（同上的分層精確檢定），p < 0.025 才算成立。
- **H3（無害）**：正確交付率 CH − OFF 的配對差，`tost_equiv_boot(diffs, delta=0.10, alpha=0.025)`
  （等效界 δ＝10 個百分點；α＝0.025 ⇒ 95% bootstrap CI 整條落在 ±0.10 內才算等效）。
  等效成立＝「只裝 Vacant、沒有閘門，不會讓 agent 變差（在 ±10pp 內）」。

**描述性（不檢定）**：擋錯率；GATE 的「可見過、隱藏沒過」（V/GT 缺口，閘門結構上擋不到的那一塊）；
每組的牆鐘、模型呼叫數、GATE+R 的額外呼叫與重抽次數；各層的 429／infra_void 數。

## 七、停止規則

- 截止時間＝發射後 7 小時。截止前 25 分鐘起，**不再領新題**；已領的題（含重抽）跑完為止。
- 一題的任一組沒有結果（逾時以外的中斷）⇒ 該題整題排除，照實報。逾時（每格 1500 秒）算

- **中途不看結果**：過程中只看進度計數與 infra 異常；分析腳本只在全部收尾後跑一次。
