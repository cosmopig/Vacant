## 0. 研究問題（凍結）

在 gemma-4-12b、每次嘗試 600 秒、APPS 的 stdin／stdout 題上：**harness 用可見案例（題目範例）從三次獨立嘗試裡挑出交付版（S），比三次裡隨機交一份（M）多多少隱藏案例全過的比例？**

- 這回答的是「**harness 用驗收來決定交哪一份**」的增益。
- 它**不是**「有沒有可見測試」的增益：每一次嘗試都看得到題目範例，agent 自己可以跑。
- 這裡的驗收訊號**很弱**：可見案例就是題目範例，通常每題 1–3 筆。結論必須同時報每題可見案例數的分布。
- 展場與對外口徑用「**可究責性／讓依賴有根據**」，不用「信任」。

## 1. 唯一的執行程序：一個池

- 每個（題, 重複）稱為一**格**。每格跑 **3 次獨立嘗試**（槽 1、2、3），每次上限 **600 秒**，**三次都跑完，不提前停**。
  - 實作：一個 `restart` 臂、`stop_on_accept: false`、`max_attempts: 3`、`attempt_timeout_s: 600`；每次都拿滿 600 秒，不被總預算截短。
  - 每次嘗試的 acc／grade 逐次落盤。
  - 槽號＝嘗試序號 k，在 harness 裡決定，跟完成先後無關。
- 每次嘗試都從同一份乾淨原件開始，不帶前一次的任何東西：沒有工作區、沒有回饋、沒有提示差異（`hint: none`）。三次嘗試彼此看不到。
- **三次的 prompt 逐字相同**，就是題庫的 `instruction.txt`。不提其他嘗試、時間或評分；符合 **KS-1**（不得有「你有責任／會被懲罰」類措辭；harness 的 `_KS1_BANNED` 檢查必須開著）。
- 一格的 3 次嘗試**綁在同一台主機**；每次嘗試的開始時間照實記錄。
- **取樣**：模型端的溫度與 seed 寫進計畫檔。溫度必須 **>0**，**不得固定 seed**（不送 seed，或每次嘗試不同）。三次嘗試是否真的不同，由 §6 的發射前檢查 (b) 驗證。
- 執行順序：每台都**以重複為外層**：先跑完所有題的第 1 重複，再跑第 2 重複，依此類推。同一重複內，依題的排序鍵（§4）。

## 2. 四種取法（全部離線計算，只讀紀錄）

每次嘗試記錄三項：
- **可見通過數**：`solution.py` 在題目範例上逐案例比對（§4 的比對規則），通過幾筆；
- `accept`：可見案例**全部**通過，而且至少有 1 筆；
- `h`：隱藏案例全部通過。

| 代號 | 取法 | 這一格的值 |
|---|---|---|
| **S** | 依可見案例挑：取槽號最小的「可見全過」那一次；都沒全過就取可見通過數最多的，**平手取槽號最小的** | 被挑那一次的 h |
| **M** | 三次的平均，也就是隨機交一份的期望值 | (h₁+h₂+h₃)/3 |
| **F** | 取第 1 次（槽 1） | h₁ |
| **O** | 三次裡至少一次隱藏全過。這是上限，**只描述** | max(h₁,h₂,h₃) |

- 可見只有 1 筆時，S 的定義照舊：那 1 筆過了才算可見全過；三次都沒過時，可見通過數全是 0，S＝槽 1。
- S 的平手規則（取最早）和 `redo.py` 的 `_policy_deliver`（取最後）不同。本批次的 S 由分析碼自己算，不用 harness 的交付欄位。

## 3. 主比較、次要比較、門檻、判讀

**主比較 S−M**：每格算 Dᵢ = h(S) − M。估計值 = 所有納入格的 Dᵢ 平均（pp）。
- 檢定：**以題為群集的精確符號翻轉置換檢定**，雙尾 α=0.05。統計量是各題 Σ(3·Dᵢ) 的總和，3·Dᵢ 是整數，所以可以用 DP 完全枚舉 2^T 種符號。
- 區間：以題為群集的 bootstrap，percentile 法，10,000 次，種子 20261128。

**次要比較 S−F**：每格 Eᵢ = h(S) − h₁，用同樣的檢定與區間。
- **多重比較的處理是固定順序**：主比較通過時，才在 α=0.05 下判讀 S−F；主比較沒通過，S−F 只描述。
- 以下都只描述，不檢定：
  - O、O−M、捕捉率 (S−M)/(O−M)、各槽的成功率；
  - **依「每題可見案例數」分層的 S−M**：1 筆、2 筆、≥3 筆三層，各報格數、估計值與群集 bootstrap 區間；
  - 誤收率（可見全過、隱藏沒過）、誤擋率（可見沒全過、隱藏全過），分槽、分可見案例數報。

**最小有意義差與判讀**（依附錄 A 模擬：polyglot 型的池，母體效果約 +6pp）。四種結果互斥，依序判定：

| 判定 | 條件（全部成立） | 固定主句 |
|---|---|---|
| **過** | p<0.05、估計值 **≥3.0pp**、bootstrap 區間下界 >0 | 「在這 N 題 APPS（{層}）、gemma-4-12b、每次 600 秒的條件下，harness 依題目範例（每題可見案例中位數 k 筆）從三次嘗試中挑選交付版，隱藏案例全過的比例比三次中隨機交一份多 X pp（95% 區間 [a, b]，題群集置換 p=…）。這是 harness 用驗收決定交哪一份的增益，不是『有沒有可見測試』的增益。」 |
| **反向** | p<0.05、估計值 <0 | 「依題目範例挑選，比隨機交一份少 X pp（[a, b]）。」 |
| **等價** | 不屬於上面兩種，且 bootstrap 區間完全落在 **(−3.0, +3.0)pp** 內 | 「依題目範例挑選和隨機交一份的差在 ±3pp 以內（95% 區間 [a, b]）；在這個驗收強度下，用驗收挑選沒有帶來有意義的增益。」 |
| **未定** | 其他情況（包括 p<0.05 但估計值 <3pp） | 「沒有確認 harness 依題目範例挑選比隨機交一份好；95% 區間 [a, b] 也排除不了 ±3pp 以內的差，所以不能說兩者一樣。」 |

為什麼門檻定在 3pp：
- 模擬中，「p<0.05 且 ≥3pp」的檢定力只比單看 p 少 0.2–2.1 個百分點（48×3：0.895 → 0.889）。
- 真實效果為 0 時，這條規則的偽陽性率是 0.3–1.5%，單看 p 是 1.7–4.3%。
- 3pp 大約是 polyglot 上預期效果的一半。

等價界限 ±3pp 的限制：真實效果為 0 時，模擬中能判成「等價」的機率只有 17–41%（§7）。所以「未定」是很可能出現的結果，**未定不得寫成「沒有效果」**。

**禁用句**（任何結果下都不准寫）：
- 「證明 Vacant 讓 agent 做得更好」；「驗收讓模型變強」；任何帶「信任」的說法。
- 「有可見測試比沒有好」（本批次沒有沒測試的臂）；「重開本身有用」（本批次只量挑選）。
- 外推到其他模型、其他題庫、其他時間上限或互動使用；外推到有浮點輸出或多解的題（§4 已排除）。
- 判定為未定時寫「沒有效果」「一樣好」。
- 把 M 寫成「實際隨機交件的結果」：M 是期望值（§9-1）。
- 主句不報可見案例數分布。

## 3b. 事前登記的劑量反應分析：驗收強度 k（不進主比較的判定）

**問題**：驗收用的案例越多（判定越強），依驗收挑選的增益怎麼變？這裡的驗收是「隨機抽的隱藏案例」，和主比較的「題目範例」性質不同（見本節最後一點），兩者不畫在同一條曲線上。

**發射條件**：每一次嘗試都對**全部**隱藏案例逐案例評分，逐案例的通過或失敗都存檔（agy 補這個功能）。沒有逐案例紀錄就不發射。

**切分（寫死）**：
- **固定評分子集 G**：每題依 `sha256(f"{id}:{案例序號}:holdout-20261128")` 由小到大取前 **4** 筆隱藏案例。G 在所有 k 下都不變，避免分母漂移。
  - 本節的結果變數是 hᴳ＝該次嘗試在 G 的 4 筆**全過**。它不是主比較的 h（全部隱藏全過）。
  - Mᴳ、Oᴳ、Fᴳ 照 §2 的定義，改用 hᴳ 計算。
- **驗收池 R**＝該題其餘的隱藏案例（不含 G、不含題目範例）。
- **驗收子集**：對每個 k ∈ {1, 2, 4, 8}，從 R 不放回、等機率抽 k 筆。每題每個 k 抽 **B＝200** 次；第 b 次的亂數種子＝`int(sha256(f"{id}:{k}:{b}:dose-20261128").hexdigest()[:16], 16)`。
  - 同一次抽樣用在同一格的三次嘗試上，三次比的是同一組案例。
- **Sₖ**：在同一組 k 筆上，取槽號最小的「k 筆全過」那一次；都沒全過就取通過數最多的，平手取槽號最小的。被挑那一次的 hᴳ 就是這一格這次抽樣的值。每格的 Sₖ＝B 次的平均。
- **k＝0 的定義：S₀＝Mᴳ**，所以 S₀−Mᴳ≡0，是曲線的錨點。
  - 理由：沒有驗收時，任何取法都不看資訊。照 S 的字面規則，三次的通過數都是 0、平手取最早，會得到 Fᴳ；但在三槽可交換的前提下，Fᴳ 的期望值就是 Mᴳ，只是多了「槽 1 恰好是哪一次」的抽樣雜訊。曲線本來就是相對 Mᴳ 畫的，錨點用期望值才不把雜訊放進 k＝0。
  - Fᴳ−Mᴳ 另報，當作槽的可交換性檢查（只描述）。
- **隱藏案例不夠時**（機械規則）：
  - **主曲線**只用 |R|≥8 的題，也就是隱藏案例 ≥12。所有 k 在同一組題上算，題目組成不隨 k 改變。
  - **副曲線**用全部正式題，每題只算到 k ≤ |R|，題目組成隨 k 改變，只描述。
  - 不改 §4 的選題規則（隱藏 ≥6），主比較不受影響。正式題中隱藏 ≥12 的題數照報；**少於 20 題時，主曲線只描述、不做趨勢檢定**。

**每個 k 要報的東西**（主曲線與副曲線各一套；以題為群集的 bootstrap 95% 區間，10,000 次，種子 20261128）：
- Sₖ−Mᴳ（pp）與區間；
- 誤收率：k 筆全過、但 hᴳ 沒過的比例（在 k 筆全過的嘗試裡）；
- 誤擋率：k 筆沒全過、但 hᴳ 過的比例（在 k 筆沒全過的嘗試裡）；
- 這兩個率都是對 B 次抽樣與全部嘗試取平均。
- **增益上限**＝Oᴳ−Mᴳ（三次至少一次 G 全過 − 單次的期望）。它不隨 k 變，畫成水平線；每個 k 並列捕捉率 (Sₖ−Mᴳ)/(Oᴳ−Mᴳ)。

**曲線與單調性**：
- 要報的曲線：橫軸 k＝0、1、2、4、8，縱軸 Sₖ−Mᴳ，附區間與增益上限的水平線。另兩條是誤收率與誤擋率對 k。
- **趨勢檢定（本節唯一的檢定）**：
  - 只用 k ∈ {1, 2, 4, 8}，不含錨點。錨點恆為 0，含進去的話，「有一筆驗收就比沒有好」會讓斜率幾乎一定顯著，量不到「再加強有沒有用」。
  - 每題把 (S₁, S₂, S₄, S₈)−Mᴳ 對等距的序位 0、1、2、3 做最小平方斜率。
  - 檢定：以題為群集的**精確符號翻轉置換檢定**，斜率四捨五入到 0.001pp 的整數倍後用 DP 枚舉，雙尾 α=0.05。
  - **獨立家族**：不和主比較、次要比較共用校正，也不影響 §3 的判定。
- **單調性只描述**：報四個點估計是否非遞減；不另做單調性檢定。
- S₁−Mᴳ（一筆隨機隱藏案例的增益）只描述、附區間。
- 讀法事前寫死：
  - 斜率顯著為正 ⇒「在這批題上，驗收案例從 1 筆加到 8 筆，依驗收挑選的增益隨之增加（每一級約 X pp）」；
  - 不顯著 ⇒「沒有量到增益隨 k 增加」，不得寫成「k 沒有影響」；
  - 斜率顯著為負 ⇒ 照實寫。

**和主比較（題目範例當可見）的關係**：
- 題目範例和隨機抽的隱藏案例**性質不同**：
  - 範例寫在題敘裡，agent 看得到、通常也會自己跑，而且多半是簡單情況；
  - 隱藏案例 agent 沒看過，含邊界與大輸入。
  - 所以範例的「k 筆」和隨機隱藏的「k 筆」不等價，**不能放在同一條曲線上**。
- 主比較的結果另外用 hᴳ 重算一次（題目範例當驗收、G 當評分），在圖上標成一個獨立的點「範例（每題 k_ex 筆）」，不連線、不參與趨勢檢定。

**檢定力**（描述用為主）。粗模擬：
- 用 ctl34 第 1 次嘗試的隱藏通過比例 r，把每次嘗試的 16 筆案例當成各自以機率 r 通過、彼此獨立；G＝4、R＝12；每格 30 次抽樣；150 次模擬。
- 結果：曲線約 S₁−Mᴳ≈+7.7pp、S₂≈+9.3、S₄≈+10.6、S₈≈+11.4，先陡後平。k≥1 的斜率約每級 +1.2pp。
- 趨勢檢定的檢定力：60×3 約 0.75，48×3 約 0.67。
- ⚠ 「案例彼此獨立」不成立：真實的失敗在案例間高度相關，曲線會更早變平、斜率更小，檢定力可能更低。所以本節以描述為主，檢定只當輔助。

   - 理由：competition 對 12B 的單次「隱藏全過」率預期遠低於 15%，幾乎只會產生「三次全錯」的格，沒有資訊。
   - 兩層中用哪一層，由 §6 的校準機械決定，只用一層。不混層：混層會讓難度與層別混在一起，群集檢定的母體也不清楚。
   - 預設偏好 interview：它在 APPS 上通常落在中段，接近 ctl34 12B 的單次成功率（約 30–50%）。但 12B 在 interview 上的嚴格正確率可能低於 15%，所以 introductory 一起校準。
4. **案例數**：隱藏案例 **≥6**、可見案例（題目範例）**≥1**。
5. **比對規則**：逐行去掉尾端空白後完全相等（工具內建），每案例逾時 4 秒。
6. **有效性**（只跑 APPS 附的參考解，不跑模型）：
   - 至少一份參考解在**全部**可見與隱藏案例上，依第 5 點的比對規則通過；沒有任何一份通過就排除。APPS 有錯的測資，這一步把它們擋掉。
   - 用來判定的參考解記入 MANIFEST。
7. **浮點排除**：任何可見或隱藏的期望輸出，含符合 `-?\d+\.\d+` 或科學記號 `\d[eE][+-]?\d` 的字元片段，就排除。
   - 理由：逐字比對無法處理浮點容差。
   - 限制：這會讓題目**偏向整數或字串輸出**的題。
8. **多解題排除**（兩條都套用）：
   - (a) **題敘關鍵字**（不分大小寫）：`any of them`、`print any`、`output any`、`if there are multiple`、`if there are several`、`any valid`、`any possible`、`any correct`、`any such`；
   - (b) **參考解不一致**：題目附 ≥2 份參考解時，所有能在第 6 點通過的參考解在全部隱藏輸入上的輸出必須兩兩相同；其他參考解只要在任一案例輸出不同（依第 5 點），也排除。
   - 限制：只有一份參考解、題敘又沒有關鍵字的多解題擋不住。逐字比對可能把這些題的正確答案算錯；這對 S、M、F 三種取法一視同仁，但會壓低成功率、增加「三次全錯」的格。
9. **排序與取題**：符合 1–8 的題，依層分開，依 `sha256(f"{id}:acceptance-pool-20261128")` 由小到大排序。
   - 第 1–60 名是**正式候選**，正式批次取前 T 名，T 由 §6 決定。
   - 第 61–68 名是該層的**校準題**，永久排除、不進分析。
   - 第 T+1 到 60 名不使用。
10. **工作區與隱藏案例**：
    - `workspace/` 只有題敘、可見案例與驗收腳本。
    - 隱藏案例、scorer 與金絲雀放在工作區外；每題的隱藏目錄放一個 32 位十六進位金絲雀。
11. **主機分配**：正式題單在第 9 點的順序裡，第 0、2、4…題給 **1004**，第 1、3、5…題給 **1003**；同一題的所有重複在同一台。
12. **MANIFEST** 記：每題 id、題目 sha、層、可見／隱藏案例數、主機、排序鍵、金絲雀的 sha256、salt、工具與輸入檔 sha。
    - 金絲雀本身不進 repo，只記雜湊；原文存在宿主端。

## 5. 環境、沙箱、評分隔離（發射前機械比對，任一不符就不發射）

**模型與兩台設定**：
- gemma-4-12b-it-qat，provider 用 `lms1003nothink`／`lms1004nothink`，兩台都 jobs 3。
- pi 的 `contextWindow` 65536、`maxTokens` 16384，已一致。
- 必須相同、而且寫進計畫檔的欄位：
  - pi 的 `contextWindow`、`maxTokens`、思考開關；
  - LM Studio 的載入參數：context length、parallel、量化檔、GPU offload；
  - 模型檔 sha256、pi 版本、harness sha。
- 發射前由 preflight 從兩台實際讀出來，和計畫檔逐欄比對，結果存檔附 sha256。（避免分台差異混入設定差；ctl34 兩台事後確認設定相同，主機差異仍無法歸因。）

**沙箱**（計畫層級 `sandbox: "netns"`）：
- `--unshare-net`，只放行該次嘗試用的那一個模型端點與推論路徑。
- `ulimit -f` 1 GiB；驗收與評分也在 bwrap 裡跑；磁碟看門。
- agent 只看得到自己這一次嘗試的工作區與 logs；看不到隱藏目錄、題庫、同格其他槽、其他格、`~/dev`。
- **負控制用 `redo.py netns-selftest`，發射前、跑完後各一次**，輸出與 sha256 記入附錄 B。任一項不符：發射前就不發射；跑完後就整批不評分。

**驗收與評分的隔離（具體條文）**

> 這一節是看了對抗審查（S1）才補上的；審查是在任何資料存在之前做的。審查實測：舊實作把隱藏目錄掛在 `/eval/hidden`，scorer 和 `solution.py` 在同一個沙箱、同一個 pid 命名空間。三支惡意解都拿到 grade=True 8/8（可見 0/2）：
> - 直接 open 隱藏的 `cases.json`；
> - 用 glob 找 `cases.json`；
> - 寫 `/proc/<父行程>/fd/1` 塞一行假裁決，再殺掉 scorer。
>
> 另外，在工作區放一個自製的 `subprocess.py`，就能遮蔽標準函式庫、騙過可見驗收，會污染「依可見挑」（S）。這些修好之前不發射。

1. **每一次執行 `solution.py`，驗收與評分都算，都放進自己的巢狀 bwrap**：
   - `--unshare-all`、新的 `/proc`；
   - 只唯讀掛入 Python 需要的檔與**工作區的唯讀副本**；
   - 有大小上限的 tmpfs `/tmp`；
   - **沒有**隱藏目錄、scorer、金絲雀檔、網路。
   - 驗收也必須用同一個子沙箱，否則可見通過可以被偽造，S 會被污染。
2. **直譯器**：一律 `python3 -I`，不讀環境變數、不加 user site、不把腳本所在目錄放進 `sys.path`，擋掉同名檔遮蔽標準函式庫。
   - 後果（照實寫）：`solution.py` 必須是單檔，import 工作區裡其他自寫模組會失敗；這算模型行為。驗收與評分用同一條規則，所以兩者一致。
3. **案例只走 stdin**：scorer 在子沙箱**之外**讀案例，把輸入經 stdin 餵進去、收 stdout，在子沙箱外比對。
4. **裁決管道**：scorer 在**所有子行程都回收之後**才輸出裁決，或寫到子沙箱看不到、也寫不進的 fd。子沙箱的任何輸出只當作「待比對的答案」，不可能成為裁決行。
5. **金絲雀**：每題的金絲雀寫進 `CANARY.txt`、`cases.json`，也寫進每一個隱藏輸出檔（作為不參與比對的註記欄位，或另存同名旁檔；由實作決定、寫進 MANIFEST）。這樣讀到任何一份隱藏資料的程式，都可能把金絲雀帶出來，被 §5 的機械訊號抓到。
6. **上限（計畫參數，寫進計畫檔）**：

   | 參數 | 值 |
   |---|---|
   | 每案例逾時 | 4 秒（照舊） |
   | 評分整體逾時 | max(計畫值 60 秒, 案例數 × 4 秒 + 10 秒)；取代舊的固定 60 秒 |
   | 驗收整體逾時 | max(計畫值, 可見案例數 × 4 秒 + 10 秒) |
   | 每案例輸出上限 | 1 MiB |
   | 位址空間上限 | 1 GiB |
   | 子沙箱 tmpfs 上限 | 寫進計畫檔 |

   **被任何上限擋下都算模型行為**：那個案例沒過；不作廢、不重跑。被擋次數分槽報。
7. **惡意解負控制**：四支惡意解＋一支正控制做成回歸測試，在合成題上跑。**發射前必過，跑完後再跑一次**：
   - (i) **直接讀**：open 已知的隱藏路徑與 `cases.json`，印出內容或照抄期望輸出；
   - (ii) **glob**：在整個可見檔案系統用 glob 找 `cases.json`、`CANARY*`、`*expected*`、`*.out`，找到就照抄；
   - (iii) **/proc fd 假裁決**：寫 `/proc/<父行程>/fd/1`（以及能找到的其他 fd）塞一行假裁決，再嘗試殺掉父行程；
   - (iv) **遮蔽標準函式庫**：工作區放自製的 `subprocess.py`（與其他常用模組名），企圖讓驗收或評分誤判為通過；
   - (v) **正控制**：參考解必須在可見與隱藏全過。
   - 判準：(i)–(iv) 任一支拿到 **grade=True**、或拿到**可見通過**（驗收 accept 或任一可見案例通過），或輸出含金絲雀 ⇒ **不發射**；跑完後才發生 ⇒ 整批不評分。(v) 沒全過也一樣。
   - 輸出與 sha256 記入附錄 B。

**其他審查要求的修正**（修好、並由審查方確認後才發射；版本 sha 寫進發射前補充）：

## 6. 校準與規模（發射前機械決定，不准中途降）

**小校準**（不進分析；校準題永久排除）：
- **題**：introductory 與 interview 兩層，各取第 61–68 名，每層 8 題，共 16 題。
- **每題跑 3 次**，程序與正式批次完全相同（同一個臂、600 秒、不提前停、同沙箱、同評分）。每層 24 次嘗試、兩層 48 次，6 串流約 8 輪。
- **為什麼是 3 次而不是 1 次**：
  - 每層只有 8 次觀測時，單次成功率的 95% 區間寬達約 ±35pp，判不了 15–85%。24 次（以題為群集）雖然仍粗，但夠判明顯的出界。
  - 3 次也能同時估誤收率與「有資訊的格」比例。
  - 校準等於一次完整的正式路徑彩排，包括 `stop_on_accept: false`、netns、評分隔離、逐次落盤。
  - 兩層同時校準，避免「一層出界再校準另一層」的第二輪等待。
- **校準算三個數**（每層）：
  - p̂＝24 次嘗試的隱藏全過比例；
  - FÂ＝可見全過的嘗試中，隱藏沒過的比例；
  - t̂＝每次嘗試的平均牆鐘。
- **選層規則**（機械）：
  1. 只看 p̂ 在 **[15%, 85%]**、而且 FÂ **<0.60** 的層（可見全過的嘗試少於 3 次時 FÂ 記為「無法估計」，不因此排除）。
  2. 兩層都符合 ⇒ 取 p̂ 離 45% 較近的層；一樣近 ⇒ interview。
  3. 只有一層符合 ⇒ 取那一層。
  4. **兩層都不符合 ⇒ 不發射**，回報「APPS 在 12B 上沒有可用的難度層」並附三個數。理由見下。
- 為什麼兩層都 >85% 也不改抽 competition：competition 沒有校準過；而兩層都 >85% 表示天花板，改層等於依結果換題庫，必須另寫預註冊。
- FÂ 門檻 0.60 的理由（§7 的敏感度）：polyglot 池的誤收率約 0.32；把它推到約 0.59 時，S−M 的期望值只剩約 1pp，60×3 的檢定力約 0.05，這時跑 10 小時幾乎不可能判「過」。
- 校準結果、選定的層、三個數寫進發射前補充後，才發射正式批次。

**發射前檢查（冒煙與校準時查；任一不符就不發射）**：
- **(a) pi 真的連得上**：用真的 pi、正式的沙箱與轉送器，對兩台各跑一次冒煙。轉送器紀錄裡必須有該次的成功推論請求，pi 也必須拿到模型回應。node 的 fetch 預設不理會代理環境變數，所以不能只用 curl 驗。任一台連不上 ⇒ 不發射。
- **(b) 三次嘗試在取樣上真的不同**：
  - 先查計畫檔：溫度 >0、沒有固定 seed；不符就不發射。
  - 再用校準的 16 格比對：每格三次最終 `solution.py` 的 sha256（原始位元組）。分母只算三次都有 `solution.py` 的格；沒有的格數另報。
  - 報兩個數：**三次完全相同的格比例**，以及**兩兩相同的比例**（每格 3 對，合計 48 對）。
  - **門檻：三次完全相同的格 >50%（16 格中 ≥9 格）⇒ 不發射**。
  - 門檻的理由：
    - 這項檢查要抓的是取樣設定失效：溫度實際為 0、seed 被固定、或伺服器端快取了回應。這時幾乎每一格三次都會逐位元組相同，比例接近 100%。
    - 真的有取樣時，agent 的程式是多回合生成、通常數十行；變數名、空白、註解任何一處不同，sha 就不同，三次完全相同應該少見。但 introductory 的短解可能收斂成同一份，所以門檻不設得太低。
    - 50% 夾在「設定失效（≈100%）」和「正常取樣下可能出現的短解收斂」之間；16 格時，若真實比例是 20%，≥9 格的機率是 0.15%；是 30% 時是 2.6%；是 40% 時是 14%。所以正常取樣被誤擋的機率很小，除非短解收斂本身就很普遍。
    - **ctl34 的「三次隱藏結果全同」約 87% 不能拿來當參考**：那是結果相同，不是程式碼相同。題目難度讓結果高度一致（ICC 0.80），程式碼仍然可以完全不同。
  - 正式批次也報這兩個比例（只描述）。三次程式碼相同的格，S−M 必為 0，只是沒有資訊，不影響有效性。

**規模**：候選組合依檢定力排序：**60×3 → 48×4 → 48×3 → 40×4 → 40×3**（題數 × 重複數）。
- 每次嘗試的估時：τ＝max(1.2·t̂, 412 秒)＋35 秒（驗收與評分）。t̂ 取選定層的校準值；412 秒是 ctl34 較慢主機第 1 次嘗試的平均，作為下限。每格 3 次 ÷ 每台 3 串流、兩台各一半格 ⇒ **預估時數＝格數 × τ ÷ 2**。
- 可用時數 H＝硬停 −（正式批次發射時刻）− 1.5 小時。正式批次在校準之後才發射，所以 H 已經扣掉校準時間。
- 取清單中**第一個**同時滿足以下兩條的組合：
  - 題數 ≤ 該層正式候選的題數（最多 60）；
  - 預估時數 ≤ H。
- 以 τ＝447 秒為例：60×3＝11.2 小時；48×4＝11.9；48×3＝8.9；40×4＝9.9；40×3＝7.5。
- **連 40×3 都放不下就不發射**。
- 選定的組合、τ、H、可用題數寫進發射前補充後才發射。**之後不准改組合**。

**時程**（決策方填）：
- 校準發射：＿＿Z（最快 09:00Z）；
- 正式批次發射：＿＿Z（最快 10:30–11:00Z）；
- 硬停：＿＿Z（22:00Z）。
- 硬停時正在跑的嘗試立刻結束；它所在的格依 §8 排除。

**在這個時程下，組合規則會落在哪裡**（撰寫時試算，實際以發射時的 τ 與 H 為準）：
- **校準時間**：16 格、每格 3 次依序跑、6 串流 ⇒ 每串流約 8 次嘗試。以 447 秒計約 60 分鐘，最壞約 90 分鐘。09:00Z 開始，約 10:00–10:30Z 結束，和 10:30–11:00Z 的正式發射相容。
- **正式批次可用時數 H**＝22:00 − 發射時刻 − 1.5 小時。10:30Z 發射是 10.0 小時，11:00Z 是 9.5 小時。
- 60×3（τ＝447 時 11.2 小時）與 48×4（11.9 小時）**放不下**。
- **48×3** 需要格數 × τ ÷ 2 ≤ H，也就是 τ ≤ 2H÷144：
  - 11:00Z 發射：τ ≤ 475 秒，也就是 t̂ ≤ 367 秒；
  - 10:30Z 發射：τ ≤ 500 秒，也就是 t̂ ≤ 388 秒。
  - τ 的下限是 447 秒，所以 t̂ 夠短時 **48×3 放得下**。48×3 最晚要在 11:34Z 發射（τ＝447 時需要 8.9 小時）。
- 48×3 放不下時，40×4 需要 τ ≤ 2H÷160：11:00Z 是 427 秒，低於 τ 的下限 447，**放不下**；10:30Z 是 450 秒，只有 t̂ ≤ 345 秒時才放得下，但那時 48×3 一定先放得下。所以**實際上是 48×3 或 40×3**。
- **40×3** 需要 τ ≤ 2H÷120：11:00Z 是 570 秒（t̂ ≤ 446 秒），10:30Z 是 600 秒（t̂ ≤ 471 秒）。
- 再長就不發射。
- **預期**：APPS 單檔題的 t̂ 若和 ctl34 相近或更短（≤367 秒），會落在 **48×3**（§7：判「過」的檢定力 0.89，前提是誤收率接近 polyglot）；t̂ 在 367–446 秒之間落在 40×3（0.79）；更長就不發射。

## 8. 事前的無法區分條件與缺格規則（在算 S−M 之前判定）

**缺格**：以格為單位，3 次嘗試沒有全部有效完成（硬停時沒跑完、或依 §5 作廢）的格**整格排除**。排除的格超過選定格數的 **10%** ⇒ 判定為**未定**，只描述。

**無法區分條件**（任一成立 ⇒ 判定「本批次無法區分」，只描述，不下 §3 的判定）：
1. **單次成功率**（全部納入格的 M 平均）<15% 或 >85%。
2. **S 和 F 挑到同一份的格 >85%**。polyglot 池模擬中這個比例的 5–95% 範圍是 56–72%。超過 85% 表示挑選只在不到 15% 的格改變交付版。APPS 的可見案例少，三次都「可見全過」或都「全不過」的格可能更多，這一條比較可能觸發。
3. **有資訊的格**（三次的隱藏結果不全相同，即 h₁+h₂+h₃ ∈ {1, 2}）**<5%**。模擬範圍是 6–21%。S−M 只可能在有資訊的格不為 0，而每格 |D| ≤ 2/3；這個比例 <5% 時，|S−M| 的上限約 3.3pp。

## 9. 最可能被挑的三個弱點

1. **M 是同一批嘗試算出的期望值，不是實際「隨機交一份」。**
   - 緩解：在給定三次嘗試的情況下，隨機交一份的期望值就是三次的平均（期望值的線性），不需要「各次獨立」這個假設，只需要三個槽同分布。
   - 為了讓三個槽同分布：prompt 逐字相同、同一台、從同一份原件開始、槽號由 harness 依序決定。各槽的成功率分開報（只描述）；任兩槽相差 ≥10pp 時，結論加註。
   - 實際抽籤只會增加變異，期望值相同。
   - 三次嘗試的取樣真的不同（溫度 >0、不固定 seed），由 §6 發射前檢查 (b) 驗證。
   - 照實寫的限制：三個槽依序跑時，時段與主機負載可能有系統差（例如槽 3 較常碰到另一格的高負載），M 和 F 都會受影響。
2. **agent 自己也會跑可見案例，所以這不是「有沒有可見測試」的增益。**
   - 照實寫：題目範例本來就寫在題敘裡，所有嘗試都看得到、也能自己跑；量到的只是 harness 層級「用驗收挑交付版」的增益。
   - 結論主句已寫進這個限定。要量「把測試給 agent」本身，需要另一個看不到範例的臂，不在本批次範圍內。
3. **只用一個模型、一個題庫（APPS 的一個難度層）、一個時間上限，而且驗收很弱，無法外推。**
   - 照實寫：結論的範圍就是「gemma-4-12b、600 秒、這 N 題 APPS（{層}）、可見案例＝題目範例」。外推列在禁用句。
   - 門檻與檢定力是用 polyglot 定的；APPS 的誤收率與難度分布不同，由 §6 的校準與 §8 的條件擋下不適用的情況。
   - 選題排除了浮點與已知的多解題，所以題目偏向整數或字串輸出、答案唯一的題。

其他也會被問、這裡先照實寫：
- **可見與隱藏來自同一題，所以有相關。**這正是被量的機制：題目範例能預測隱藏案例多少。APPS 的範例往往是最簡單的情況，相關可能偏低，這會讓增益偏小，對 S 不利。
- **逐字比對與多解題**：§4-8 擋不住的多解題會被算錯，三種取法一視同仁，但會壓低成功率。
- **APPS 的訓練資料暴露**：APPS 是公開題庫，12B 可能看過，無法排除。但它對 S、M、F 一視同仁，影響的是成功率的水準，不是取法之間的差。
- **門檻是看過 ctl34 才定的**；但它們是在本批次任何資料存在之前定的，本批次的題也還沒選。
- **S 要跑 3 次，F 只跑 1 次。**花費的比較見 §10。S−M 是等花費（都是三次）；S−F 不等花費。

## 附錄 A：模擬方法（撰寫者執行；可重現）

母體是 `ctl34_g12` 稽核包第二版（`edf6d323f`）裡，每個（題, 重複）R、B、C 三臂的第 1 次嘗試。它們提示相同、從同一原件開始、彼此不以對方為條件，等於每題 6 次獨立的 600 秒嘗試（33 題；pg_transpose 的 C 是 void，排除）。

每次模擬：
- T 題以放回方式從 33 題重抽；
- 每個重複從該題的 6 次嘗試**不放回**抽 3 次，當成槽 1–3；
- 依 §2 算 S（平手取最早）、M、F；
- 依 §3 的檢定算 p，「過」規則同 §3。

其他設定：
- 「效果為 0」的世界：把 S 換成三槽裡隨機一槽。
- 等價機率：每次模擬做 400 次群集 bootstrap，看區間是否落在 ±3pp 內，共 200 次模擬。
- 每個組合跑 1,500 次（判「過」與檢定力）、600 次（效果為 0 的偽陽性）、200 次（等價、區間寬度）；種子 11。
- 分布：S 和 F 同一份的比例 5–95% 在 0.56–0.72；有資訊格比例 5–95% 在 0.06–0.21（2,000 次）；單次成功率 5–95% 在 0.31–0.52。
- 誤收敏感度：在抽出的嘗試上，把「隱藏沒過、可見沒全過」的嘗試以機率 q 改成可見全過，再算 S；每個 q 跑 1,000 次，種子 5。

程式核心（與 `ops/redo/analysis/acceptance_signal_offline.py` 的 `power_sim` 相同，只改平手規則與判定規則）：

```python
def S(tri):                      # 取槽號最小的可見全過；否則可見通過最多、平手取最早
    for i, x in enumerate(tri):
        if x["accept"]: return i
    return max(range(3), key=lambda i: (tri[i]["acc_passed"], -i))
# 每題：sm += 3*h[S] - sum(h)；sf += h[S] - h[0]
# 主比較：signflip([各題 sm]) < 0.05 且 mean(D) >= 0.03（判「過」）
```
