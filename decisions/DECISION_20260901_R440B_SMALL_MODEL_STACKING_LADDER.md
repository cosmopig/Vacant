# R440B：小模型堆疊階梯——把「最強的 Vacant 架構」一階一階疊出來

（2026-09-01，依人類指令：「多平行實驗，用小模型一次次的堆疊上去……做現在
最強的 vacant 架構去改，或甚至全部全做，我要他足夠有效」。本文件是階梯的
預註冊：每一階是一個獨立條件、獨立 DECISION、獨立 run；上一階沒訊號不准跳。）

## 為什麼是「階梯」不是「一次全做」

R438 的機制發現：評審≈常數函數 ⇒ revise 無淨修正 ⇒ 等預算無增益。
「全部一起改」若翻盤，不知道是哪一階翻的，展場就只能說「改了很多東西之後有用」
——那是 demo 不是證明（鐵律 5）。階梯讓每一階的貢獻可歸因。

## 階梯（由弱到強，每階只加一個機制）

| 階 | 加什麼 | 對應的 R438 病灶 | 成功判準（配對 McNemar，等預算） |
|---|---|---|---|
| L0 | **基線重定**：gemma-4-12b 單模型池（R440 E1） | 天花板 | OFF 失敗率進 35–60% 窗 |
| L1 | **有反例才修**：revise 只在評審給出「可執行且真推翻」的反例時觸發（R439 的方向） | revise 82% 被丟棄 | revise 淨效應由 -3.5pp 轉正 |
| L2 | **異質評審**：評審用**不同模型家族**（worker=gemma、reviewer=qwen3.6，或反過來）| 評審≈常數函數、同族盲區 | 評審票準確率 − almost-PASS 基線 > +5pp |
| L3 | **反例驅動的第二輪**：L1 的反例回饋給 worker 再寫一版，預算從 OFF5 的 5 呼叫裡挪（不加預算） | 單輪修訂無記憶 | ON > OFF5 配對顯著 |
| L4 | **信譽路由真的有東西可路由**：worker 池刻意異質（gemma-12b × 更小模型，例如 4B 級），讓 UCB 有訊號 | 路由端無差異 | ON 的路由選擇與 worker 真實正確率相關（Spearman > 0.5） |
| L5 | **困難題庫**（R440 E2/E3：LCB medium+hard） | 題目太易 | 上面各階在 LCB 上重現 |

每階：先跑 MBPP+（179 題、既有 seed），有訊號才在 LCB 重跑。
每階一個 `runs/g_r4xx_Lk_*`，一份 DECISION，預測寫在跑前。

## 平行執行配置

- 8765 中轉池：一次一個 run（§7）。順序：E1(L0) → L1 → L2 → …
- win1003:1234（LM Studio，本機 gemma-12b）：可平行跑**同一階的 LCB 版**或
  L4 的小模型池——但 GPU 被 ComfyUI 夜班佔用時（`/d/lock_scene`、
  `/d/lock_night14` 存在）不得起模型。
- 這樣最多兩條 run 同時在跑，延遲資料各自乾淨。

## 「足夠有效」的定義（人類要的，先寫死）

不是 p<0.05 就算：展場要能對外行說一句真話。本階梯的「有效」＝
**在等預算下，至少一階讓 ON 的 hidden_check 通過率配對顯著高於 OFF5，
且評審準確率高於 almost-PASS 基線 ≥5pp**——兩個條件同時成立才算「機制
真的在工作」，否則只是統計漂移。達不到就照實寫「在這個模型量級上，
這個機制的可歸因增益上限是 X pp」，那也是展場能說的真話。

## 稽核（fable 層，見 LOOP_PROMPT 模型政策）

每階收官由 fable 輪裁決：重算配對表、核 rows.jsonl 行數與 sha256、
檢查 void 率窗、對照本文件的預測。sonnet 收數字、opus 改碼、fable 裁決——
三權分立，避免同一個模型既寫碼又替自己判分。
