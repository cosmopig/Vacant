# R445：把 CONFORM 對照擴到 MBPP+ 全庫（`g_r445_conform_mbpp_ext`）

**日期**：2026-09-03 UTC 22:2x　**輪次**：round673　**模型**：Opus 5（實驗設計取捨）
**狀態**：預註冊（R440G 閘門用）。**本檔在寫任何程式碼、跑任何量測之前定稿。**

## 一、要解的問題（r444 留下來的唯一未答項）

round672 收官：CONFORM vs OFF5 在 deliv 上
`n=179 Δ=+2.79pp b=9 c=4 p=0.2668 95%CI=[-1.66,+5.94] NON_INFERIOR_BUT_UNRESOLVED`。

LOOP_PROMPT「有成效」三條裡，第 1 條（量測有訊號，OFF 失敗率 27.9%）與第 2 條的
**成本面**（1.39 vs 5.00 calls/task）已成立；**第 3 條（等預算誰贏）沒有答案**——
179 題只給出 13 對 discordant，區間同時容得下「沒用」與「+5pp」。
**這是檢定力不足，不是「打不贏」。**

## 二、選了什麼：**接著跑同一設定的剩餘題目，不是重跑、不換條件**

`load_tasks()` 回傳 `ts[offset:offset+n]`＝**seed 決定性前綴**。本輪逐一驗過（零 API）：

```
全庫（扣掉 GAIN_EVALPLUS_RESOURCE_EXCLUSIONS）          371 題
r444 的 179 題 == load_tasks(evalplus, seed, 179)       True（逐 id 逐序相同）
offset=179 取到的第一題 == full[179]                     True（mbppplus_Mbpp/786）
剩餘與 r444 的交集                                       0
```

⇒ **`--offset 179 --n 192` 拿到的是與 r444 完全不重疊的 192 題**，
把兩個 run 併起來就是全庫 371 題的配對比較。**成本只有增量的 192 題，
r444 的 179 題不必重跑。**

### 為什麼不選另外兩個候選（round672 §七 列的）

- **不選「把 OFF5 換成等呼叫預算的對照」**：CONFORM 1.39 vs OFF5 5.00 calls/task，
  換成 1.4 呼叫的自洽對照會讓對手**變弱**，CONFORM 必然變好看。
  LOOP_PROMPT ⚠「不要為了有成效去挑對自己有利的設定」。
  現在這組的不對稱是**對 Vacant 不利**的那個方向（對手多花 3.6 倍），保留。
- **不選「難題子集（OFF 失敗的 50 題）」**：那是**照結果選題**。
  R440B 的 `counterexample_confirmed` 已經在同一個坑裡死過一次（逆向選擇器）。
  50 題就算 discordant 密度翻三倍也只有 ~10 對，仍不夠，卻換來一個要辯護的選擇偏誤。

## 五、`--offset` 接線的植入缺陷測試（事前寫死四條）

接一個新旋鈕**不算接好**，除非它壞掉的時候會被抓到。含「安靜量不到」兩型：

| # | 植入什麼 | 必須發生 |
|---|---|---|
| M1 | `--offset` 被忽略（傳了但 `load_tasks` 收不到） | 取到的題目 == r444 的 179 題 ⇒ **重疊 179，測試必須 FAIL** |
| M2 | `offset` 傳成負數 | 必須被擋（負 offset 在 python 是從尾巴切＝安靜取到別的題目） |
| M3 | `offset` 超過庫尾（如 400） | 題目數 0 ⇒ **必須拒絕啟動，不准當成通過**（安靜量不到型一） |
| M4 | `offset+n` 超過庫尾（179+300） | 只拿得到 192 題 ⇒ 數量掉下來，**必須顯式報出實際題數**（安靜量不到型二） |
| M5 | `summary.json` 要記 `offset` | 沒記＝run 不能自我描述，併庫分析無從驗證用了哪一段 |

**M1–M4 要在真的發射之前跑過，且要看到 FAIL 的那一面**（乾淨版 PASS 不算證據）。

## 六、已知的污染與限制（先揭露，不等被抓）

1. **尾段 192 題不是處女地**：`g_off371_20260825`(OFF 189/192)、
   `g_onoff5_371_r123_20260825`(ON/OFF5 192/192) 等舊 run 跑過它們——
   但那是 **qwen 世代的模型池**（2026-08-25），本 run 是 gemma-4-12b-it-qat，
   結果不可互推。**CONFORM 臂對尾段零曝光。**
2. **本輪為了估計檢定力，看過舊 run 的 head/tail OFF 通過率**
   （79.78% vs 77.25%，qwen 世代）。這只用來確認尾段不是系統性更難、
   讓 P-E2/P-E3 的外推有依據；**它不能、也沒有改變任何臂的設計或門檻**。
   配對檢定在題目內配對，head/tail 難度差本來就不會偏誤 Δ。
3. **舊 run 的「同 seed」不等於同題序**：`g_onr_r212_20260828` 同樣是
   `g-r212-route-20260828`、n=179，卻與現在的尾段有 7 題重疊
   ⇒ 排除清單改過之後前綴會位移。**本 run 的對齊是逐 id 驗過的**（§二），
   靠的不是「seed 一樣」這個宣稱。
4. 全庫只有 371 題 ⇒ **就算全跑完，若 Δ 維持 +2.79pp，`hi` 仍會落在 +5 附近**
   （外推 [+0.15,+5.43]）。**r445 有可能還是答不出 RULED_OUT，這是事前就知道的。**
   真要把 ≥5pp 切乾淨需要 n≈530 ⇒ 得跨題庫併（LCB），那是 r445 之後的決定，
   **不在本檔授權範圍內**。

## 七、什麼條件下這個決定該被推翻

- 新 192 題的 OFF 失敗率跑出 20–60% 之外 ⇒ 「全庫是個好量測窗口」這個前提錯了。
- P-E4 觸發（calls_per_task >4.5）或 P-E6 觸發（void >20%）⇒ 中止，不補跑。
- 若併庫後 `n_d` 仍 <20 ⇒ 「加大 n 就能答第 3 條」這條路在 MBPP+ 上走死，
  下一輪要改談跨題庫或改談成本面結論，**不要再加同一個庫的樣本**。
